## 第一部分：產品（v0.6 設計，尚未實作）

Agent 對話是寫程式的 Agent 工具留在本機的聊天紀錄。v0.6 支援 Claude Code、Codex、Pi、DeepSeek Harness 這四個（用戶 2026-11-13），只列這台電腦上找得到的。這些工具會自己刪掉舊對話，PathKeep 替使用者留下來。

Agent 空間的頁面依序是洞察、紀錄、專案、備份。這個空間沒有首頁，第一頁就是洞察（用戶 2026-11-13）。清單頁叫「紀錄」，不叫「對話」，免得跟 PathKeep 自己的助理（也是聊天）混在一起（用戶 2026-11-13）。

整個空間的原則：

- 操作用的畫面（紀錄、閱讀器、專案）每個只有一件主要的事，其他的收在一次點擊後面。東西是收起來，不是拿掉：token 和時間都還在，只是不放在每一列。
- 洞察是給人看的報告，不是拿來操作的工具，像儀表板一樣全部攤開，不折疊（用戶 2026-11-13）。
- 頁面隨視窗變寬，多出來的寬度放更多欄位或卡片；閱讀用的文字仍限制行寬（[data-spaces-tradeoff.md](../design/data-spaces-tradeoff.md) §4.5）。
- 每個工具用自己的圖示和名稱，不用縮寫。依工具分的圖表顏色見 [data-spaces-tradeoff.md](../design/data-spaces-tradeoff.md) §4.4。
- 每個畫面打開時 100 ms 內先有骨架；長清單都虛擬化；重的計算不在主執行緒。

### 1. 用詞與數字

這一節定義每個詞和每個數字一次，後面各節只引用。

#### 1.1 用詞

| 詞               | 意思                                                                                                                                                 |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 對話             | 你開的一次對話。它叫出來的 subagent 算在它裡面，不另算一段。同一段對話可能有好幾個檔案（例如 Codex 還原後的另一份 rollout），PathKeep 把它們當成一段 |
| subagent         | 對話在某一步派出去的 agent。它有自己的紀錄檔，PathKeep 把它掛在派出它的那一步底下，清單裡不單獨列出                                                  |
| 訊息             | 你送給 Agent 的話。計數寫「{n} 則訊息」                                                                                                              |
| 一輪             | 從你送出一則訊息，到 Agent 為它做完（回覆完、被你中斷，或你送出下一則）                                                                              |
| 只剩 PathKeep 有 | 這段對話的每個檔案，在最近一次能讀到它們所在資料夾的備份裡都不見了。資料夾讀不到（磁碟沒接上、沒有權限）不算不見                                     |
| 專案             | 一個或好幾個資料夾，裡面的對話算在一起。怎麼歸類見 §5.9                                                                                              |
| 零散資料夾       | 家目錄本身和系統暫存資料夾。在這些地方跑的對話不各自算一個專案，全部放進「零散資料夾」                                                               |
| 封存             | 把一段對話從清單收起來，見 §8.1                                                                                                                      |
| 垃圾桶           | 不想再看到的對話放的地方，見 §8.2。垃圾桶裡的對話還存在存檔裡                                                                                        |

#### 1.2 時間範圍

洞察、紀錄、專案洞察用同一組範圍：`今天`、`7 天`、`30 天`、`90 天`、`1 年`、`全部時間`。

- 範圍以完整的本地日算，日子照洞察的時區（[insights-time-zone.md](../architecture/insights-time-zone.md)）。「今天」從今天的本地午夜開始，不是 24 小時前；`7 天` 是今天加上之前的六天；`30 天`、`90 天`、`1 年` 也一樣往前數。
- 範圍選的是「範圍裡發生的事」：
  - 洞察算落在範圍裡的那幾輪。一段跨過範圍起點的對話，只有範圍裡的那幾輪算進來。
  - 紀錄列出在範圍裡有活動的對話。
- 一輪本身跨過範圍的邊界時，Agent 工作時間照時鐘在邊界切開，只算範圍裡的那一段。Token 和費用屬於產生它們的那一則回覆的時間（每一筆用量紀錄有自己的時間），所以跨過邊界的那一輪照紀錄分開：邊界前的回覆算前面，邊界後的算後面。
- 洞察選過的範圍會記住，下次打開還是同一個；第一次打開是「全部時間」。專案洞察和洞察共用這個記住的範圍。工具與專案的篩選不記住：回來看到一份被悄悄篩過的報告會誤導人（用戶 2026-11-13）。

#### 1.3 按天切開與分桶

所有按天算的數字都在本地午夜（洞察的時區）切開：一年日曆、「這一年」的數字、每天的長條。一輪跑過午夜，Agent 工作時間兩天各算各的那一段，所以一天永遠不會超過 24 小時；token 和費用照 §1.2 跟著每一則回覆的時間。每週、每月的數字由這些天加起來。

圖表的分桶跟著範圍：

| 範圍                     | 一根長條是       |
| ------------------------ | ---------------- |
| `今天`                   | 一小時           |
| `7 天`、`30 天`、`90 天` | 一天             |
| `1 年`                   | 一週（週一開始） |
| `全部時間`               | 一個月           |

副標裡的 `{每小時｜每天｜每週｜每月}` 照這張表寫。

#### 1.4 Agent 工作時間

**按時鐘算，同時開幾個都只算一次。**

- 每一輪是一段工作時間，從你送出訊息到 Agent 做完。subagent 在這一輪裡跑，它的時間已經在這一輪裡。
- 「Agent 工作時間」是範圍裡所有對話的這些時段合起來（聯集）的長度。兩個 Agent 一起跑 1 小時，算 1 小時。
- 每一輪的時長，工具自己有記就用它的（Claude Code 較新的版本會記），沒有就從紀錄裡的時間戳推算。卡片上寫 `{r} / {n} 段的時長是工具自己記的，其餘從時間戳推算。`

說明文字：`按時鐘算：同時開幾個 Agent 都只算一次。兩個 Agent 一起跑 1 小時，算 1 小時。`

#### 1.5 分開加總

**每段對話各算各的再加起來。** 每段對話只算落在範圍裡的那幾輪（跨過邊界的那一輪只算範圍裡的那一段），把這些時長加起來；「分開加總」再把範圍裡每段對話的這個數字加起來。兩個 Agent 一起跑 1 小時，算 2 小時。

說明文字：`分開加總：每段對話各算各的再加起來。兩個 Agent 一起跑 1 小時，算 2 小時。`

**平均同時開幾個** = 分開加總 ÷ Agent 工作時間，寫成 `平均同時開 {x.x} 個`。

#### 1.6 你在場的時間（估算）

**估算你在跟 Agent 來回的時段。**

- 把範圍裡所有對話中你送出的訊息，照時間排成一串。
- 相鄰兩則相隔不超過 15 分鐘，算同一段。
- 一段從它的第一則訊息開始，到它最後一則訊息那一輪結束為止；這最後一截最多算 15 分鐘。
- 這些段的總長就是「你在場的時間」。它也照 §1.2、§1.3 在範圍邊界和午夜切開。

說明文字：`估算：把你送出的訊息串起來，相隔不超過 15 分鐘的算同一段；最後一則算到那一輪結束，最多 15 分鐘。`

這不是打卡紀錄。Agent 自己跑長任務時你可能不在，所以它跟 Agent 工作時間不會一樣。

#### 1.7 Token

- 一律分成四種顯示：`輸出`、`輸入`、`寫入快取`、`讀取快取`。推理用的 token 是輸出的一部分，不另外加。
- 「Token」的總數是這四種的和。
- 數字照工具寫進紀錄的用量，每一筆用量算在它那一則回覆的時間。同一則回覆在 Claude Code 的紀錄裡會重複出現好幾次，只算一次；Codex 記的是累計值，取差值；從別的對話複製或繼承來的部分，只算在它最早出現的那段對話。每個工具的規則見 [agent-history-product-design.md](../architecture/agent-history-product-design.md) §7。
- 說明文字：`輸入、寫入快取、讀取快取、輸出四種加起來。每一輪都會把前面的對話重新送給模型，大多從快取讀，所以讀取快取占了絕大部分。`

#### 1.8 費用（按 API 牌價）

- 費用跟著用量：每一筆用量紀錄算一次，算在那一則回覆的時間。工具自己記了金額的（Claude Code 與 Pi 會寫），照它記的。
- 其餘按 PathKeep 附的牌價表估算：四種 token 各乘上回答的模型的價格。牌價表有版本，跟著 PathKeep 更新。估算出來的數字一律標 `估算`。
- 本機模型和不認得的模型沒有牌價，不估；沒有用量紀錄的也不估。這兩種都不算成 0，另外寫出有幾段。
- 兩個開關，都在「設定 › Agent 對話 › 用量與費用」，預設都開：
  - `顯示費用`：關掉時，洞察和閱讀器都不顯示任何費用數字。
  - 它下面的 `沒有紀錄的對話按牌價估算`：關掉時只算工具記下的。洞察費用卡上的開關是同一個。
- 說明文字：`訂閱方案不按 token 收費，這是換成 API 牌價的等值金額。工具自己記了金額的用它記的，其餘按 PathKeep 附的牌價表估算。`

#### 1.9 模型

- Token 和費用以每一輪算給回答那一輪的模型。subagent 的每一輪算給 subagent 自己用的模型。
- 一段對話的**主要模型**是輸出 token 最多的那一個。

#### 1.10 其他數字

- **對話數**：範圍裡至少有一輪的對話。subagent 另外寫 `另有 {n} 個 subagent`。
- **改動的程式碼**：Agent 用編輯工具改檔案時記下的行數（Edit、apply_patch 的 diff），不含它用 shell 指令改的部分。各對話分開算，同一行被改兩次算兩次。
- **工具呼叫**：名稱照各家原本的叫法，Read 和 read_file 是兩個工具。派出 subagent 也算一次工具呼叫。

#### 1.11 沒有紀錄不是 0

工具沒記下的數字（某些版本沒寫 token，或沒寫每輪時長）不當成 0。每張用到它的卡片都寫出有幾段對話有這項資料，例如 `{k} / {n} 段對話有用量紀錄`。一段對話完全沒有用量紀錄時，它沒有 token 總數，不是 0 token。

#### 1.12 小時數旁邊的「≈」

「Agent 工作時間」和「你在場的時間」的小時數旁邊有一段小字，把小時數換成比較有感覺的說法（用戶 2026-11-13 的點子與版面）。它只是換算，不是另一個統計數字，用的就是旁邊那個數字和目前的範圍。小時數永遠顯示，不會被換掉。

- 一次只寫一種說法，點一下換另一種：`≈ 不眠不休 {n} 天` 和 `≈ 8 小時工作制 {m}`。後面有一個小小的左右箭頭，表示可以換。
- 兩張卡用同一個選擇，換一張另一張跟著換，這樣兩個數字比得起來。選擇會記住；第一次是 `不眠不休`。
- 卡片放得下就跟小時數同一行，放不下就排在小時數正下方，不會在一句話中間斷開。
- **不眠不休**：小時數 ÷ 24，單位是天；滿 1,000 天改寫成年（÷ 365）。
- **8 小時工作制**：一個工作天 8 小時，一週 5 天，一年 260 個工作天，一個月是 260 ÷ 12 個工作天。不到 22 個工作天寫 `{n} 個工作天`，不到 12 個月寫 `{n} 個月`，再多寫 `{n} 年`。
- 數字不到 10 留一位小數，10 以上取整數。
- 不到 8 小時（不滿一個工作天）不顯示；不到 24 小時只有 `≈ 8 小時工作制 {n} 個工作天`，不能換。
- 滑過時寫完整的換算：`把這些小時連在一起，是 {n} 天不眠不休。按 8 小時工作制（每天 8 小時、每週 5 天）算，是 {n} 個工作天，約 {m} 個月，{y} 年。`（沒到的單位不寫）。
- 它是一個按鈕，無障礙名稱 `相當於{目前的說法}。按一下換成{另一種}`；鍵盤可以聚焦和按下。
- 專案洞察的「Agent 工作時間」也有。

### 2. 洞察 `#/agent/insights`

- **主要的事**：看這段時間 Agent 做了多少、花了多少、什麼時候在做。
- 它是 Agent 空間的第一頁，是報告，全部攤開。

#### 2.1 標頭

- 標題 `洞察`，旁邊用灰字寫目前的範圍：`（今天）`、`（最近 7 天）`、`（最近 30 天）`、`（最近 90 天）`、`（最近 1 年）`、`（全部時間）`，免得以為數字是全部的（用戶 2026-11-13）。
- 範圍切換（無障礙名稱 `時間範圍`），選項照 §1.2。
- `篩選` 按鈕。有條件時按鈕上寫出專案名稱和工具名稱（兩個以上寫 `{n} 個工具`），外框換色。無障礙名稱 `篩選（{n} 個條件）` / `篩選工具與專案`。
  - `工具`：每個工具一顆，可多選。
  - `專案`：下拉搜尋 `在 {n} 個專案裡找…`；每列是圖示、名稱、上層資料夾（零散資料夾寫 `零散資料夾`）、勾；選了專案時多一個 `全部專案` 清掉它；再點一次已選的專案也清掉。沒有結果 `沒有符合的專案`。
- 範圍和篩選只影響數字列和卡片牆；一年日曆不受範圍影響（§2.3）。
- 封存的對話照算；垃圾桶裡的不算。
- 沒有網址參數。

#### 2.2 數字列

五個數字，照這個順序：

| 數字                  | 下面一行                                                                       | ⓘ 說明                                    |
| --------------------- | ------------------------------------------------------------------------------ | ----------------------------------------- |
| `Agent 工作時間`      | `分開加總 {x} · 平均同時開 {x.x} 個`（小時數旁邊是 §1.12 的小字）              | §1.4、§1.5 的說明文字，加上時長來源那一句 |
| `你在場的時間`        | `估算：你在跟 Agent 來回的時段`（小時數旁邊是 §1.12 的小字）                   | §1.6 的說明文字                           |
| `Token`               | 有對話沒有用量紀錄時 `{k} / {n} 段對話有用量紀錄`，否則 `其中 {x}% 是讀取快取` | §1.7 的說明文字                           |
| `費用（按 API 牌價）` | 估算開著時 `工具記下 {金額} · 估算 {金額}`，關著時 `只算工具記下的（{n} 段）`  | §1.8 的說明文字                           |
| `對話`                | `另有 {n} 個 subagent · {m} 個專案`                                            | 沒有                                      |

`對話` 可以點，到「紀錄」，帶著同樣的範圍、工具和專案篩選。`顯示費用` 關著時沒有費用那一格，數字列是四個。

#### 2.3 一年

數字列下面一列，是唯一不受時間範圍影響的區塊（工具與專案篩選照樣套用）。它寬度固定，放進卡片牆中間或最後會切出空洞，所以單獨放在這裡。

**`每天的 Agent 工作時間`** 卡：

- 副標 `一年裡的每一天，同時開的只算一次。不受上面的時間範圍影響`。
- 年份切換 `上一年` / `下一年`，從有資料的第一年到今年，預設今年。
- 熱力圖：七列（週一到週日）乘每週一欄，每格 13 px；不在這一年或還沒到的日子是空的。圖例 `少` / `多`。
- 滑過每格時寫：`{YYYY-MM-DD} · Agent 工作 {x.x} 小時`（不到 1 小時寫 `{n} 分`），沒有的日子 `{YYYY-MM-DD} · 沒有`。
- 點一格到 `#/agent/chats?day=YYYY-MM-DD`，列出那天的對話。
- 卡片只有日曆那麼寬，格子不拉大。

**`{year} 年`** 卡補滿這一列，放不下時換到下一列。六個數字，依寬度排成每列 2、3 或 6 個：

| 數字           | 值                              | 下面一行                                    |
| -------------- | ------------------------------- | ------------------------------------------- |
| `Agent 工作`   | 每天 Agent 工作時間的和         | `同時開的只算一次`                          |
| `有對話的日子` | `{n} 天`                        | `今年到今天 {d} 天` / `全年 {d} 天`         |
| `每天平均`     | 總數 ÷ 有對話的日子，沒有時 `—` | `只算有對話的日子`                          |
| `最長連續`     | `{n} 天`                        | 超過一天時 `{M月D日} – {M月D日}`            |
| `最忙的一天`   | 時數，沒有時 `—`                | 連結 `{M月D日} →`，到 `#/agent/chats?day=…` |
| `最忙的月份`   | `{m} 月`，沒有時 `—`            | 時數                                        |

下面是每月長條（無障礙名稱 `{year} 年每個月的 Agent 工作時間`）：最忙的月份顏色深一點；還沒到的月份是透明的，滑過時寫 `{m} 月 · 還沒到`，其他 `{m} 月 · {時數}`。

#### 2.4 卡片牆

其餘卡片是一面依高度堆疊的牆，欄數隨寬度變（筆電兩欄、更寬三到五欄）。卡片上緣永遠照下面的順序由上往下，不為了填空回填：越有用的越上面，排版不准為了填滿空間改這個順序（用戶 2026-11-13）。

順序分五組：時間與依專案 → Token → 什麼時候 → 做了什麼 → 花了多少。

1. **`Agent 工作的時間`**
   - 副標 `{範圍}{每小時｜每天｜每週｜每月}，單位：小時`。分桶照 §1.3。
   - 每桶兩根：`Agent 工作時間（同時開的只算一次）` 和 `分開加總（同時開的各算各的）`。照時鐘在桶的邊界切開。
   - 只有時間，沒有 Token 切換；token 在下一組的卡片裡。
2. **`依專案`**
   - 副標 `{範圍}，Agent 花最多時間的專案（分開加總）`；右上連結 `全部 {n} 個 →` 到專案頁。
   - 前 8 個專案，照分開加總排。每列：專案（圖示、名稱、工具圖示，可點）、長條、時數，下面一行 `{n} 段 · {token} token`。
   - 用專案現在的名稱和歸類，你加進專案的資料夾一起算。
3. **`Token 用量`**
   - 副標 `{範圍}{每小時｜每天｜每週｜每月}的 token，按每一則回覆的時間歸入，單位：{萬｜億}`。分桶照 §1.3。
   - 切換 `按種類` / `按工具` / `按模型`；開關 `含讀取快取`（預設關）。
   - 按種類：`輸出`、`輸入`、`寫入快取`，開關打開時加 `讀取快取`。按工具：每個工具一個序列。按模型：前 5 個模型加 `其他 {n} 個`，照 §1.9 每一輪算給回答它的模型。
   - 單位自動：一億以上用億，一萬以上用萬。
4. **`Token 組成`**
   - 副標 `同一個範圍裡，四種 token 各占多少`。
   - 一條分成四段的長條，圖例寫數量和百分比。
   - `讀取快取占 {x}%。Agent 每一輪都把前面的對話重新送一次，大多直接從快取讀，所以這個數字很大，但比一般輸入便宜很多。`
   - 每個工具一條占比（工具名稱、token、`{n} 段`）。
   - 有對話沒有用量紀錄時：`{k} / {n} 段對話有用量紀錄。` 沒有紀錄的大多來自同一個工具的舊版本時，接著說明是哪個工具、從什麼時候開始有紀錄。最後 `沒有紀錄的不算成 0。`
5. **`作息`**
   - 副標 `{範圍}，你在一週裡哪些時段送出訊息`。
   - 24 欄（標 0、6、12、18、23）乘 7 列（週一到週日），格子跟一年日曆一樣大。無障礙名稱 `一週各時段送出的訊息`。
   - 滑過每格時寫 `{週X} {h}:00–{h+1}:00 · {n} 則訊息`；底下 `最常在 {週X} {h}:00 左右送出訊息`；圖例 `少` / `多`。
   - 數的是你送出的每一則訊息，照本地時間。
6. **`你在場的時間（估算）`**
   - 副標是 §1.6 的說明文字。
   - 數值，旁邊 `同一範圍裡 Agent 工作時間 {x}`。
   - `這不是打卡紀錄。Agent 自己跑長任務時你可能不在，所以兩個數字不會一樣。`
7. **`各工具的工作時間`**
   - 副標是 §1.5 的說明文字。每個工具的分開加總時數和 `{n} 段`。
8. **`最久的對話`**
   - 副標 `單一段對話裡 Agent 工作最久的`。
   - 前 6 段，照那段對話在範圍裡的 Agent 工作時間排。每列：圖示、標題、工具、`{專案} · {n} 輪`、時長。點了打開那段對話。
9. **`改動的程式碼`**
   - 副標 `Agent 用編輯工具改檔案時記下的行數，不含它用 shell 指令改的部分`。
   - `+{新增}`（綠）`−{刪除}`（紅），`{k} / {n} 段改過檔案`。
10. **`工具呼叫`**
    - 副標 `共 {n} 次。名稱照各家原本的叫法，Read 和 read_file 是兩個工具`。
    - 前 10 個（工具加呼叫名稱），帶工具標籤，名稱用等寬字。
11. **`模型`**
    - 副標 `每一輪算在回答它的模型；subagent 的算在它自己用的模型`。
    - 前 7 個模型：token 占比（不到 1% 寫 `<1%`，沒有 token 寫 `—`），和 `{n} 段`（主要模型是它的對話數）。
12. **`費用（按 API 牌價）`**（`顯示費用` 關著時沒有這張卡）
    - 副標 `訂閱方案不按 token 收費；這是換成 API 牌價的等值金額，看用量的分量`。
    - 大數字，旁邊 `工具記下的＋估算` 或 `只算工具記下的`。
    - 三列：`工具自己記下的` {金額 · n 段}；`按牌價估算` {金額 · n 段}（估算關著時劃掉）；`沒有牌價（本機模型或沒有用量紀錄）` {n 段}（有才顯示）。
    - 開關 `沒有紀錄的對話按牌價估算`，說明 `牌價表 {版本} 版，跟著 PathKeep 更新；在設定 › Agent 對話也能關`。
13. **`這些數字怎麼算`**（條列）
    - `一段對話：你開的一次對話。它叫出來的 subagent 算在它裡面，不另算一段。`
    - `Agent 工作時間：每一輪從你送出訊息到 Agent 做完。工具自己有記的用它記的（Claude Code 較新的版本會記），其餘從紀錄裡的時間戳推算。「Agent 工作時間」按時鐘算，同時開幾個都只算一次；「分開加總」每段各算各的，兩個一起跑 1 小時就算 2 小時。`
    - `Token：工具寫進紀錄的用量。同一則回覆在 Claude Code 的紀錄裡會重複出現好幾次，只算一次；Codex 記的是累計值，取差值；從別的對話分出來的部分不重算。`
    - `沒有紀錄的不當成 0：每張卡片都會標出有幾段對話有這項資料。`
    - `全部在這台電腦上算，不需要網路，也不需要設定 AI。`

#### 2.5 必須有的狀態

- **載入中**：先畫骨架（五個數字格和四張卡片），數字在背景算好再填進去。每個範圍與篩選的結果會快取。
- **範圍裡沒有對話**：數字列和卡片牆換成一句說明這個範圍裡沒有對話，並提供改成「全部時間」或清掉篩選。不畫成一堆 0 和空的圖。一年日曆照常顯示。
- **篩選後沒有對話**：同上，說明是篩選造成的。
- **都沒有用量紀錄**：`Token` 和費用寫 `—`，下面一行 `0 / {n} 段對話有用量紀錄`。
- **第一次備份還沒跑完**：照目前存下的算，標題下一行說明數字還在增加。
- **還沒有任何對話**（工具都沒找到對話）：說明 PathKeep 在哪些資料夾找過，連到備份頁。
- **讀取失敗**：說明讀不到，提供重試。

桌面後端使用瀏覽洞察目前顯示的時區，依區段傳送數字列、圖表與一年日曆。換範圍只需重讀報告。沒有用量樣本時，總數、平均與圖表資料都以 `null` 表示。命令與覆蓋率欄位見 [Agent Insights](../architecture/desktop-command-surface.md#agent-insights)。

**已做進 app 的部分（2026-11-20）**：§2 的整個畫面在 `src/features/agent-insights/`，是 Agent 空間的第一頁，切換到這個空間和啟用流程的 `看對話` 都到這裡。數字照後端的報告（`get_agent_insights`）一段一段填進來：先畫骨架，數字列、圖表、卡片牆和一年各自到了就換上；換範圍只重讀報告，換年份只重讀那一年，換工具或專案兩個都重讀；新的還沒到時，舊的留在畫面上變淡。備份存進新對話、改了星號或垃圾桶、專案改了歸類時自動重讀；讀到一半剛好有備份存進新對話時，自動再讀一次（最多三次），之後才說讀不到。跟這一節寫的不一樣的地方：

- 網址可以帶 `project=<專案 id>`（§2.1 原本「沒有網址參數」，2026-11-20 為了讓專案的頁面能打開它的洞察而加）。專案選單的 `洞察` 和專案頁標頭的 `洞察` 都到這裡（§5.11）。標題下一行寫 `只看這個專案：{名稱}` 和一個 ✕（`看全部專案`）。篩選裡選專案也寫進網址；工具不寫進網址，回來就不在了。網址裡的專案不存在時寫 `找不到這個專案` 和 `它的資料夾可能已經加到別的專案裡了。`（同 §5.10），提供 `看全部專案`，不畫一份什麼都沒有的報告。
- 範圍、`≈` 的說法和兩個費用開關存在後端（`get_agent_insights_preferences` / `set_agent_insights_preferences`），別的視窗改了這裡也跟著變。閱讀器的資訊面板跟著同兩個開關：`顯示費用` 關著時沒有費用那幾列，估算關著時沒有估算那一列，也不寫 `有 {n} 次回覆用的模型沒有牌價，沒算進去。`；開著的面板在開關改了時重讀。
- 從洞察到紀錄的連結都帶著同樣的工具和專案：`對話` 格（再加上範圍）、一年日曆的格子、`最忙的一天`，以及 `Agent 工作的時間` 和 `Token 用量` 上按天的長條（§2.3 只寫了 `day`）。按小時、週、月的長條不能點，紀錄沒有這種範圍。
- Agent 工作時間的 ⓘ：有對話既沒有記下時長、也推算不出來時，多一句 `有 {n} 段既沒有記下時長，也推算不出來；它們不算進來，不當成 0。`，因為這時 §1.4 那句「其餘從時間戳推算」不對。
- 一年日曆裡有對話但沒有時長紀錄的日子，格子是空的顏色，滑過寫 `{日期} · 有對話，但沒有時長紀錄`；月份長條寫 `{m} 月 · 沒有時長紀錄`。
- 依專案、各工具的工作時間：部分對話沒有用量或時長紀錄時，那一列多寫 `{k} / {n} 段有用量紀錄` 或 `{k} / {n} 段有時長紀錄`（§1.11）。作息卡在有訊息沒有時間時多一行 `有 {n} 則訊息沒有時間，不在圖裡。`；改動的程式碼卡在有編輯整個換掉檔案時多一行 `有 {n} 次編輯整個換掉了檔案，它們的行數不算進來。`
- 圖表滑過時，沒有紀錄的那一桶寫 `沒有紀錄`，不寫 0；Token 圖那一桶有對話沒有用量紀錄時加一行 `{k} / {n} 段對話有用量紀錄`。Token 圖的單位：中文用萬、億，英文用 thousands、millions、billions。
- 顏色：Token 的四種跟閱讀器資訊面板一樣（輸出、輸入、寫入快取、讀取快取依序是 `--chart-1`、`--chart-2`、`--chart-3`、`--chart-5`）；工具固定 Claude Code `--chart-2`、Codex `--chart-1`、Pi `--chart-3`、DeepSeek Harness `--chart-5`；模型照名次用 `--chart-1` … `--chart-5`，其餘 `--chart-other`。
- 第一次備份還沒跑完、存檔裡還沒有對話時，寫範圍裡沒有對話（不寫「還沒有任何對話」），標題下那一行說備份還在跑。
- 英文：洞察是 Insights，`你在場的時間` 是 "Time you were there"，`分開加總` 是 "Summed"，`≈` 的兩種說法是 "days nonstop" 和 "full-time work"。

E2E：`tests/e2e/agent-insights-1-report.spec.ts`、`-2-project.spec.ts`、`-3-zone.spec.ts`，Playwright 專案 `agent-insights`，接在 `agent-chats` 後面。

### 3. 紀錄 `#/agent/chats`

紀錄清單和閱讀器已有桌面命令。清單依排序鍵翻頁，閱讀器依選定分支的顯示列、原始紀錄或提問目錄翻頁。兩個畫面的欄位、單位、範例和錯誤代碼見[視窗命令](../architecture/desktop-command-surface.md#conversation-list-and-reader)。專案篩選用的是專案的 id（§5，`list_agent_projects`），一個專案的對話包括你加進來的資料夾裡的。

- **主要的事**：找到並打開一段對話。
- 左邊是清單（約 400 px，視窗較窄時約 360 px），右邊是閱讀器（§4）。
- 沒選對話時右邊寫 `選一段對話來看`，下面三行按鍵說明：`↑ ↓ 切換對話`、`/ 搜尋全部對話`、`⌘K 跳到任何地方`。

**已做進 app 的部分（2026-11-20）**：清單、篩選（專案、工具、時間、只看）、排序、分組、條件標籤、右鍵選單、§3.3 的狀態，和 §3.4 的搜尋（網址的 `q`、`roles`、`find`、`at`，搜尋框、`/`、⌘F）都在 app 裡，閱讀器見 §4。同一個工作台也是一個專案的頁面（§5.10）。跟這一節寫的不一樣的地方：

- 篩選裡的專案清單就是專案頁的全部專案（`list_agent_projects`），圖示分 git repo、一般資料夾、零散資料夾；`全部 {n} 個專案` 的 n 是專案總數。
- `紀錄` 這個標題只給螢幕閱讀器念，它的位置放搜尋框。
- 沒有日期的對話歸在 `沒有日期` 這一組；沒有標題的對話寫 `沒有標題的對話`。
- 垃圾桶裡的列，右鍵選單跟平常一樣，只是最後一項換成 `放回`。
- 英文介面裡「封存」寫 "Put away"，取消封存寫 "Bring back"。
- 搜尋：
  - 停在中途（`停止`）時，已經找到的卡片留著，那一行寫 `已停止：找到 {n} 段、{m} 處 · 搜過 {s} / {t}`。
  - 搜尋的狀態行一秒最多念一次，找完時馬上念。
  - 結果卡片照後端送來的順序（最近活動）排，同一段對話後來的卡片取代原本的那張，位置不動。
  - 結果清單不能用 ↑ ↓ 換對話（§3.4 沒寫；清單才有）。
  - 開著閱讀器時 ⌘F 打開閱讀器的找字列（§4.4）；沒開時 ⌘F 和 `/` 一樣跳到搜尋框。
  - 篩選選單在搜尋時不出現排序和分組。
- 語意搜尋（2026-11-20）：搜尋時搜尋框下面多一排 `全文` / `語意`（網址 `mode=semantic`；全文是預設，不寫進網址，沒有 `q` 時也留著，下一次搜尋照用）。語意模式用 `建立語意搜尋索引` 建好的索引，把意思相近的段落一段一段列出：最相近的在最上面，一次載入一頁（最多 100 段），捲到接近底部時自動載入下一頁，直到後端說沒有下一頁為止。沒有分數門檻，所以載到最後，索引裡每一段符合條件的都會出現；結果虛擬化。每段寫對話標題、工具、誰說的、時間和那一段的文字，沒有標亮的字，不顯示分數。`搜哪些內容` 四顆照樣有效。點一段在右邊打開存著那筆紀錄的對話，停在那一筆（`chat`、`at`，不帶 `find`）；subagent 的段落打開那個 subagent 本身。狀態行寫 `{n} 個段落，最相近的在前 · 往下捲會繼續載入`，全部載完時寫 `· 已全部載入`，下一行寫索引用哪個模型、什麼時候建的、之後對話有沒有變動（正在更新時也說）。某一頁失敗時，已載入的段落留著，清單底部寫 `沒能載入更多段落` 和 `再試一次`（同一頁再要一次，不會重複）；按 `停止` 取消正在載入的那一頁，底部給 `繼續搜尋`；索引、對話或它們的標記中途變了（`stale_cursor`）就從第一頁重來。

  搜尋之前只看索引本身的狀態：沒選 embedding 模型、第一次建立中（已讀幾個段落）或暫停、上次建立失敗（後端給了原因時寫出原因和該去哪裡改）、還沒建，這些不送出搜尋，直接說原因並連到該去的設定頁。AI、語意搜尋、`建立語意搜尋索引` 或 Agent 對話關著時，索引狀態只說「不能用」，所以照樣送出搜尋，由後端的拒絕代碼說是哪一個（`AI 關著`、`語意搜尋關著`、`對話的語意搜尋關著`、`Agent 對話關著`……，跟設定頁、Ask 同一組字），連到「設定 › AI」、「設定 › Agent 對話」或「管理資料類型」。會自己過去的原因（embedding 服務沒回應、模型換了、內建模型不能用）附 `再試一次`；已經有段落時，這種拒絕寫在清單底部，段落留著。被拒絕之後索引狀態一變就自動再送一次。後端說索引還不能用時也一樣。每一種都有 `改搜全文`，`語意` 那一顆不會變灰，也不會自己退回全文。語意模式下搜尋框的提示字是 `描述你要找的內容…`；`/…/` 和 `"…"` 照字送出，不當語法。每停一下打字就送一次搜尋，用遠端 embedding 服務時搜尋的字句會送過去（跟瀏覽紀錄的語意搜尋一樣）。

| `day`     | `YYYY-MM-DD`，只列那天有活動的對話                 | 沒有               |
| `flags`   | 「只看」的條件，逗號分隔（含 `archived`、`trash`） | 沒有               |
| `sort`    | 排序                                               | 最近活動           |
| `group`   | 分組                                               | 按日期             |

| `find`    | 閱讀器裡找的字                                     | 沒有               |
| `at`      | 閱讀器停在哪一筆紀錄                               | 沒有               |
| `mode`    | 搜尋方式：`semantic` 照意思搜（用語意索引）        | 全文               |

有 `find` 時，`at` 是要先看的那一處；沒有 `find` 時（語意搜尋的結果、Ask 的引用），閱讀器讀到標頭後直接把那一筆捲到中間，短暫標出來（在 Pi 的另一條分支上就切到那條，不在任何一條上就打開原始紀錄）；那一筆不在這段對話裡時說 `這段對話裡已經沒有那一筆紀錄`。

大多數改動取代目前的瀏覽紀錄；送出一次搜尋、按「只看這個專案」會新增一筆，所以上一頁回得去。

`day` 和 `range` 二選一：選了時間範圍就拿掉日期。`day` 以一個可移除的條件顯示（`{M月D日}`）。

#### 3.2 工具列

**搜尋框**：提示字 `搜尋所有對話…`（只看一個專案時 `搜尋這個專案的對話…`）。

- 停止輸入 280 ms 後送出；輸入法組字中不送；按 Enter 立刻送；按 Esc 清掉。
- 空的時候右邊顯示 `/` 鍵，有字時是清除鈕（無障礙名稱 `清除搜尋`）。
- 在任何文字輸入框以外按 `/` 都會跳到這裡。沒打開閱讀器時，⌘F（Windows、Linux：Ctrl+F）也會。

**篩選按鈕**：只有圖示，有條件時加一個數字。專案、每個工具、不是全部時間的範圍、日期、每個「只看」條件各算一個；排序和分組不算。無障礙名稱 `篩選（{n} 個條件）` / `篩選與排序`。

篩選選單，照這個順序：

| 區塊   | 內容                                                                                                                                                                                             |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `專案` | 只看一個專案時不出現。下拉搜尋，顯示 `全部 {n} 個專案` 或目前的專案；搜尋框 `找專案…`；沒有結果 `沒有這個專案`；選了專案時多一項 `全部專案`。每列：圖示、名稱、最近活動（相對時間）、勾          |
| `工具` | `全部`（沒選任何工具時亮著），加上每個工具一顆，可多選                                                                                                                                           |
| `時間` | `全部時間`、`今天`、`7 天`、`30 天`、`90 天`、`1 年`，單選（§1.2）                                                                                                                               |
| `只看` | 可多選，要同時成立：`已加星`、`只剩 PathKeep 有`、`有開 PR`、`用了 subagent`、`有改檔案`、`沒有用量紀錄`、`已封存`、`垃圾桶`。選了 `已封存` 時只列封存的對話；選了 `垃圾桶` 時只列垃圾桶裡的對話 |
| `排序` | 搜尋時不出現。`最近活動`、`開始時間`、`Agent 工作時間`、`Token 用量`、`來回輪數`                                                                                                                 |
| `分組` | 搜尋時不出現。`按日期`、`按專案`、`不分組`。只看一個專案時沒有 `按專案`                                                                                                                          |

- 按日期分組時改用 `Agent 工作時間`、`Token 用量` 或 `來回輪數` 排序，分組自動改成 `不分組`。
- 照 `開始時間` 排序時，每列的時間和按日期的分組都改用開始時間。

**條件標籤**：搜尋框下面，每個作用中的條件一個（專案、每個工具、範圍、日期、每個「只看」），各有一個 ×（無障礙名稱 `移除這個條件`）。兩個以上時多一個 `全部清除`；只看一個專案的頁面上，`全部清除` 不清掉那個專案。

#### 3.3 清單

- 虛擬化。清單有焦點時 ↑ ↓ 或 k j 換選取的對話（無障礙名稱 `對話列表，用上下鍵切換`），選到的那列捲進畫面。
- 封存的對話不在清單裡，除非選了 `只看 › 已封存`。垃圾桶裡的對話只在 `只看 › 垃圾桶` 裡出現。
- 正在看的對話被移到垃圾桶時，閱讀器關掉。

**分組**

- `按日期`：照本地日期分（照排序用的時間，預設是最後活動）。標題 `今天 · 11月13日 週五`、`昨天 · 11月12日 週四`，其他 `11月10日 週二`，不是今年時加年份。
- `按專案`：標題是專案圖示和名稱，每個專案最多 3 段，下面 `還有 {n} 段，只看這個專案 →`，點了設成只看這個專案、按日期分組。
- `不分組`：一條清單。
- 各組出現的順序照它第一段對話在排序裡的位置。

**分組標題**：從左邊到右邊的淡色橫條，上下各一條細線，上面多留一點空，右邊寫 `{n} 段`。列是圓角、內縮的，分組標題用列沒有的樣子，快速捲動時一眼找得到。捲動時目前這一組的標題釘在頂端，底下經過的列模糊掉；那一組自己的標題還在原位時不釘，所以清單最上面只有一條；下一組的標題到頂時把它推上去。

**每一列**只有：

- 第一行：標題，右邊是時間。標題取自你的第一則訊息時用一般字重，其他（工具給的、你改過的）用中等字重。
- 時間：按日期分組時只寫 `14:32`。其他分組寫 `今天 14:32`、`昨天 14:32`、`週二 14:32`（這一週）、`10月28日`（今年）、`2025年6月3日`。
- 第二行：工具圖示、專案圖示和名稱（按專案分組或只看一個專案時不寫），右邊依序：
  - 星號（無障礙名稱 `已加星`）；
  - 「只剩 PathKeep 有」的圖示，滑過時寫 `工具自己的資料夾裡已經沒有這段對話，只有 PathKeep 的存檔還留著。`；
  - 封存的圖示（無障礙名稱 `已封存`）；
  - 照 Agent 工作時間、Token 用量或來回輪數排序時，那個數字：`{n} 小時` / `{n} 分`、`{n} token` 或 `沒有紀錄`、`{n} 輪`。

token、時間、subagent、分支、PR 都不放在列上，在閱讀器的資訊面板裡。

**右鍵選單**（在一列上按右鍵；列以外的地方沒有選單）：

| 項目                  | 做什麼                            |
| --------------------- | --------------------------------- |
| `打開`                | 在右邊打開                        |
| `全頁打開`            | 到 `#/agent/chat/:id`             |
| `加星號` / `取消星號` | 切換星號                          |
| （分隔線）            |                                   |
| `封存` / `取消封存`   | §8.1                              |
| `移到垃圾桶`          | §8.2；在垃圾桶裡的列上換成 `放回` |

**必須有的狀態**

- 沒有符合的：`沒有符合條件的對話。` / `試試放寬時間或清除篩選。`
- 載入中：骨架列。
- 讀取失敗：說明讀不到，提供重試。
- 還沒有任何對話：說明 PathKeep 在哪些資料夾找過，連到備份頁。
- 第一次備份還沒跑完：列出目前存下的，頂端一行說明還在備份。
- 備份進行中：清單照樣能捲動、翻頁；新存下的對話出現在該出現的位置，不會讓清單跳回頂端。

#### 3.4 搜尋

輸入 `q` 時，搜尋結果取代清單，排序和分組不出現。

**搜哪些對話**：符合目前篩選（專案、工具、範圍或日期、「只看」）的對話，含封存的（標出 `已封存`），不含垃圾桶裡的。選了 `只看 › 垃圾桶` 時只搜垃圾桶。

**怎麼比對**

寫法跟瀏覽紀錄的搜尋一樣，v0.6 只有這三種：

| 寫法       | 意思                                        |
| ---------- | ------------------------------------------- |
| `字 字`    | 每個字都要出現在同一筆紀錄裡，順序不拘      |
| `"一串字"` | 片語：這幾個字相鄰、照這個順序出現          |
| `/…/`      | 正規表示式。寫錯時說 `這個正規表示式寫錯了` |

- 都不分大小寫。
- 標題一定搜。另外 `搜哪些內容` 四顆：`你說的`、`Agent 說的`、`工具輸出`、`思考`。開著的有勾，關著的是虛線加刪除線，至少留一顆開著。`工具輸出` 包含工具的參數和輸出。

**結果一邊找一邊出來**

- 每段對話一張卡，照最近活動排。數字只會變大，不會跳回去。
- 找的時候：`已找到 {n} 段、{m} 處 · 搜尋中 {s} / {t}`，加一條進度條。
- 找完：`{n} 段對話、共 {m} 處符合 · 搜完{篩選後的} {t} 段`（有篩選時才有「篩選後的」）。這兩行用 aria-live（polite）念出來。
- 沒有上限，不截斷，每一個符合的都找得到。
- 改了搜尋字或離開這一頁時，前一次的搜尋停下來。
- 結果清單虛擬化。

**結果卡**

- 第一行：工具標籤、標題、`{n} 處`。
- 第二行：專案、時間、「只剩 PathKeep 有」的圖示、`已封存`（有字）。
- 最多 3 段摘錄：角色 `你` / `Agent` / `工具` / `思考`，符合處前約 36 字、後約 60 字，空白收成一個，截斷處加 `…`，符合的字標亮，最多兩行。
- 更多時：`這段對話裡還有 {n} 處，打開後按 Enter 逐一看`。
- 只有標題符合時：寫 `標題符合`，沒有摘錄。
- subagent 的紀錄也搜。它的符合處算在派出它的那段對話的卡片裡，摘錄前面多一個 `subagent` 標籤。

**打開**

- 點標題，停在第一段摘錄的那一筆紀錄；點一段摘錄，停在那一筆。只有標題符合時從頭打開。
- subagent 的摘錄打開那個 subagent，停在符合的那一筆。
- 打開時帶上 `chat`、`find`（搜尋的字）、`at`（那一筆紀錄），閱讀器的「在這段對話裡找」用同一串字打開，寫法照上表。

**沒有結果**：`沒有對話提到「{q}」。`，下一行說這次搜了什麼：

- 沒有篩選、四種內容都開著：`搜尋涵蓋全部 {t} 段對話裡你說的、Agent 說的、工具輸出和思考。`
- 有篩選或關了某幾種內容時，照實寫：`搜尋涵蓋符合篩選的 {t} 段對話裡{開著的那幾種}。`

**必須有的狀態**

- 備份進行中：搜尋照樣回答，讀最後一次存好的索引，並說明索引落後多少（例如還有幾段對話沒進索引）。
- `/…/` 裡沒有可用的字面字，只能逐段掃：照常顯示進度，可以停。
- 搜尋失敗（索引讀不到或損壞）：說明原因，不顯示成「沒有結果」。

#### 3.5 Ask 引用

「設定 › Agent 對話」的 `助理可以讀 Agent 對話` 開著，而且「設定 › AI」的助理也開著時，助理可以用 `search_agent_conversations` 搜已存的 Agent 對話，一次最多 8 段。它用的是紀錄的字面搜尋索引，不需要語意索引。

- 回答下面每一筆引用的紀錄是一個標籤：寫那段對話自己的標題，前面是工具的圖示。標題還沒讀到或讀不到時（空間關著、存檔鎖著、對話不在了），先寫引用那段的開頭，圖示用 Agent 空間的。滑過標籤寫 `{標題} · {工具} · 「{段落}」`。
- 同一段對話引用了兩筆紀錄就有兩個標籤，同一筆引用兩次只有一個。
- 這組標籤叫 `用到的 Agent 對話`；同時引用了網頁時叫 `用到的頁面和 Agent 對話`；只有網頁時照舊叫 `用到的頁面`。
- 第一個引用是對話紀錄時，回答下面的按鈕寫 `開啟這段 Agent 對話`，不寫 `在紀錄中開啟`，因為 Agent 空間的清單頁也叫「紀錄」。
- 標籤、這個按鈕，以及模型寫在回答裡的 `pathkeep://conversation/open?…` 連結，都在 app 裡打開 Agent › 紀錄，閱讀器停在那一筆（`?chat=…&at=<序號>:<來源>`，沒有要找的字），把那一筆捲到中間並短暫標出來，不交給系統；其他 `pathkeep:` 連結只當文字顯示。那一筆已經不在這段對話裡時，閱讀器說 `這段對話裡已經沒有那一筆紀錄`。
- 引用的紀錄在 subagent 裡時，`conversationId` 是 subagent 自己的，閱讀器單獨打開那個 subagent，不是在主對話的側邊欄裡。
- 關掉開關後，新的問題不再提供這個工具。在引用過對話的 Ask 對話裡接著問時，從第一個引用 Agent 對話的回答起，之後的回答都不再送給模型，你自己問的問題照送。已經存下的標籤照樣顯示，因為那是這台電腦自己的紀錄。
- 匯出成 Markdown 時，每個回答引用的對話列在 `用到的 Agent 對話` 下面（介面照自己的語言送這個標題），寫那段對話現在的標題；讀不到標題時寫 `新對話`（跟 Ask 自己沒有標題時同一個字，後端只收一個「沒有標題」）。引用的網頁照舊列在 `用到的頁面` 下面。
- 後端拒絕回答並說了原因時（AI 或助理在「設定 › AI」裡關著：`ai-disabled`、`assistant-disabled`），失敗的回答不寫後端的原文，寫那個原因（例如 `助理關著` / `在「設定 › AI」裡打開助理。`），附 `設定 › AI` 按鈕，跟紀錄的語意搜尋用同一組字（`aiRefusals`）。這個原因不存下來，重開對話時那一則照舊寫 `這則回答沒有完成。`。回答途中才被拒絕（例如途中關掉了 `助理可以讀 Agent 對話`）時，後端的錯誤沒有帶代碼，照舊寫後端的原文。

### 4. 閱讀器

- **主要的事**：讀這段對話、接著做。
- 兩種開法：在紀錄頁右邊（目錄關著，有關閉鈕）；全頁 `#/agent/chat/:id`（目錄開著，關閉回到上一頁）。
- 從清單打開時停在開頭；從搜尋結果打開時停在符合的那一筆。要到最後用 ⋯ 的 `跳到最後`。沒有另外「跳到第幾筆」的控制。

**已做進 app 的部分（2026-11-20）**：兩種開法、標頭、繼續對話（含確認過版本的接續指令）、⋯ 選單（含 `匯出 ▸` 和選取原始檔的 `在 Finder 顯示`）、改名、內容（依顯示列一段一段讀，虛擬化）、目錄、資訊面板、原始紀錄、subagent 側邊面板、提問的版本切換、在這段對話裡找（§4.6）和 ⌘F，以及 §4.9 的狀態。閱讀器跟著「設定 › Agent 對話」的兩個閱讀開關（§7）和兩個費用開關。

跟這一節寫的不一樣的地方：

- 標頭和資訊面板裡的專案連到那個專案的頁面（§5.10）。
- 找字：
  - 寫法跟搜尋一樣，打字後約 280 ms 才找，輸入法組字時不找。
  - Enter 和 Shift+Enter 到底時繞回另一頭。
  - 標亮用瀏覽器的 CSS Custom Highlight API，不改動畫面上的列。webview 沒有它時不標亮，計數和跳到下一個照樣能用。
  - 工具的參數只畫出一行摘要，符合處不在那一行裡時，會打開那次呼叫、跳到那裡，但沒有字可標亮；改檔的呼叫畫的是 diff，輸出裡的符合處也一樣。
  - 符合處在 Pi 的另一條分支上時，切到經過那一筆的分支；不在任何顯示列上的（例如更早的來源檔、找不到上一筆的紀錄），打開原始紀錄並捲到那一筆。
  - subagent 側邊面板開著時，找字列放在面板最上面，Esc 先關找字列、再關面板。
  - 跳到某一處時讀不到它所在的地方（例如 subagent 的資料），那一處仍算目前這個，通知 `沒辦法顯示這一處`。
- `在 Finder 顯示`（Windows、Linux 各用自己檔案管理員的名稱）選取工具的原始檔；系統無法選取時打開所在資料夾。工具已經刪掉這段對話時這一項不能按。
- `匯出 ▸`：選了格式之後，系統的存檔對話框問存到哪裡（建議的檔名是 `conversation.<副檔名>`）；寫檔時通知 `正在匯出成 {格式}…`，下面寫 `已寫入 {大小}`（寫完之前不知道多大，所以是數字，不是進度條；最多半秒換一次，螢幕閱讀器才不會一直念），附 `停止`。按了 `停止` 寫 `正在停止匯出…`；後端接受了就是 `已停止匯出` / `什麼都沒有寫入。原本就在那裡的檔案維持原樣。`；檔案已經在放到位時停不了，寫 `來不及停止了：檔案正在放到選好的位置。`，接著照常完成；停止本身失敗時另一則通知 `沒能停止匯出` 和原因，`停止` 還在。同一個閱讀器一次只匯出一個，進行中子選單寫 `正在匯出…`、各格式不能按。完成時通知 `已匯出成 {格式}`，寫出檔案的位置，附 `在 Finder 顯示`（選取那個檔案），停留 10 秒；在存檔對話框按取消就什麼都不說。失敗時說原因：匯出途中對話有了變化（`再匯出一次`，閱讀器同時重讀標頭）、選的位置在存檔或工具的資料夾裡（換一個地方）、存下的內容讀不了（什麼都沒寫入），其他照後端的說法。HTML 與 Markdown 照閱讀器現在顯示的那一條（Pi 的分支也一樣）、照視窗的語言寫標籤；HTML 的工具呼叫照「預設收起工具呼叫」收起或展開，「顯示思考過程」關著時兩種都不含思考。
- 「設定 › Agent 對話」的「顯示思考過程」關著時，思考那一行不顯示，只有工具呼叫和思考的一列併進前後的工具呼叫；「預設收起工具呼叫」關著時每一組預設展開，你自己收起或打開過的那一組維持你的選擇。偏好第一次讀到之前，閱讀器先放骨架，不會先畫出思考再拿掉。
- 工具沒記錄思考花了多久時，那一行只寫 `思考過程`。
- `繼續對話`：已確認的 Claude Code 與 Codex CLI 版本可複製接續指令，其他版本可複製工作階段 ID。版本與依據見[接續指令表](../architecture/research/agent-history/resume-commands.md)。指令除了 `cd {工作資料夾}` 和工具的接續指令，還把工具的資料夾設成存下這段對話的那一個（`CLAUDE_CONFIG_DIR=…`、`CODEX_HOME=…`），這樣有好幾個工具資料夾的電腦也接得到同一段；Windows 上是 PowerShell 的寫法。只有從終端機（CLI）開的對話有指令，Claude 桌面應用程式與 Codex 桌面版開的只能複製工作階段 ID。
- 對話中的提示依種類分語氣：你中斷的那一輪是灰色、工具重試是黃色、API 錯誤是紅色。

#### 4.1 標頭

**第一行**：標題（半粗；取自你的第一則訊息時用中等字重；滑過看完整標題），右邊依序：

- `加星號` / `取消星號`；
- `繼續對話 ▾`（§4.2）；
- 資訊（無障礙名稱 `資訊`，切換資訊面板）；
- `⋯`（無障礙名稱 `更多`，§4.3）；
- `×`，滑過時寫 `關閉（Esc）`（只有在紀錄頁右邊時）。

**第二行**：工具圖示和名稱 · 專案（可點，到那個專案）· 開始的日期與時間（`2026年11月13日 14:32`）· `Agent {時長}` · 封存時 `已封存`。

**橫幅**只有一種，一行：這段對話只剩 PathKeep 有時，`{工具} 已經刪掉這段對話；這是 PathKeep 在 {時間} 存下的版本。` 第二行不再重複這件事。工作資料夾已刪除（例如 worktree 刪了）不放橫幅，寫在「繼續對話」選單和資訊面板裡。

**正在看原始紀錄時**，標頭下一行 `正在看原始紀錄。` 加 `回到對話`。

**找字列**（打開「在這段對話裡找」時）：輸入框 `在這段對話裡找…`（寫法跟搜尋一樣，§3.4）、計數 `{i} / {n}` 或 `沒有`、按鈕 `上一個`、`下一個`、`關閉找字`。Enter 下一個，Shift+Enter 上一個，Esc 關掉。

#### 4.2 繼續對話

點開是一個小視窗：

PathKeep 只替接續指令確認過的工具版本複製指令。確認是照工具自己的文件或原始碼，不是猜的。

- **確認過的版本**：`在終端機用 {工具} 接著這段對話：`，下面一個程式碼框，內容是 `cd {工作資料夾} && {工具的接續指令}`。按鈕 `複製指令`，複製後通知 `指令已複製，貼到終端機就能繼續`。
- **其他版本**：不給指令，只有 `複製工作階段 ID`，複製後通知 `工作階段 ID 已複製`。
- **只剩 PathKeep 有**時：不給指令，寫 `{工具} 的資料夾裡已經沒有這段對話，沒辦法在 {工具} 裡接著做。`
- **工作資料夾已經刪了**（而工具的檔案還在）時，指令上面多一行：`工作資料夾已經刪了。要在原處接著做，得先在同一個路徑把資料夾建回來（例如重新建立 worktree）。`
- 註腳 `PathKeep 不會替你開終端機或啟動 {工具}。`

#### 4.5 內容

- 虛擬化，只讀畫面附近的一段紀錄，捲到哪裡讀到哪裡。內文欄限制行寬（約 760 px）。
- **目錄** `你說過的話 · {n}`：右邊一欄（約 220 px），視窗夠寬（約 1180 px 以上）時才有。列出你每一則訊息和它是第幾輪，最多兩行；畫面最上面那一輪標亮；點了捲到那裡。全頁打開時預設開著，在紀錄頁右邊時預設關著。

每一種紀錄怎麼顯示：

- **你的訊息**：靠右的泡泡，上面 `你 · 14:32`。
  - 你改寫過這則訊息時有版本切換 `第 {v} / {n} 版`（無障礙名稱 `上一個版本` / `下一個版本`），預設是工具最後採用的那一條。選了較早的版本，它後面的所有內容都換成從那個版本接下去的那一條分支，並多一行：`這是你改寫前的版本，下面是從它接下去的那一條分支（{n} 筆紀錄）。PathKeep 兩條都存了；預設顯示工具最後採用的那一條。`
  - 附件：圖片顯示縮圖，其他檔案顯示一個有檔名的標籤。PathKeep 拿不到的附件是虛線標籤，寫檔名和原因，例如 `· 工具沒有把這張圖存進對話紀錄，所以 PathKeep 也拿不到`。
- **思考**：收成一行 `思考了 {時長}` ▾，點開是全文（斜體）。「設定 › Agent 對話 › 顯示思考過程」關掉時不顯示。
- **工具呼叫**：每一組一行 `用了 {n} 次工具 · 改了 +{x} −{y} 行`（沒改檔時只有前半）。有失敗的只多一個小點，滑過時寫 `{n} 次沒成功`。
  - 點開：一行摘要（例如 `Read ×3 · Bash`，有失敗時加 `{n} 次沒成功`），下面每次呼叫一列：圖示、工具名稱、參數、`+x −y`、`失敗` 或 `你拒絕了`、時長。
  - 點一次呼叫：有改檔時是著色的 diff，否則是輸出（太長時在框裡捲動），沒有輸出時 `這個工具沒有輸出。`
  - 「設定 › Agent 對話 › 預設收起工具呼叫」關掉時，每一組預設是展開的。
- **Agent 的回覆**：Markdown。
- **subagent**：一張小卡 `subagent {標題} {時長} ›`。連續派出好幾個時收成一行：`派出 {n} 個 subagent · {類型、類型} · 合計 {時長}`，點開才是一張張卡。點一張卡從側邊打開：
  - 標題；說明 `subagent · {類型} · {模型} · {時長} · {token} token`；
  - `subagent 有自己的紀錄檔；PathKeep 把它掛在呼叫它的那一步底下，不在列表裡單獨列出。`
  - 下面是 subagent 自己的紀錄，顯示方式跟這裡一樣。
  - 它又派出的 subagent 在裡面一樣是一張卡。點開時取代目前的內容，上面有 `‹ {上一層的標題}` 回到上一層。
- **壓縮**：一條分隔線 `上下文在這裡壓縮了（壓縮前約 {x} token）`，下面 `從這裡開始，Agent 只看得到前面的摘要；上面的完整內容 PathKeep 都留著。` 和 `看 Agent 拿到的摘要` / `收起摘要`。
- **狀況**（工具記下的中斷、重試、錯誤）分三種，各有圖示和文字，不只靠顏色：
  - 一般（灰）：例如 `你中斷了這一輪，Agent 沒有回覆`。
  - 警告：例如 `API 回傳 529（過載），工具自動重試了 2 次後成功`。
  - 錯誤（紅）：工具記下的失敗，例如重試後仍然失敗的 API 錯誤。
- **每一輪的結尾**：滑過這一輪、或鍵盤焦點在這一輪裡時，最後出現一行 `這一輪 {時長} · {x} token · {模型}`（沒有用量紀錄時 `沒有用量紀錄`），滑過 token 看 `輸出 / 輸入 / 寫入快取 / 讀取快取` 各多少。被你中斷的那一輪也有，寫 `這一輪 {時長} · 中斷了`，有用量時接著寫用量。

#### 4.6 在這段對話裡找

- 找每一筆紀錄，包括收起來、還沒捲到的：你的訊息、Agent 的回覆（不含 Markdown 符號）、思考、工具的參數與輸出、subagent 的標題。
- 不分大小寫；寫法跟搜尋一樣（§3.4），`/…/` 是正規表示式。
- 符合的字標亮，目前這一個更明顯。
- 符合處在收起的工具呼叫、思考、subagent 群組裡時，那一組自動打開。
- 也找 subagent 裡的紀錄；跳到那裡時打開那個 subagent。
- 長對話一邊找一邊更新計數。

| `在哪裡做的`（開） | `專案`（可點）；`資料夾`（等寬字，不在時加 `worktree 已刪除` 或 `資料夾已不在磁碟上`）；`遠端`；`分支`；`開始時的 commit`                                                                                                                                                                                                                                                                    |
| `改動`（收）       | `程式碼` `+x −y 行 · {n} 個檔案` 或 `沒有改任何檔案。`；`PR` `{repo}#{n}`，點了在瀏覽器打開                                                                                                                                                                                                                                                                                                  |
| `用什麼做的`（收） | `工具`（名稱與版本）；`從哪裡開`（`終端機（CLI）`、`VS Code 擴充`、`桌面 App`、`SDK / 腳本`、`Codex App`）；`模型`（主要模型在前，其他用 `、` 接）；`推理強度`；`權限模式`；`壓縮` `{n} 次`；`API 錯誤` `{n} 次`（都重試成功時加 `（都重試成功）`）                                                                                                                                          |
| `保存`（收）       | `狀態` `只剩 PathKeep 有：工具資料夾裡的檔案已經不在` 或 `工具資料夾裡也還在`；`原始檔`（路徑）；`大小` `{大小} · {n} 筆紀錄 · 另有 {n} 個 subagent 檔`；`上次備份`（這段對話的檔案最後一次被存下的時間）                                                                                                                                                                                    |

`遠端`、`分支` 來自備份時讀到的 `.git`；`開始時的 commit` 只有工具自己記下時才有。

#### 4.8 原始紀錄

- 開頭：`原始紀錄 {n} 筆，PathKeep 一字不改地保存。對話是從這些紀錄整理出來的；其中 {k} 筆（檔案快照、權限切換、用量狀態等）不會出現在對話裡。`
- 每筆一列：`#`、`類型`、`時間`、`大小`，最後是 `在對話中看`（跳到那一筆）或 `不顯示`。虛擬化。
- 點一列展開成那一筆的 JSON 原文，旁邊一個 `複製`，複製後通知 `已複製`。

#### 4.9 必須有的狀態

- **載入中**：100 ms 內先出骨架；捲到還沒讀的段落時，那一段先放佔位。
- **讀取失敗**：說明讀不到，提供重試；已經讀到的段落留著。
- **找不到這段對話**（網址的 id 不存在）：`找不到這段對話`。
- **在垃圾桶裡**：最上面一行 `這段對話在垃圾桶裡。` 和 `放回`。
- **有紀錄解析不了**：一行說明有幾筆沒整理進對話，連到原始紀錄。解析不了不等於對話是空的。
- **很長的對話**（上萬筆紀錄）：打開、捲動、跳到某一筆、找字都不用先讀完整段。

### 5. 專案 `#/agent/projects`

- **主要的事**：到某個專案的對話；把在意的專案照自己的方式排好。

**已做進 app 的部分（2026-11-20）**：三種看法、每一列、釘選和區塊（含拖曳）、其他專案、專案選單、改名、專案設定、加入資料夾、可能屬於同一個專案的資料夾、一個專案的頁面，以及 §5.12 的狀態。還沒做的：

- 專案洞察（§5.11），以及專案選單和專案頁標頭的 `洞察`：還沒有專案洞察的視窗命令，Agent 的洞察頁也還沒做。

跟這一節寫的不一樣的地方：

- 拖曳用 dnd-kit 的滑鼠和鍵盤感應器，不用 HTML5 拖放：桌面 app 自己接收拖進來的檔案，這時 Windows 的 webview 不把 HTML5 拖放事件交給頁面。每一種移動在選單裡都做得到。
- 釘選卡的列不虛擬化（是你自己放的那幾個）；其他專案、清單和資料夾看法的列跟著頁面捲動虛擬化。
- 釘選的英文是 Pin，簡體中文是「置顶」；區塊在簡體中文是「分区」。
- `30 天內有活動` 是後端的範圍：今天和前 29 天，照洞察的時區。
- 同名專案寫完整路徑，看的是全部專案裡有沒有同名的（後端的 `nameIsShared`），不只是畫面上的。
- 建議橫幅的數字只算還沒回答的，`之後再說` 的不算。
- 區塊改名、收合不出通知；改專案名稱的通知沒有 `復原`（再改一次就好）。復原只能撤回最近的那一次修改；之後又改過時說 `沒辦法復原：之後又改過了`。
- `在 Finder 顯示` 打開主資料夾；知道主資料夾已經不在時不能按。
- 專案設定裡，你從別的專案移出來、自己算一個專案的資料夾，原因寫 `你把它從別的專案移出來`；你指定到這個專案、但不是從另一個專案整個加進來的，寫 `你把它放進這個專案`。
- 一個專案的資料夾加到別的專案後，它的網址照 §5.10 說找不到這個專案，不自動轉到收下它的專案。
- 通知（含 `復原`）在專案設定、可能屬於同一個專案的資料夾開著時也按得到；按它不會關掉側欄。

- 副標 `{n} 個專案。一個專案可以包含好幾個資料夾；點一個專案看它的對話。`
- 三種看法（無障礙名稱 `檢視方式`）：`預設`、`清單`、`資料夾`。網址 `?view=list` 或 `?view=tree`，預設不寫。`?review=1` 打開「可能屬於同一個專案的資料夾」（§5.8）。

#### 5.1 每一列

三種看法共用一套欄位：`專案` | `工具` | `對話` | `最近活動` | ⋯。`清單` 在 `最近活動` 前多兩欄 `分開加總`（滑過標題時寫的是 §1.5 的說明文字）和 `Token`。每列約 40 px，跟著頁面捲動虛擬化。

- **圖示**：git repo、一般資料夾、零散資料夾各一個圖示；資料夾全都不在時是灰色的圖示，滑過時寫 `資料夾已不在磁碟上，對話仍完整保存在 PathKeep`，名稱也變淡。
- **名稱和位置**：位置用來分辨同名的專案。
  - 平常寫主資料夾的上一層（`~/code`）。
  - 畫面上有另一個同名專案時寫主資料夾的完整路徑（`~/code/api`、`~/work/acme/api`）。
  - 資料夾不只一個時加 `{n} 個資料夾`；都不在時加 `資料夾已不在`。
  - 零散資料夾不寫路徑。
- 視窗夠寬（約 1500 px 以上）時，右邊多寫最近一段對話的標題（滑過時寫 `最近的對話：{標題}`），名稱和數字之間不會空一大段。
- **最近活動**用相對時間：`今天`、`昨天`、`{n} 天前`、`{n} 個月前`、`{n} 年前`。
- 點一列或按 Enter 打開那個專案（§5.10）。

#### 5.2 預設看法：釘選

上面一張 `釘選` 卡，是你自己的區塊。

- 標題列：`釘選` 和裡面的專案數；`＋ 區塊`（在最上層的最上面新增一個 `新區塊`，直接進入改名）；⋯（無障礙名稱 `釘選的選項`）：`全部收合`、`全部展開`。
- **區塊**可以巢狀、收合、拖曳排序，層數和數量都不限，每層縮排一格。區塊列：收合箭頭、名稱、裡面（含子區塊）的專案數、工具欄空著、對話總數（淡色）、最近活動、滑過時出現 ⋯。
  - 點一下、Enter 或空白鍵收合或展開；F2 改名；右鍵開選單。
  - 改名就地進行（無障礙名稱 `區塊名稱`）：Enter 或離開欄位時存，Esc 取消，空的名稱不存。
- **區塊選單**：`在裡面新增區塊`（加在最後並打開上層）、`重新命名`、`移到… ▸`、`上移`、`下移`、分隔線、`刪除區塊…`。區塊不能移進自己或自己的子區塊（選單裡不能選，拖過去也放不下）。
- **刪除區塊**：空的區塊直接刪，通知 `已刪除「{名稱}」`，可 `復原`。有東西的先問：`刪除「{名稱}」區塊？` / `裡面的 {n} 個專案會回到「其他專案」，子區塊也一起拿掉。專案和對話都不會刪除。` / `取消` / `刪除區塊`。
- **一開始是空的**。空的區塊寫 `空的區塊。把專案拖進來，或用專案的 ⋯ →「移到區塊」`；整張卡空著寫 `把常用的專案拖到這裡，或在專案的 ⋯ 選「釘選」`。

**拖曳**（只有預設看法可以拖）：

- 滑過時出現握把，按住移動超過一點距離才開始。拖著的時候跟著一個標籤，放不下時寫 `· 不能放在這裡`，拖到「其他專案」上寫 `· 取消釘選`，放得下時是一個勾。放下的位置有一條線。
- 拖到區塊上：上緣一小段是放在它前面，下緣一小段是放在它後面（打開的區塊是放成第一個子項），中間是放進去（加在最後，區塊標亮）。拖到專案上：上半或下半。拖到空區塊的佔位是放進去；拖到釘選卡的空白處是加在最上層的最後；拖到「其他專案」卡是取消釘選（只有專案可以）。
- 靠近捲動區上下邊緣時自動捲動，按住越久越快。停在收合的區塊上一下子（約 650 ms）會打開它。Esc 取消。拖曳結束的那一下點擊不算點擊。從輸入框或按鈕上不會開始拖。
- 放下後通知 `已把「{名稱}」移到「釘選」`（或 `「{區塊}」`、`「其他專案」`），可 `復原`。
- 不能拖曳的人用專案選單的 `移到區塊…` 做到同樣的事。

**規則**：區塊是你的資料，存在存檔裡，重建索引不會動到它。

- 新出現的專案先放在「其他專案」。
- 刪掉區塊，裡面的專案回到「其他專案」，不刪任何東西。
- 資料夾不在了的專案留在原位，圖示變灰。
- 一個專案的資料夾加進別的專案時，它從清單消失；之後把資料夾移出來，它回到原來的位置。

#### 5.3 預設看法：其他專案

下面一張 `其他專案` 卡，列出沒有釘選的專案，標題旁是數量。整張卡是「取消釘選」的放置區。

- 搜尋 `找名稱、資料夾或遠端`（無障礙名稱 `在其他專案裡找`，有清除鈕）：比對名稱、每個資料夾的路徑和遠端網址。
- 工具下拉：`所有工具` 或選了的工具名稱（用 `、` 接）；標籤 `用過這些工具的專案`；可多選，符合任何一個就列出。
- 狀態（無障礙名稱 `專案狀態`）：`全部`、`30 天內有活動`、`資料夾已不在`。
- 排序（無障礙名稱 `排序：{目前}`）：`最近活動`、`對話數`、`名稱`（照中文排序）。
- 有建議時頂端一行 `有 {n} 個可能屬於同一個專案的資料夾` 和 `檢視`（打開 §5.8）。數的是還沒處理的建議。
- 沒搜尋、沒篩選時先顯示 15 個。底下：`顯示全部 {n} 個` / `只看前 15 個`；搜尋或篩選時 `符合的有 {n} 個`。右邊 `新出現的專案會先放在這裡；拖到「釘選」就會留在上面。`
- 沒有符合的：`沒有符合條件的專案。` / `試試清除搜尋或篩選。`

#### 5.4 清單看法

- 一張卡 `全部專案` 和數量，有搜尋（無障礙名稱 `搜尋專案`）。
- 可排序的欄：`專案`、`對話`、`分開加總`、`Token`、`最近活動`。點一下換方向；換到新的欄時從大到小，`專案` 從 A 到 Z。預設 `最近活動` 從新到舊，相同時新的在前。
- `Token` 沒有資料時 `—`；只有部分對話有紀錄時加 `*`，滑過時寫 `{k} / {n} 段有用量紀錄`。
- 沒有符合的：`沒有符合「{q}」的專案`。
- 不能拖曳；⋯ 和右鍵選單同 §5.6。

#### 5.5 資料夾看法

- 一張卡 `依資料夾` 和數量；有打開的資料夾時多一個 `全部收合`；有搜尋。
- 專案照主資料夾的上一層分組。沒有專案、只有一個子資料夾的路徑合併成一行（`work/acme`）。家目錄攤平：它底下的資料夾直接列在最上面（`~/code`），直接在家目錄裡的專案是最上層的列。零散資料夾自己一組。
- 資料夾列：收合箭頭、路徑（等寬字）、專案數、對話總數、最近活動，照最近活動排。
- 預設全部收合，不記住。搜尋時打開每個有符合的資料夾，搜尋中不能收合。
- 沒有符合的：`沒有符合「{q}」的專案`。

#### 5.6 專案選單

每列滑過時的 ⋯、右鍵、和一個專案頁標頭的 ⋯ 是同一份選單：

| 順序 | 項目                | 做什麼                                                                                                                           |
| ---- | ------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 1    | `打開對話`          | 打開這個專案（標頭的選單沒有這一項）                                                                                             |
| 2    | `洞察`              | 到專案洞察（§5.11）                                                                                                              |
| —    | 分隔線              |                                                                                                                                  |
| 3    | `改名…`             | 改名對話框（§5.7）                                                                                                               |
| 4    | `釘選` / `取消釘選` | 釘選加在最上層的最後，通知 `已釘選「{名稱}」`；取消時通知 `已取消釘選「{名稱}」，它回到「其他專案」`。都可 `復原`                |
| 5    | `移到區塊… ▸`       | `釘選（最上層）`、每個區塊（縮排，目前所在的不能選）、分隔線、`其他專案（取消釘選）`。通知 `已把「{名稱}」移到{位置}`，可 `復原` |
| 6    | `專案設定…`         | §5.7                                                                                                                             |
| —    | 分隔線              |                                                                                                                                  |
| 7    | `在 Finder 顯示`    | 打開主資料夾。資料夾不在時不能按。Windows `在檔案總管顯示`，Linux `在檔案管理員顯示`                                             |

#### 5.7 改名與專案設定

**改名**對話框：標題 `改名`，說明是主資料夾的路徑；欄位 `名稱`；`只改 PathKeep 裡顯示的名字，資料夾名稱不會變。留空就用回「{原本的名稱}」。`；`儲存`（沒改過時不能按）；通知 `名稱已更新`。改過的名稱在每個地方都用新的：專案頁、清單的列、閱讀器、⌘K、洞察、篩選。

**專案設定**從側邊打開（約 580 px），標題 `專案設定`，說明是圖示 · 名稱 · 主資料夾路徑。

1. `名稱`：同一個欄位，存了不關掉側欄。
2. `資料夾 {n} 個`（有不在的時加 `，{m} 個已不在磁碟上`）和 `加入資料夾…`（零散資料夾沒有）。說明 `一個專案可以包含好幾個資料夾，這些資料夾裡的對話都算在這個專案。`
   - 每個資料夾一列：角色圖示；路徑（在主資料夾裡的寫成 `./sub`）；角色標籤；不在時 `已刪除`；一行原因；`{n} 段` 或 `沒有對話`；滑過時 `移出`（主資料夾沒有）。

     | 角色標籤     | 原因那一行                                                                  |
     | ------------ | --------------------------------------------------------------------------- |
     | `主資料夾`   | `git 根目錄`，或 `不是 git repo，只看這個資料夾`                            |
     | `worktree`   | `這個 repo 的 worktree；分支 {分支}`                                        |
     | `子資料夾`   | `在 git 根目錄裡面，所以自動算進來`                                         |
     | `暫存`       | `家目錄：在這裡跑的對話不屬於任何專案`，或 `系統暫存資料夾，用完就會被清掉` |
     | `你加進來的` | `原本單獨算一個專案（{名稱}）`                                              |

   - 移出你加進來的資料夾：它回到 PathKeep 自己會把它放的地方，通知 `已把 {路徑} 移出，它又是獨立的專案了`，可 `復原`。
   - 移出 PathKeep 自己歸進來的資料夾（worktree、子資料夾）：它變成一個獨立的專案，這個選擇記成你做的分組，之後重新歸類也不會把它併回去。通知 `已把 {路徑} 移出，它現在是獨立的專案`，可 `復原`。
3. `可能屬於同一個專案的資料夾`：要加進這個專案的建議卡（同 §5.8）。

底下一行：`這裡只改 PathKeep 裡的名稱和分組，不動 Claude Code、Codex 等工具自己的資料夾和檔案。`

**加入資料夾**對話框：

- `把資料夾加到「{名稱}」` / `選一個目前單獨算一個專案的資料夾。它的對話會算進「{名稱}」；之後能在專案設定裡移出。`
- 搜尋 `搜尋資料夾或專案名稱`，沒有結果 `沒有符合的資料夾`。
- 可選的是其他有對話的專案，不含零散資料夾、已經加進來的、和本身已經收了別人資料夾的專案。不能從磁碟上挑一個沒有對話的資料夾。
- 每列：圖示、名稱、上層路徑、`{n} 段`。選了通知 `已把 {路徑} 加到「{名稱}」`，說明 `{n} 段對話跟著過來`，可 `復原`，回到專案設定。

#### 5.8 可能屬於同一個專案的資料夾

從側邊打開，標題 `可能屬於同一個專案的資料夾`。

- 說明 `一個專案可以包含好幾個資料夾。下面這些資料夾現在各自算一個專案，但看起來屬於同一個專案。加進去只改 PathKeep 的分組，不動 Claude Code 或 Codex 的資料夾，之後隨時能在專案設定裡移出。`
- 還沒處理的在前，你說之後再看的在後並標 `你說之後再看`。
- 每張卡：
  - 一個標籤寫這個建議根據什麼（§5.9 的表）；
  - `把 {路徑} 加到「{專案}」？ {n} 段對話`（資料夾不在時加 `，資料夾已不在`），下面一行寫出細節；
  - 按鈕 `加進去` / `不是` / `之後再說`（已經說過之後再看的沒有這顆）。`加進去` 通知 `已把 {路徑} 加到「{專案}」`，說明 `{n} 段對話現在算在「{專案}」`，可 `復原`。
- `不是` 會被記住，同一個建議不會再出現。
- 都處理完時：`都處理完了`。
- 底下收起的 `已處理 {n}`：每列 `已加入` 或 `不是` · 路徑 → 專案名稱 · `復原`。

#### 5.9 專案怎麼歸類

PathKeep 只在確定時自動歸類；只是「可能」的，做成建議讓你確認。備份時讀專案資料夾的 `.git` 是用戶 2026-11-13 同意的。

**自動**（備份時讀到的 `.git` 能證明的）：

- 在一個已知 repo 的根目錄裡面的資料夾，屬於那個 repo。資料夾自己已經不在也一樣：路徑就說明了它在哪裡。工具建在 repo 裡面的 worktree（例如 `{repo}/.claude/worktrees/…`）也是這樣。
- worktree 屬於它的主 repo（從 `.git` 認出）。
- 不在任何 git repo 裡的資料夾，自己算一個專案。
- 零散資料夾的位置（預設 `/tmp`、`/private/var/folders`、家目錄本身）裡的對話，全部放進「零散資料夾」。位置在設定裡改（§7）。

**建議**（要你確認）：

每個建議都寫出它根據什麼：

| 情況                                                                               | 標籤（根據）                   | 細節那一行                                           |
| ---------------------------------------------------------------------------------- | ------------------------------ | ---------------------------------------------------- |
| 不同的資料夾，遠端網址相同                                                         | `同一個遠端網址`               | `兩個資料夾的遠端網址都是 {遠端}`                    |
| 同樣名稱的資料夾換了位置，舊的已經不在                                             | `同名，舊資料夾已經不在`       | 寫出舊路徑和新路徑                                   |
| 工具建在 repo 以外的 worktree（例如在工具自己的資料夾底下），讀不到它屬於哪個 repo | `工具的 worktree，讀不到 repo` | `{工具} 建的 worktree，分支 {分支}；讀不到它的 .git` |

規則：

- 專案名稱預設是主資料夾的名稱，可以改（§5.7）。
- 你做的分組（加入、移出、確認或拒絕的建議）PathKeep 重新歸類時不會改掉。
- 你做的分組包括移出 PathKeep 自己歸進來的資料夾（§5.7）。
- 在 Agent 對話的備份頁關掉「備份時也讀專案資料夾的 .git」時，專案只照路徑歸類：每個資料夾自己一個專案，加上零散資料夾。
- 讀 `.git` 讀什麼、不讀什麼見 [agent-history-product-design.md](../architecture/agent-history-product-design.md) §2。

已儲存的專案名、釘選、分組與建議答覆會隨存檔搬移。紀錄頁的專案選單也包括只有封存對話的專案；對話沒有工作目錄時，專案維持未知。桌面命令及欄位見 [Projects contract](../architecture/desktop-command-surface.md#agent-projects)。

#### 5.10 一個專案 `#/agent/projects/:id`

- **主要的事**：看這個專案的對話。
- **標頭**：‹（無障礙名稱 `回到專案`）、圖示、名稱和位置（一行、淡色）、工具圖示、視窗夠寬時 `{n} 段 · {最近活動}`；按鈕 `洞察`、`專案設定`、⋯（無障礙名稱 `這個專案的選項`，§5.6 的選單，沒有 `打開對話`）。
- **內容**就是紀錄頁（§3），只列這個專案的對話：包括它每一個資料夾裡的對話，含你加進來的。搜尋框 `搜尋這個專案的對話…`；篩選沒有 `專案` 區塊，分組沒有 `按專案`；列上不寫專案名稱；`全部清除` 不清掉這個專案。
- **必須有的狀態**：找不到（id 不存在，或它的資料夾都加到別的專案了）：`找不到這個專案` / `它的資料夾可能已經加到別的專案裡了。` / `回到專案`。後端說它的資料夾加到了哪個專案（`addedInto`），而那個專案還在時，`回到專案` 前面多一個按鈕 `打開「{名稱}」`，到那個專案的頁面（2026-11-20 加：舊的網址或書籤還能找到這些對話）。

#### 5.11 專案洞察 `#/agent/projects/:id/insights`

- 回上一頁的連結 `{名稱} 的對話`；標題是圖示加 `「{名稱}」的洞察`；有你加進來的資料夾時副標 `含你加進來的 {n} 個資料夾`（它們的對話算在裡面）。
- 範圍切換跟洞察一樣（§1.2），和洞察共用記住的範圍。標題旁同樣用灰字寫範圍。

數字：

| 數字             | 下面一行                                                                  | ⓘ 說明                                                                                         |
| ---------------- | ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `Agent 工作時間` | `分開加總 {x}`，平均同時開不到 1.05 個時不寫後半 ` · 平均同時開 {x.x} 個` | §1.5 的說明文字，加上 `{r} / {n} 段對話的時長是工具記錄的，其餘從時間戳推算。`                 |
| `Token`          | 沒有時 `—`；有對話沒紀錄時寫比例，否則 `其中 {x}% 是讀取快取`             | §1.7 的說明文字                                                                                |
| `對話`           | `另有 {n} 個 subagent`                                                    | 沒有                                                                                           |
| `改動行數`       | `+x −y`，下面 `動過 {n} 個檔案`                                           | `從 Agent 的編輯紀錄（Edit、apply_patch 的 diff）加總，各對話分開算，同一行被改兩次會算兩次。` |

卡片：

- **`活動`**：切換 `對話數` / `分開加總` / `Token`，依工具堆疊，分桶照 §1.3 跟著範圍。一段對話在它有活動的每一桶都算一次。副標 `{範圍}{每…}有活動的對話數，依工具分開`、`{範圍}{每…} Agent 工作的小時數（分開加總），依工具分開`、`{範圍}{每…}用掉的 token（單位：萬），沒有用量紀錄的對話不算在內`。範圍裡沒有對話時 `這個範圍裡沒有對話`。
- **`分支與 PR`**：副標 `{n} 個分支、{m} 個 PR 有對話`。每列：分支、工具標籤、最多 3 個 PR（`#n`）、`{n} 段`、最近活動（相對時間）。先列 8 個，`還有 {n} 個分支` / `收起`。不是 git repo 時 `這個資料夾不是 git repo，沒有分支資訊。`；零散資料夾 `暫存資料夾沒有分支資訊。`
- **`工具與模型`**：副標 `{n} 段對話`；每個工具一條占比，`{n} 段 · {x}%`；模型標籤（先 8 個，滑過時寫 `{n} 段對話`，數的是有任何一輪由它回答的對話），多的寫 `還有 {n} 個`。

必須有的狀態：載入中（骨架）；範圍裡沒有對話；找不到這個專案（同 §5.10）。

**已做進 app 的部分（2026-11-20）**：還沒有這一頁自己的畫面。專案選單的 `洞察`（§5.6 第 2 項）和專案頁標頭的 `洞察` 打開洞察（§2），只看這個專案（`#/agent/insights?project=<專案 id>`）：數字、圖表和一年都只算它的對話，標題下一行寫 `只看這個專案：{名稱}`，✕ 回到全部專案。這一頁的 `活動`、`分支與 PR`、`工具與模型` 卡，`{名稱} 的對話` 的返回連結，和 `含你加進來的 {n} 個資料夾` 都還沒有。

#### 5.12 專案頁必須有的狀態

- 載入中：骨架列，每張卡各自。
- 讀取失敗：說明讀不到，提供重試。
- 還沒有任何專案（還沒有對話）：說明專案會在備份後出現，連到備份頁。
- 第一次備份還沒跑完：列出目前存下的，頂端一行說明還在備份。

### 6. 備份 `#/agent/backup`

> 狀態：已經做進 app（2026-11-19），包括備註與格式提醒；自動備份那一列、背景任務頁、排程與選單列的觸發方式在 2026-11-20 做進去。落地的細節見 [data-spaces-tradeoff.md](../design/data-spaces-tradeoff.md) §6 第二段。一個工具的資料夾不在這台電腦上、存檔裡又有它的對話時，那一列寫 `不在這台電腦上`，開關不能按；在這台電腦上、還沒備份過的寫 `不備份`，打開開關會先看一次它的資料夾。

這一頁的共同部分見 [data-spaces.md](data-spaces.md) §4。Agent 對話自己的部分：

- 副標 `Agent 對話 · {n} 段對話。只讀來源，不改也不刪。`
- **會自動刪舊對話的提醒**：預設會自動刪舊對話的工具（Claude Code）有一張可以收起的提醒（按鈕 `知道了`，無障礙名稱 `知道了，收起`）。PathKeep 不讀工具的設定檔，只寫工具的預設值：
  - `Claude Code 預設會刪掉 30 天前的對話`
  - `PathKeep 已經存下的不受影響，現在有 {n} 段對話只剩 PathKeep 有。Claude Code 自己的設定可以改這個天數；PathKeep 不會去讀或改它的設定。`
  - 連結 `Claude Code 設定說明`，到工具自己的說明文件。
  - 收起之後就不再出現。
  - 這個工具在來源列上多一個標籤 `會自動刪舊對話`。
- **來源**：每個工具一列，列首是它的開關（關掉後不再備份這個工具，已存的留著，狀態寫 `不備份`），數量寫 `{n} 段`。卡片右上有 `加入其他資料夾…`（`例如用 CLAUDE_CONFIG_DIR 把 Claude Code 的資料放在別處，或從另一台電腦拷過來的資料夾。`）。展開一列：
  - 讀的資料夾（例如 `~/.codex/sessions 和 ~/.codex/archived_sessions`）；Claude 桌面應用程式的資料夾先寫它是什麼：`Claude 桌面應用程式（本機的 Cowork 工作階段）`，啟用流程的預覽也一樣；
  - 保存了哪些部分，每項一個勾：`對話內容`、`subagent`（有的話）、`工具輸出與附件`、`已從工具刪除的仍保留`；
  - `另有 {n} 個 subagent · 來源 {大小} · 只剩 PathKeep 有 {n} 段`。
- 來源卡最下面一列 `備份時也讀專案資料夾的 .git`，有開關（預設開）：`只看 repo 的根目錄、worktree 屬於哪個 repo、目前分支、遠端網址，用來把同一個專案的資料夾併在一起。資料夾刪掉之後就查不到了，所以要在備份當下記下來。不讀程式碼，也不改任何檔案。` 關掉時專案只照路徑歸類。
- 在 **最近的備份** 和來源列都看得到備註。空檔案、壞掉的一行、只存得下原檔的舊格式，都照樣保存。工具正在改寫的檔案會留到下次再讀。這些情況仍可顯示「備份成功」；同一個檔案的同一件事，下次還會列出，但不再算一筆新備註。
- 選的資料夾不見了、換了一個資料夾、沒有讀取權限，或有檔案因讀取錯誤沒存下來，這次是「部分完成」，會列在「需要你處理」。存檔寫入失敗也會提醒；已經存好的部分保留。
- 第一次碰到工具用了更新的格式，顯示「已按原樣保存，更新 PathKeep 後才能閱讀」。同一工具的同一版本只提醒一次，即使多個檔案都用這個版本。收起後，下次備份仍看得到備註。收起格式提醒只影響這個工具的這個版本；同一次備份若有檔案沒存下來，仍留在「需要你處理」。
- 畫面上：
  - 只有備註的備份就是 `完成`，旁邊寫 `{n} 則備註`，有新的再加 `{n} 則新的`；標頭的「上次備份」也這樣寫，按下去看那次備份。沒有全部存下的才寫 `完成，但沒有全部存下`。
  - 那次備份的詳情分三段：`沒存下來的`（沒有就寫 `讀到的都存下了。`）、`PathKeep 還讀不懂的格式`（有提醒時，帶 `收起`）、`備註`。備註先說 `這些檔案都照原樣存下了。備註說的是 PathKeep 讀它們時還看不懂的地方，並沒有因此少存什麼。`，每則用白話寫是哪一種情況（例如 `空檔案：裡面還沒有對話。`、`有一部分讀不了，例如壞掉或被截斷的一行；其餘的都讀了。`、`用的是格式版本 {版本}，PathKeep 還讀不懂；更新之後就能讀。`），加上工具、檔案和代碼；第一次出現的標 `新`。不認得的代碼也有一句，不會空白。
  - 來源列寫 `{n} 則備註`；展開後 `上次備份留下的備註`，同一種情況合併成 `{次數} × {說明}`。格式還讀不懂、或正在寫入要下次再讀的資料夾，都不算 `需要你看一下`。
  - 格式提醒寫 `PathKeep 還讀不懂 {工具} 的格式 {版本}。它的檔案照原樣存下了，更新 PathKeep 之後就能讀。`，出現在備份頁頂端、那次備份的詳情、背景任務頁的「需要你看一下」（只有 `收起`），也算進背景任務指示器的數字。
  - 備份完成的通知只說新的備註，舊的不每次重說；有格式提醒時也寫在通知裡。啟用流程的 `存好了` 寫 `全部都存下了，讀取時留下 {n} 則備註；備份頁上有列出來。`
  - 每則格式提醒有自己的 `收起`（無障礙名稱 `收起 {工具} 格式 {版本} 的提醒`），在備份頁頂端、那次備份的詳情、背景任務頁都一樣；只收那個工具的那個版本。同一次備份沒存下來的，另有 `再試一次` 和 `收起`。
  - 那次備份的詳情上方有它自己的 `再試一次`、`收起`（後端在詳情裡給這次備份的任務），重開 app、隔天也還在。
  - 沒存下來的另外幾種說法：工具輸出超過保留的大小（`它指向的一些工具輸出超過 PathKeep 保留的大小，所以沒有存下來。`）、它指向的檔案已經不在或讀不了。寫入結束紀錄時磁碟用不了的，任務的原因寫 `記錄結束時磁碟用不了，所以晚一點才記下。它存下的都還在。`
- 一個核准過的資料夾被刪掉又重建（同一個路徑、不同的資料夾），PathKeep 不會讀它，那一列寫原因，展開有 `再看一次…`（`重新掃描` 也會改成這個）：用那個路徑看一次資料夾（只數檔案），按 `核准並備份` 才換成新的資料夾並馬上備份。還是同一個資料夾時寫 `還是你核准的那個資料夾，不用再核准。`；那裡沒有讀得到的資料夾時照實說，不給核准。原本那次失敗的備份沒辦法照原樣重試；在它上面按 `再試一次` 也會帶到這裡。
- **自動備份**那一列（[data-spaces.md](data-spaces.md) §4）寫 Agent 對話自己的下次時間：排程從上一次做完的 Agent 對話備份起算（後端的 `agentNextScheduledBackupAt`），不一定跟瀏覽紀錄同時。暫停中、沒有選資料夾、或它的存檔打不開時後端不給這個時間，這一列只寫目前的排程。
- 排程和選單列圖示的 `立即備份` 也會備份 Agent 對話。那次備份詳情的 `怎麼開始的` 寫 `排程` 或 `選單列圖示裡的「立即備份」`；它們跟你按下的備份一樣出現在背景任務頁和指示器上。
- 備份的最後一步（讓存下的對話能被搜尋）可以暫停：在背景任務頁按 `暫停`，它停在那裡，列在「等待中」，附註 `你暫停了`，有 `繼續` 和 `取消`；備份頁的標頭仍然寫正在備份，進度條停住並寫 `你暫停了`。其他步驟只能取消。
- Agent 對話是唯一開著的類型、某個工具是唯一的來源時，它的開關不能關，來源卡寫 `{工具} 是 Agent 對話唯一的來源，而現在只開著這一種資料，所以沒辦法關掉它。先打開另一個工具或瀏覽紀錄。`
- 開著卻沒有可以備份的（`sourceReviewRequired`），`立即備份` 不出現，標頭下照情況說：
  - 這台電腦上沒有核准的資料夾（例如搬入的存檔不帶這台電腦的核准）：`重新選擇要備份的資料夾` 和原因，按鈕 `選擇資料夾…` 打開啟用流程；來源的開關等選好之後才能用。
  - 有核准的資料夾，但每個工具都關了（瀏覽紀錄開著時可以這樣）：`所有工具都關著`，在下面的來源打開一個，或到管理資料類型把 Agent 對話暫停。

必須有的狀態在 [data-spaces.md](data-spaces.md) §4 之外，還有：一個工具沒裝（那一列不出現，或寫出沒找到資料夾）；工具的資料夾讀不到（讀不到不算對話不見了）；一個工具的格式版本 PathKeep 還不認得（原始檔照存，那一列說明還沒整理進對話）。

### 6.1 存放對話的檔案壞了：提醒、修復、安全副本

> 狀態：已經做進 app（2026-11-19）。修復在後端怎麼做，見第二部分「從安全副本修復對話」。

**提醒**：存放已存對話的檔案打不開時，瀏覽紀錄照常可用。Agent 對話的備份頁，以及「設定 › 管理資料類型」的 Agent 對話卡片，都改成一則提醒 `已存的 Agent 對話現在打不開`：哪個檔案壞了（`存放已存對話的檔案損壞了，或者讀不了。` 或 `存放對話清單、搜尋和洞察的檔案損壞了，或者讀不了。`）、什麼時候發現的（例如 `在讀取其中的資料時發現的。`）、`瀏覽紀錄不受影響。`，按鈕 `再試一次` 和 `修復對話…`。壞的是和存檔其他部分共用的檔案，或對話是較新版本的 PathKeep 存的，修復幫不上忙，就只有 `再試一次`。檔案開得起來、讀到某一頁才發現壞了的，在那一刻換成這則提醒。只有幾段對話的清單壞了時（後端把那幾段擱著，對話庫照常可用，`readerRebuildRequired`），不是這則提醒，而是同兩處多一則平和的 `有些已存的對話現在讀不了`：`要先重建它們的清單，它們才能再打開。什麼都沒有遺失：已存的對話本身完好，其他對話照常打開。`，附 `修復對話…`（修復對話框的 `出了什麼問題` 寫 `有些已存的對話要先重建清單才能讀。什麼都沒有遺失：……`）；修好後後端送出資料類型變更，提醒自己消失。

**暫時讀不了不是壞了**：系統暫時拒絕讀取（例如權限被改掉，後端的 `access-denied`），提醒寫 `PathKeep 現在沒有讀取它們檔案的權限。檔案沒有壞：等能讀取了（例如修好權限之後），按「再試一次」。`；檔案正被佔用（`archive-busy`）寫 `它們的檔案現在正被佔用。檔案沒有壞：過一會兒再試一次。`。兩種都只有 `再試一次`，沒有修復。另有兩種也不說壞了，但修復幫得上：對話檔案屬於另一個存檔（`conversation-evidence-foreign`）寫 `存放已存對話的檔案屬於另一個存檔，例如同步工具或備份軟體把別的檔案放回了這裡。PathKeep 不會把另一個存檔的對話當成這個存檔的來讀。`，修復可以從安全副本取回，或用新的對話檔案重新開始（那個檔案留成副本）；清單和已存的對話對不上（`conversation-history-diverged`）寫 `對話清單和已存的對話對不上，例如其中一個檔案是從較舊的備份放回來的。用已存的對話重建清單就能解決。`，修復重建清單。

**拒絕時說是哪個檔案**：修復的檢查和執行、建立安全副本、搬移、加密和還原被拒絕，原因又是某個檔案時，拒絕的話下面另起一行寫那是什麼檔案（`存放已存對話的檔案`、`存放對話清單、搜尋和洞察的檔案`、`PathKeep 開著時不見了的對話檔案`、`存檔的檔案`）和它的路徑，附「在資料夾中顯示」；檔案已經不在時打開它所在的資料夾。寫不進檔案（`archive-file-write-failed`）有自己的話：`PathKeep 沒能寫入它正在產生的一個檔案。請確認磁碟還有空間、PathKeep 可以寫入那個資料夾，然後再試一次。` 對話備份頁的提醒不寫檔案：後端在那裡只說是哪一類檔案，不給路徑。 **被拒絕的搬家和加密**：對話讀不了時，搬到另一台電腦（匯出、打開檔案）和開關加密都會被拒絕，什麼都不變動。對話框說原因，例如 `已存的 Agent 對話現在讀不了，沒辦法打包進檔案。請先修復，再匯出一次。什麼都沒有變動。`，附同一個 `修復對話…`：按下去關掉原本的對話框，在同一個畫面上打開修復。只是暫時讀不了時（`conversation-access-unavailable`），對話框改說 `PathKeep 現在沒有讀取已存 Agent 對話的權限，所以沒辦法打包進檔案。檔案沒有壞，也什麼都沒有變動。`，附 `再試一次`：還是讀不了就說 `還是讀不了。檢查這些檔案的權限，或者有沒有別的程式佔用它們，然後按「再試一次」。`，讀得到了就說 `已存的對話又能讀取了，現在可以重新開始這項操作。`，對話框留著，再按一次原本的按鈕就好。

**修復對話框** `修復 Agent 對話`，網址加 `?repair=agent`，疊在目前的畫面上。開頭 `瀏覽紀錄不受影響。在你按下修復之前，什麼都不會變動。`

1. 一打開就檢查：`正在檢查能救回哪些對話…`，有進度和 `停止`，下面寫 `檢查只會讀取。檢查時照樣可以查看和備份瀏覽紀錄。` 上方 `出了什麼問題` 重述提醒裡的兩句。
2. 檢查完，後端決定用哪一種修復。對話框寫它會做什麼、數量，和換下的檔案留在哪：
   - 已存的對話完好、壞的是清單：`用已存的對話重建清單`、`重建後可以讀到 {n} 段對話。`。星號、改過的標題、垃圾桶和備份紀錄都留著；選好的資料夾不變，也沒有來源可選。清單和對話對不上時，說明改成 `已存的對話本身完好，只是它們的清單、搜尋和洞察跟對話對不上。……`。只有幾段對話讀不了時，說明改成 `已存的對話本身完好，讀不了的是其中一些對話的清單。PathKeep 會從已存的對話重新建好這些清單，其他對話維持原樣。……`，數量只算那幾段：`現在讀不了的 {n} 段對話，重建後能再打開。`。
   - 已存的對話壞了：`重新開始，救回還能核對的部分`、`會救回 {n} 段對話。`，接著分三件事說，每一件後端算不出來就說算不出來，不寫 0：
     - 回來的有多完整：都帶著最新的訊息就寫 `它們都會完整回來，包括最新的訊息。`；有的只剩較早的版本，就寫 `其中 {n} 段會完整回來，包括最新的訊息。` 和 `{n} 段回來時不帶最新的訊息：它們只有較早存下的版本還能核對無誤。那些最新的訊息只留在壞檔案的那份副本裡。`；看不出來時寫 `其中有多少段能帶著最新的訊息回來，沒辦法確定：壞掉的檔案看不出最新的訊息是什麼。`
     - 回不來的：全部回來寫 `每段對話都會回來。`；有救不回的寫 `有 {n} 段對話救不回來，只會留在壞檔案的那份副本裡。`；算不出來寫 `救不回來的有幾段，沒辦法算出來：壞掉的檔案列不出對話。`。
     - 沒帶回來的細節（任何一種修復都會說）：`有 {n} 項細節（例如星號、標題，或對話來自哪個檔案）核對不過，沒有帶回來。`、`已存檔案裡有 {n} 個列出或描述對話的部分完全讀不了。只存在那裡的內容（例如星號和標題）不會回來。`

     救不回的不是 0（或算不出來）時加一則警告：工具已經刪掉的對話，只有核對無誤的才會回來。另寫 `下次備份會把工具資料夾裡還在的每段對話重新存一次。` 重建和用副本修復不比對壞掉的檔案，這三件事不出現。對話檔案屬於另一個存檔時，重新開始不用裡面的任何內容，標題改成 `用新的對話檔案重新開始`、說明 `存放已存對話的檔案屬於另一個存檔，所以 PathKeep 不會用裡面的對話，而是建立新的對話檔案。`，不比對、不出現上面三件事，也不說「壞掉」：來源清單第一項寫 `重新開始`（`不用另一個存檔的檔案裡的任何內容`），提示句改成 `重新開始不會帶回另一個存檔的檔案裡的對話。下面的安全副本可能還有這個存檔的對話：……`。選的副本自己的對話檔案屬於另一個存檔時，檢查說 `這份副本裡的對話檔案屬於另一個存檔，不能用來修復。請選另一份。`。

   - 這時多一組 `從哪裡取回對話`：`壞掉的檔案`（預設）和每一份安全副本，新的在前，寫是哪種副本、建立時間、大小。重新開始會留下東西（有回不來的對話、有回來但缺最新訊息的，或算不出來），又有能選的副本時，清單上方多一句 `有些對話或它們最新的訊息，可能沒辦法從壞掉的檔案救回。下面的安全副本可能還有：先選一份檢查，再決定要不要重新開始。` 每份副本能不能選由後端判斷（看副本裡有哪些檔案，不打開資料庫）；能選的，檢查時才確認。不能選的照樣列出，並說為什麼：沒有已存的對話（`這份副本裡沒有已存的 Agent 對話，沒辦法用來救回。`，例如還原換下的那份只有瀏覽紀錄）、缺修復需要的對話檔案（`這份副本缺少修復需要的對話檔案。`）、還沒檢查過（`這份副本還沒檢查過，不能用來修復。`，和還原清單上的「尚未檢查」是同一回事）。建立時對話就讀不了的副本可以選，旁邊說 `建立這份副本時對話讀不了。檢查它就知道裡面的對話還能不能核對無誤。`；檢查發現沒有能核對的，說 `這份副本裡沒有能核對無誤的已存對話，不能用來修復。請選另一份。`。對話檔案在 PathKeep 開著時不見了，PathKeep 會把它單獨留成一份副本（`對話檔案不見時留下的`，`PathKeep 開著某個對話檔案時，這個檔案不見了，於是單獨留了下來。裡面只有已存的對話。`），它也在這裡，可以選。選一份副本按 `檢查這份副本`（選擇本身不會開始檢查）。副本是在另一個密碼下建立的，檢查會說 `這份副本是用另一個密碼建立的。輸入那個密碼才能檢查。`，並出現 `這份副本的密碼` 欄；密碼錯寫 `這不是這份副本的密碼。`。副本檢查過：`從安全副本取回對話`、`這份副本裡有 {n} 段對話。`。存檔的密碼和加密方式不變，不會換成副本的密碼。
   - 不是重建時加一則：`要先在 Agent 對話的備份頁重新選擇要備份的資料夾，才會再備份對話。`
   - 每一種都寫 `現在的檔案會留成一份安全副本，不會刪掉：` 和它的路徑、`它會列在「從安全副本還原」裡，也可以在「釋放空間」刪除。`、`這次檢查的結果保留 15 分鐘，超過就要重新檢查。`
3. 執行按鈕寫它要做的事：`重建清單`、`用這份副本修復`、`重新開始`（後兩個是紅色）。修復進行時對話框關不掉，有進度和 `停止`。
4. 完成：`已存的對話又能打開了`、`現在可以讀到 {n} 段對話。`（只有幾段讀不了時改成 `原本讀不了的 {n} 段對話又能打開了。`；重新開始時，有回來但缺最新訊息的再加 `其中 {n} 段回來時不帶最新的訊息，那些訊息留在下面這份副本裡。`；看不出來的加 `沒辦法確定它們是不是都帶著最新的訊息回來了。缺的部分留在下面這份副本裡。`）、換下的檔案留在哪（可以在資料夾中顯示）。需要重選資料夾時再說一次，附 `打開 Agent 對話的備份頁`。

`取消`、Esc、或離開這個網址，都會讓後端放掉這次檢查（`cancel_maintenance`），不用等十五分鐘。暫時讀不了時打開修復，檢查會說 `PathKeep 現在沒有讀取對話檔案的權限。檔案沒有壞，所以不需要修復：等能讀取了，在提醒裡按「再試一次」。`。檢查過期或之後存檔變了，修復會說 `檢查的結果已經過期，或之後有東西變了。請重新檢查再修復。`；讀不了必須保留的檔案時，說是哪個檔案，什麼都沒變動。修復失敗之後一律重新檢查。

**建立安全副本**：「設定 › 儲存空間」的「搬移與還原」分組有一列 `建立安全副本`（`把存檔現在的樣子複製一份，之後可以從它還原`），按 `建立…`。對話框先檢查（只讀），說副本放在哪個資料夾、裡面有什麼、大約佔多少空間，按 `建立副本` 才複製；完成通知 `安全副本已建立。`，可以在資料夾中顯示。對話讀不了時也能建立，事先說 `已存的 Agent 對話現在讀不了。副本會把它們的檔案原封不動地帶走，能用來還原瀏覽紀錄；能不能幫忙修復對話，要在修復時選它檢查才知道。` 這種副本在「從安全副本還原」和「釋放空間」的清單上標 `對話讀不了`；在「從安全副本還原」選了它，會說 `建立這份副本時，已存的 Agent 對話讀不了。這在這裡沒有影響：還原只會帶回瀏覽紀錄。` 自己建立的副本標 `你建立的副本`，修復換下的標 `修復對話之前`。對話檔案不見時留下的副本只有對話、沒有瀏覽紀錄，所以不出現在「從安全副本還原」；在「釋放空間」寫 `只有已存的 Agent 對話，供修復使用`，勾選它會警告 `對話檔案不見時留下的副本，可能存著某些對話唯一的已存版本。刪除之後，修復就沒辦法從它救回這些對話。`

**從安全副本還原只帶回瀏覽紀錄**（用戶 2026-11-15）：對話框開頭 `瀏覽紀錄會回到副本保存時的狀態。已存的 Agent 對話不受影響。存檔的密碼和加密方式維持現在的樣子。`，提醒 `之後新增的瀏覽紀錄不在副本裡。目前的瀏覽紀錄會保留為一份安全副本，之後還能還原回來……`，完成通知 `瀏覽紀錄已還原。`。結束程式時正在做的工作寫 `正在還原瀏覽紀錄或修復對話`（還原和修復在後端是同一種前景工作）。

### 7. 設定 › Agent 對話 `#/settings/agent`

**已做進 app 的部分（2026-11-20）**：整頁，五組都在。跟這一節寫的不一樣的地方：

- 側欄「資料類型」下的這一項只在 Agent 對話開著或暫停時出現。關閉時打開這個網址，頁面說它關著、可以在「管理資料類型」打開。
- 開頭那句話後面是一個連結 `打開備份頁`，不是句中的連結。
- `加入位置` 打開一個小框：資料夾欄位，app 裡多一個 `選擇…`（系統的資料夾選擇器），沒有選擇器的地方（開發用的瀏覽器）就打完整路徑。不是完整路徑寫 `請用完整路徑，從磁碟的最上層開始。`，已經在清單裡寫 `這個位置已經在清單裡了。`。路徑最後的 `/` 會拿掉。家目錄本身寫 `~（家目錄本身）`，家目錄底下的寫 `~/…`；滑過標籤看完整路徑。
- 「可能屬於同一個專案的資料夾」沒有待確認的時寫 `沒有等你確認的資料夾。`，不出現 `去看看`；數不出來時（例如已存的對話打不開）說數不出來。
- 牌價表的 `{版本}` 是後端給的版本代碼（例如 `standard-text-2026-11-20`），跟洞察費用卡和資訊面板一樣。已存的對話打不開時，兩個費用開關不能切，說明改成讀不到。`顯示費用` 關著時估算那一列後面加 `先打開「顯示費用」才能切換這一項。`。
- `這三個開關都關著時，Agent 對話不會送到任何地方。` 只在三個都關著時寫在 AI 存取下面。三個開關存的是這台電腦的選擇（後端 `set_agent_viewer_preferences`），後面的功能都接上了：Ask 引用對話（§3.5）、紀錄的語意搜尋（§3.4）、MCP。
- `建立語意搜尋索引` 的說明多寫一點：用遠端 embedding 服務時，送過去的是對話內容和你搜尋的字句（搜尋也要先轉成向量）。
- 語意索引開關下面多一塊，說索引現在怎樣（後端 `get_agent_semantic_index`，跟著 `pathkeep://agent-semantic-index-changed` 更新），狀態那一行是 polite 的 live region（無障礙名稱 `語意搜尋索引`），一直在跳的段落數放在它外面：
  - `已就緒` / `{n} 個段落，{多久前}用{模型}建立。`（內建模型寫「App 內建靜態模型」，embedding 服務寫「服務名稱 · 模型」）。
  - `沒跟上` / `{多久前}建立之後對話有變動。更新之後，語意搜尋才找得到變動的部分。`，按鈕 `現在更新`。備份完後端會自己更新，這是更新失敗或被取消之後才會停在這裡。
  - `正在建立` / 第一次寫 `建好之後才能用語意搜尋；這段期間字面搜尋照常可用。`，已有索引時寫 `這次建好之前，語意搜尋繼續用{多久前}建立的索引。`；下面一條沒有百分比的進度條（建好之前不知道總共幾段）和 `已讀 {n} 個段落`，按鈕 `暫停`、`取消`（跟背景任務頁同一組字）。
  - `已暫停` / `暫停期間什麼都不建立。`，按鈕 `繼續`、`取消`。`正在停止` / `這次已建立的部分會丟掉。`，沒有按鈕。
  - `還沒建立` / `建立之前，對話紀錄不能按意思搜尋。`，按鈕 `現在建立`；上次被取消時多一行 `上次建立被你取消了。`。`上次建立失敗` / `再試一次。如果還是失敗，檢查「設定 › AI」裡的 embedding 模型。`，按鈕 `現在建立`。失敗帶著後端的代碼時（`job.error`），第二行改寫那個原因和怎麼辦（例如 `Embedding 服務沒有回應。確認它在執行、連得上，再試一次。它是在「設定 › AI」裡選的。`），該去「設定 › AI」時多一顆 `打開 AI 設定`；舊索引還在用時，那一行寫 `上次建立失敗：{原因}`。
  - 「設定 › AI」的 AI 或語意搜尋關著：`AI 設定裡關著` / `「設定 › AI」裡的 AI 或語意搜尋關著，所以不建立索引，也不用它。`，按鈕 `打開 AI 設定`。後端在這裡只說「不能用」，不說是哪一個開關。
  - 後端說了原因的（狀態的 `reason`，或讀狀態本身被拒絕，例如 Agent 對話關著）：寫那個原因的標題和怎麼辦，跟紀錄的語意搜尋、Ask 同一組字（`aiRefusals`）；沒選 embedding 模型是 `語意搜尋需要 embedding 模型` / `在「設定 › AI」裡選一個。`。要去「設定 › AI」時附 `打開 AI 設定`，要去「管理資料類型」時附 `打開「管理資料類型」`；要去的就是這一頁時不附按鈕。
  - 最後一行說關掉會怎樣。開著時：`關掉這項會停止建立，搜尋也不再用這個索引。已經建好的部分留在本機，不會被用到。`；關著時：`關著：不建立索引，搜尋也不用它。`。開關打開或關上時，狀態那塊用高度動畫展開或收起。
  - 索引沒在用（開關關著，或「設定 › AI」裡關著）而本機還留著時（後端 `keptBytes` 大於 0），這一塊多一行 `之前建立的索引還留在本機，沒有被用到：{大小}。` 和按鈕 `釋放…`（無障礙名稱 `釋放留在本機的語意搜尋索引`），一樣用高度動畫出現和收起。按下去先讀一次大小（`preview_free_agent_semantic_index`，讀的時候對話框裡是骨架），對話框 `釋放語意搜尋索引？` 寫 `這會刪除留在本機的索引：{大小}。你的對話、全文搜尋和瀏覽紀錄的索引都會保留。之後再打開對話的語意搜尋，索引會從頭建立。`，按鈕 `取消` 和 `釋放 {大小}`（`free_agent_semantic_index`，按下後寫 `正在釋放…`，對話框等後端回答才關）。成功時通知 `已釋放 {大小}`，那一行收起。讀大小之後索引變了（後端說 `preview-expired`）時什麼都不刪：對話框重讀大小，多寫一行 `讀取大小之後索引有了變化。這是它現在的大小。`，再問一次。還有一次建立正在停止時寫 `還有一次建立正在停止。等它停下再試。`；開關又打開了時寫 `對話的語意搜尋又打開了，索引正在使用，不能釋放。`；其他失敗寫 `沒能釋放索引：{原因}`。讀到的大小是 0 時寫 `沒有可以釋放的：索引已經不在了。`，沒有釋放按鈕。
  - 按鈕被後端拒絕時跳出 `沒能改變索引的建立` 和原因。
- `繼續對話` 的說明改成「PathKeep 還沒確認過接續指令的工具版本，按下去只複製工作階段 ID」，因為 Claude Code 和 Codex CLI 有確認過的版本了（[接續指令表](../architecture/research/agent-history/resume-commands.md)）。
- 改暫存位置後，後端重新歸類專案並送出專案和對話的變更事件，專案頁和紀錄跟著更新；改的當中標籤不能再按。

這一頁只放跟備份無關的偏好。要備份哪些工具、加入其他資料夾、備份時要不要讀 `.git`，都在 Agent 對話的備份頁（§6），因為它們決定的是備份讀什麼；這一頁開頭有一句話連過去（用戶 2026-11-13 同意，分法見 [data-spaces.md](data-spaces.md) §8）。

### 8. 封存與垃圾桶

兩個動作都只是在對話上做記號，都在閱讀器的 ⋯ 和清單的右鍵選單裡。v0.6 一次處理一段對話；一次處理多段（整個專案、某一天之前的全部）之後再做。

#### 8.1 封存

封存只是把對話收起來，不刪任何東西。

- 封存的對話不出現在清單和 ⌘K 的最近對話裡。
- 搜尋照樣找得到，結果上標 `已封存`；洞察照樣算它；閱讀器的標頭寫 `已封存`。
- 要看全部封存的：篩選 › 只看 › `已封存`。
- 封存後通知 `已封存，不再出現在清單裡`，說明 `搜尋還找得到；要看全部，在「篩選」裡選「已封存」。`，可 `復原`。取消封存通知 `已取消封存`。

#### 8.2 垃圾桶

`移到垃圾桶` 把一段對話和它的 subagent 從清單、搜尋、⌘K，以及洞察和專案的每一個數字裡拿掉。

- 跟著進垃圾桶的只有它派出去的 subagent。從它 fork 出去的對話是另一段對話，留在原處。
- 不跳確認的對話框，因為可以復原：通知 `已移到垃圾桶`，可 `復原`。
- 打開著的閱讀器關掉；全頁打開時回到 `#/agent/chats`。
- 要看垃圾桶：篩選 › 只看 › `垃圾桶`（網址 `flags=trash`）。清單最上面一行：`垃圾桶裡的對話還存在 PathKeep 的存檔裡，也照樣備份，只是不顯示。垃圾桶不會自己清空。`
- 垃圾桶裡的每一列，右鍵選單和閱讀器的 ⋯ 都有 `放回`。在閱讀器裡打開垃圾桶裡的對話時，最上面一行 `這段對話在垃圾桶裡。` 和 `放回`。
- `放回` 讓對話回到移進垃圾桶之前的樣子：星號、改過的標題、封存與否都照舊。通知 `已放回`。
- 備份頁的數字照存檔裡實際存了多少算，含垃圾桶裡的。

垃圾桶裡的對話還在存檔裡，也照樣備份，只是不顯示。v0.6 不能永久刪除單獨一段對話；要把 Agent 對話從存檔裡拿掉，只能刪除整個類型存下的資料（[data-spaces.md](data-spaces.md) §2），或刪除所有資料。永久刪除單獨一段對話之後再做，這一版為什麼先不做見 [agent-history-product-design.md](../architecture/agent-history-product-design.md) §4。

### 9. 還沒定的

- 每個工具、每個版本確認過的接續指令（Claude Code、Codex、Pi、DeepSeek Harness），做這個功能時照研究筆記定。

## 第二部分：核心庫現在做到的事

[agent-history-product-design.md](../architecture/agent-history-product-design.md) 的設計在第一次發布前會改掉下面好幾條，改的是哪幾句見那份文件的「Clauses this amends」。其中第一塊已經做進核心庫（2026-11-13）：

- 對話與來源分開：一段對話可以有好幾個來源檔，id 從工具自己的資料算出來；subagent 連回派出它的對話，fork 另外記；Codex 還原過的 thread 連同它繼承的內容讀成一條。
- 星號、封存、垃圾桶、自訂標題跟著原始資料存，重新解析、重建索引、檔案搬家都還在。
- 每次備份記下每個來源這次有沒有看到，以及對話工作資料夾的 git 資訊。
- 保存規則依來源種類分；原始位元組壓縮後存，前綴版本共用內容。
- 存檔可以不加密。
- 附件沒存到另外計數，不算對話不完整。

還沒做的：跟 PathKeep 的存檔合一、讀取模型（現在每筆紀錄仍多存兩份）、永久刪除。

狀態：獨立核心庫與 CLI；產品 UI 整合尚未開始。使用者要求先交付研究、可靠備份與可維護的底層，之後由 Claude 接手 UI／UX 和產品呈現。這一部分只講核心庫，不談介面；介面見第一部分。

核心在 `src-tauri/crates/agent-history`。它保存所選來源的歷史 revisions，提供按 harness／項目路徑篩選、建立／更新時間排序、事件分頁、全文搜尋及匯出。它不依賴模型、embedding、provider 帳號或雲端服務，也不使用 PathKeep 自己的 assistant conversation store。

### 使用者可依賴的資料契約

來源保持唯讀，不啟動 harness，不執行來源 loader 的修復／遷移，不讀登入狀態來補 cloud history。只從已知資料位置與明確選取的根目錄收集；聊天或工具文字不能授權讀取任意路徑。可用的本機附件以來源與 reference 關係保存；缺失、越界、遠端或無法解析的內容回報診斷。

Raw revisions 不跟著來源刪除而消失；重寫、縮短、同大小內容變更和再次出現舊內容都有自己的觀察結果。Ordinary native files 保留原始 bytes，包括壓縮、未知欄位、壞行與尾端碎片。SQLite 是一致 transaction 的 logical schema／rows evidence，export 明示格式，不能改名成 `.sqlite` 便宣稱可直接還原。每個來源檔各自驗證，不宣稱整個 harness 的所有檔案同時停在同一時間點。

核心庫回報 raw integrity、normalization coverage、search freshness 與診斷；未解析到的資料不等於空對話。已發布的歷史不因一次失敗的新 capture 被覆寫成空資料。Archive、衍生資料與搜尋索引沿用 repo 的加密儲存契約；只有使用者明確匯出的檔案是交付給其指定 writer／destination 的明文。

Parser 更新後可用 `reparse --source-id ID --execute` 從已保存的 native revision 重新建立投影；即使來源已消失，也只讀 archive 與先前保存的 attachment bindings，不重新掃描本機或補抓新檔案。Raw bytes 不變，發布成功才切換新投影；未保存的 reference 仍顯示缺口。這個操作不適用於把 SQLite logical evidence 當 transcript 解析。

### 查詢與匯出

`sources` 分頁列出保留的原始來源，包含附件、metadata 與無法解析的 transcript；不依賴 live source 或 parsed session。來源刪除後，仍可從這個清單找到 source／revision ID 並 raw-export。`plan` 的 256 筆預覽上限不限制已備份清單。

Session list 可以以 harness、**exact recorded project path** 篩選，按建立或更新時間排序；不同 harness 記錄相同 path 時可以一起查。它沒有 project alias、pin、路徑合併或 repo/worktree 語意判斷。Session／event 游標約束 publication，投影更換後舊游標需重新開始；raw revision list 則以 source 與 revision ID 向較舊資料分頁，新增 capture 不破壞已開始的歷史遍歷。

CLI 的 `search` 是區分 exact harness／project filter 的 lexical AND term search；不區分字母大小寫，CJK 以單字元 token 處理。沒有自然語言推理、語意相似、模糊／regex／phrase query。查詢回傳 top-k（上限 100）與 matching event 總數，**不提供搜尋結果逐頁翻完**；不要把保留的 `next_cursor: null` 當成分頁功能。索引落後時回錯，不以空結果掩蓋；`sync-search` 同步衍生資料，損壞索引另用明確的 `sync-search --rebuild` 重建。

桌面的紀錄搜尋依 §3.4 分批傳回全部符合的對話，備份期間讀上一次完成的索引。閱讀器依 §4.6 搜尋本段對話和 subagent；兩種讀取都可以取消。請求、訊息格式及 UTF-8 高亮範圍見 [desktop-command-surface.md](../architecture/desktop-command-surface.md#records-search-and-reader-find)。

匯出有 raw revision、normalized JSONL、Markdown。Normalized 格式仍含 native payload、ordinal、parent evidence；它保留事件順序，可能包含互斥分支、mirror records 與 metadata，不能當已去重、可直接 resume 的 native conversation。桌面閱讀器另可匯出單檔 HTML，並可把原始對話與子代理檔案一起存成 tar。Raw export 的「完整」僅指該 captured revision 的 bytes，不是整個帳號歷史或附件全齊。

### 這次沒有做的產品功能

沒有 UI／typed IPC／設定／onboarding／排程整合，沒有執行 native resume 或遷移，沒有可安裝 plugin runtime。Adapter trait 與分層已提供可維護的擴展位置，但新 adapter 仍須納入程式與驗證。

原始 usage、model 與 timing evidence 會保留；token／cost／response 去重 analytics 尚未交付。不能直接加總各 event 的 usage，因為 streaming blocks、mirror events、fork inherited history 與 compaction 都可能重複。同樣沒有完成 AI 摘要、語意搜尋或 project pinning；未來功能應建立在可重建投影上，而非改寫原始 archive。

### UI／UX 接手條件

後續產品整合需在背景 worker 使用同步 Rust API，保持主線程可響應；自行提供 PME 選取／預覽／執行、取消與進度，明確顯示來源／解析／附件差異。不得因有一個 complete raw revision 就把整個來源標成完全成功。User-visible copy、error／empty／loading／disabled 與 accessibility 都仍須交付三語。

Resume、項目移動與跨 harness 轉移需先按 [Claude](../architecture/research/agent-history/claude-code.md#resume-and-migration-research-no-execution)、[Codex](../architecture/research/agent-history/codex.md#resume-and-project-migration-research-only)、[Pi／DeepSeek](../architecture/research/agent-history/pi-deepseek.md) 的證據重新定義 per-version 能力；目前 `native_resume_ready` 一律 false。平台、效能、未知格式與限制必須從交接紀錄延續，不因換了一層 UI 就消失。

### 從安全副本修復對話

畫面見第一部分 §6.1。

瀏覽紀錄仍可開啟時，安全副本會備份瀏覽資料，也原樣保留資料夾中可複製的對話資料庫和日誌。清單會標出建立時對話讀不了的副本。還原這些副本只退回瀏覽紀錄。搬家和開關加密必須逐庫轉換，需先把對話修好。

個別對話的閱讀資料損壞或尚待重建時，對話庫仍可用，其他對話可以照常閱讀。後端修復預覽會在副本中重建待處理的對話，並回報重建後能開啟幾個。確認執行前，原本能讀的對話仍使用同一份閱讀資料；如果這段期間對話資料有變動，必須重新預覽。

修復另走預覽和確認。原始證據完整時，從保留的位元組重建讀取模型，保留原始修訂、星號、標題、垃圾桶與執行紀錄。證據已損壞時，可從已驗證的副本取回已存的對話（副本只有證據、沒有讀取模型也可以），並沿用本機現行金鑰。沒有可用副本時，可選擇建立新的對話庫，救回仍可驗證的修訂。只剩存檔持有且無法驗證的對話會留在被換下的副本裡。確認後被換下的資料會成為一份可列出、計量、單獨釋放的安全副本。從副本或救回的修訂建立新證據庫後，必須重新確認來源資料夾才會再次擷取。

修復預覽會先逐段核對原始修訂的分塊和整段摘要。即使執行紀錄的一頁已經損壞，仍會從通過核對的修訂重建可搜尋的對話，並保留能讀取的來源資訊與使用者標記。預覽分別顯示可找回的對話數，以及只能留在副本裡的對話數。如果兩份對話清單都無法讀取，後一個數量顯示為未知。準備預覽時仍可瀏覽和備份瀏覽紀錄。確認有效期為十五分鐘。

**作業系統拒絕讀取檔案時**（例如權限不足的 EACCES，或磁碟讀取錯誤 EIO），需要保留該檔案的安全副本、還原或修復會停止，指出檔名並說明資料未變更。PathKeep 不發佈缺少該檔案的瀏覽副本。若開啟的對話檔案已被移走，仍可從已開啟的檔案讀到的位元組也會保存在被換下的副本中。 副本包含已解除連結的檔案時，PathKeep 先完整寫入並列出副本，再關閉最後的檔案控制代碼。即使之後因為來源又變更而停止安裝，這份副本仍留在清單中。

PathKeep 發現對話庫只剩開啟中的檔案可讀時，會先把該世代的資料獨立封存為可列出、計量及釋放的副本。若儲存失敗，正常關閉會停止並保留控制代碼。重試成功後，之後的備份屬於新的開啟世代；舊世代的檔案只作為額外保留資料。標記為建立時讀不了的副本仍可提供通過驗證的證據，用來重建對話。

救援預覽分別計算完整找回、缺少最新訊息、以及只留在副本中的對話。即使其中一份逐字稿損壞，只要另一個來源保留了全部最新內容，該對話仍算完整找回。清單資訊不足時，數量為未知。原始證據的可讀標記優先，只有已找回的對話才會從可信的讀取模型補回讀不了的標記。無法使用的個別解析提示會計數並跳過。暫時缺少讀取權限時，可在恢復權限後重試。
