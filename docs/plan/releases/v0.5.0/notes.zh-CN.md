# PathKeep v0.5.0

PathKeep v0.5.0 改善浏览器备份，加入搜索排序与搜索构建器，并在建立新的语义索引时继续提供现有索引。AI 仍然可选。

## 升级之前

新版会自动升级存档与语义索引的元数据。**v0.4.0 无法打开升级后的数据，也无法导入新版导出的便携存档。** 如果要保留降回 v0.4.0 的能力，请在升级前完全退出 PathKeep，保存整个数据目录的副本，并保留存档密码。这是降级兼容性的限制，不是升级已知会失败。

升级后第一次备份会重新读取已选浏览器的历史。大型存档需要更久，Insights 也可能在后台重建。浏览器已经删除的历史，无法再从该浏览器恢复。

## 这次改变

- 语义索引更新分批统计剩余工作，并在批次之间响应停止。长读取不再连带阻塞其他读取与之后的写入，空闲的搜索索引器也不再反复写入。
- 备份以网址与浏览器自己的时间识别访问，浏览器重新使用行号时，不再因此悄悄漏掉新访问。升级会保留导航链接；Firefox Sync 副本分别保存，但只计算一次。
- 运行结果区分完整、部分完成与失败，并列出各个配置文件的结果。菜单栏与计划备份会保留最近一次备份的警告，直到之后的备份解决它。
- 备份返回后，链接预览继续在后台获取。
- History 可以排序搜索结果，也可以用界面组合文字与模式搜索。完整加上引号的运算符会当作文字，模式搜索的后续页面延续同一次搜索。
- 语义索引按完整的代发布；新索引完成前，搜索继续使用现有完整索引。History 说明这次搜索实际使用哪个索引。关闭语义搜索后，不再发送 embedding 请求。
- 导入、导出等受保护工作还在进行时，退出会先询问如何处理。前一次保存尚未完成时，新编辑的笔记与标签仍会保留。
- Insights 在新结果发布后重新读取，跨浏览器与搜索引擎的相同搜索只列一次。Ask 会说明模型没有写出回答就结束的情况。

## 已知限制

- 语义索引的增量更新仍会扫描整个存档，即使只新增了几条访问；大型存档的后台建索引仍可能持续较久。
- 14.4M 次访问时，部分 Insights 卡片第一次读取，以及没有精确结果的搜索，可能要一分钟以上。大型存档更改网站类别也很慢。
- 后来才找到的打开者会立即更新 Navigation，但已建好的 Insights 路径要等完整重建。
- 目前没有单独清除语义索引文件的界面，大型索引可能占用很多磁盘空间。
- 删除所有数据前请先停止备份；删除不会等待正在运行的备份。
- 备份打开的浏览器时，获取可读副本可能需要等待，也可能出现读取副本的备注／警告。

## 下载与安装

提供 Apple Silicon／Intel Mac、Windows x64 与 Linux x64 软件包。Windows 安装程序维持未签名的 preview，Linux 软件包也维持 preview。Safari 在 macOS 需要“完全磁盘访问权限”。Firefox 仍限历史记录；Atlas 与 Comet 仍限已验证的 macOS 历史配置文件。

这些 preview 软件包未签名，须手动安装，不提供 app 内自动更新。macOS 可能阻止下载的 app，更新后也可能需要重新授予完全磁盘访问权限。Windows 可能显示“未知发布者”或 SmartScreen 提示。

下载后请按照 `SHA256SUMS.txt` 与 `RELEASE-MANIFEST.json` 核对文件。这些 preview 软件包不附更新签名或 `latest.json`。JavaScript 锁文件审计结果为零。Rust 审计通过，保留八项有记录的例外。
