## 整體結構

```
SessionGate（src/app/index.tsx）
├─ booting        → BootScreen
├─ error          → BootErrorScreen（錯誤全文、重試、顯示 log）
├─ access         → AccessScreen（這一版不打開這個存檔：說明原因，只提供不刪資料的修復）
├─ app-locked     → LockScreen kind="app"（App Lock passcode）
├─ archive-locked → LockScreen kind="archive"（加密 archive 的密碼）
├─ recovery       → RecoveryScreen（archive 打不開，從已驗證快照還原）
├─ upgrade        → UpgradeScreen（一次性 archive 升級，含進度）
├─ onboarding     → Onboarding 路由（七步設定）
└─ ready          → AppFrame：導航列（切換鈕、目前空間的頁面、共用項目）+ 當前畫面 + ⌘K
```

- 狀態由 `src/app/session.tsx` 決定，順序是：先問後端 `get_archive_access`，存檔被拒絕（較新版本做的、設定檔不見或壞了、少了檔案、上一次的變更沒做完、0.5.0 的交接還沒選，或用復原模式啟動）時，App Lock 鎖著 → `app-locked`，否則 → `access`（[archive.md](../features/archive.md)「打不開存檔時」）；其餘照下面：App Lock 鎖著 → `app-locked`；舊版 app 留下沒做完的工作（crash journal）收不了尾 → `recovery`；archive 還是舊的 SQLCipher 格式 → `upgrade`（升級畫面自己問加密 archive 的密碼，所以排在解鎖之前）；加密 archive 沒有金鑰 → 先試鑰匙圈（只試一次），失敗就 `archive-locked`；明文 archive 打不開 → 先試著復原，復原不了 → `recovery`；`config.initialized` 為 false → `onboarding`；其餘 → `ready`。
- 只有 `ready` 會掛主路由；鎖定、升級、onboarding 都是全螢幕，主畫面完全不渲染。鎖定時清空整個查詢快取，archive 資料不留在記憶體。
- 路由是 hash router（`src/app/router.tsx`）。每個畫面是 lazy chunk，載入時顯示 skeleton；每個畫面有自己的 `RouteError`，一個畫面崩潰不會拖垮整個 app。

## 導航

- **空間**：每種資料類型一個空間，有自己的一組頁面、自己的網址前綴和自己的色相（[data-spaces-tradeoff.md](data-spaces-tradeoff.md)）。登記表在 `src/lib/spaces/registry.ts`：導航列的頁面、路由、⌘K 的「前往」與搜尋結果、切換選單的狀態行、快捷鍵的順序都從它來，外框別的地方不寫死任何一個空間；連結一律用 `src/lib/spaces/paths.ts` 組出來。現在登記了瀏覽紀錄和 Agent 對話。
- **目前的空間**（`src/app/shell/current-space.ts`）：在空間自己的頁面上由網址決定，所以從連結、搜尋結果或 ⌘K 跳過去，導航列跟著換；在共用的畫面（Ask、Settings）上沿用上一個。它記在本機（跟深淺色一樣），並寫在 `<html data-space>` 上讓色相的 token 跟著換。
- **左側導航列**（76 px，`src/app/shell/nav-rail.tsx`），由上到下：
  - 上一頁 / 下一頁兩個小箭頭（沒有可去的時變灰）。macOS 的紅綠燈在箭頭上面（導航列頂端 46 px 是可拖動區）；三個平台的導航列一樣，沒有品牌標誌（2026-10-13，`back-forward-window-frame-tradeoff.md` D）。
  - **切換鈕**（`space-switcher.tsx`）：目前空間的圖示和短名稱；開著兩種以上時下面有一排小圓點表示這是第幾個。點開是空間清單，每個空間一行（圖示、名稱、一句狀態、快捷鍵、目前的那個打勾）；瀏覽紀錄的狀態是「{n} 筆 · {m} 個瀏覽器」，選單打開時才讀，讀的是首頁本來就讀的資料。選單裡只有空間。「保存其他類型的資料」只在登記表裡有沒開的類型時出現，現在沒有。
  - **這個空間的頁面**：瀏覽紀錄是首頁、紀錄、洞察、備份（圖示加文字，當前項目是白色卡片底；洞察的 drill-in 也算洞察）；Agent 對話現在是洞察、紀錄、專案、備份，空間從洞察打開；全頁的閱讀器 `#/agent/chat/:id` 也算紀錄（登記表的 `elsewhere`），一個專案的頁面 `#/agent/projects/:id` 算專案（登記表的 `children`）。當前項目同時帶 `aria-current="page"`，這兩種頁面也是。清單頁在中文叫「紀錄」，英文仍是 History。
  - 一條分隔線，下面是**共用項目**，切換空間時不動：背景任務指示器、助理、⌘K、鎖定（⌘L）、深淺色切換、Settings。
- **背景任務指示器**（`task-indicator.tsx`、`use-background-tasks.ts`）：沒有工作時是一個安靜的圖示；有工作在跑且都知道總量時是填到平均進度的圓環，有不知道總量的就轉圈（「減少動態效果」時不轉）；兩項以上另外顯示數字；有事需要你看一下（後端算的：沒存完的對話備份、格式提醒、沒有人收起的失敗或沒做完的瀏覽紀錄與整個存檔的工作）時多一個小點。滑過或聚焦約 180 ms 後打開小視窗（指標或焦點在裡面時不關；鍵盤按 ↓ 或 → 進去，Esc 回來）：每個在跑的工作一列（名稱、百分比或「準備中」、進度條、一行說明）、還有幾項在排隊、「{n} 項需要你看一下」（到 `#/tasks`）、「全部立即備份」與「打開背景任務」。列的工作和數字都來自後端的摘要（`get_task_summary`，每種類型與整個存檔的工作都算），不輪詢：帳本事件（`pathkeep://background-tasks-changed`）、對話備份與語意索引的事件讓它重讀。這個視窗自己開始的瀏覽紀錄備份與匯入帶即時的進度，掛在帳本裡同一種工作的那一列上；Agent 對話的語意索引寫已讀幾段，沒有取消鈕。點指示器或「打開背景任務」到背景任務頁（`#/tasks`）。
- **切換空間**：選單、⌘K 的「切換到」（開著兩種以上才有）或 ⌘1 … ⌘9（Windows、Linux 是 Ctrl+1 … Ctrl+9），到那個空間的第一頁。導航列先動：屬於空間的項目照方向滑出、滑入（`space-slide.tsx`），170 ms 後才去要新空間的頁面，面板淡入（`space-panel.tsx`），重的頁面拖不慢動畫；「減少動態效果」時只有淡入淡出。切換選單每個空間一列：圖示、名稱、狀態行（瀏覽紀錄：造訪數與瀏覽器數；Agent 對話：對話數與「只在 PathKeep」的數），快捷鍵與目前空間的勾；有關閉的類型時最後一項是「保存其他類型的資料…」。暫停的類型照樣在選單和 ⌘K 裡。E2E：`spaces-shell.spec`（一個空間）、`shell-3-switch.spec`（兩個空間、滑動與減少動態效果、`#/` 回到上一次的空間）。
- **上一頁 / 下一頁**走 router 的歷史；篩選與選取用 `replace`，不進歷史，所以只在畫面與 drill-in 之間跳（`use-history-steps.ts`）。快捷鍵 ⌘[ / ⌘]（Windows、Linux 用 Alt+← / Alt+→）與滑鼠側鍵，在文字框裡不攔。
- **Windows、Linux 的視窗**沒有系統標題列（`desktop_integration/window.rs` 在視窗第一次顯示前關掉）。最小化 / 最大化（還原）/ 關閉畫在視窗右上角，跟 macOS 紅綠燈在左上角是同一個位置關係。它們在 app 的根畫一次（`src/app/window-chrome/window-controls.tsx`），所以每個畫面都有：新手引導、鎖定、啟動、升級、錯誤畫面都算。它們疊在對話框的遮罩之上，對話框開著時照樣能按。有面板的畫面（主畫面、新手引導）在面板上方留一條 32 px 的視窗底層給它們（`window-chrome/frame.ts`）；這條空白處可以拖動，雙擊最大化 / 還原。Windows 11 的貼齊版面（滑鼠停在最大化上出現）還沒做：要在 Windows 上建置並實測，見 BACKLOG `WORK-WINDOWS-SNAP-LAYOUTS`。
- **拖動區**（`drag-region.ts`、`title-bar.tsx`）：三個平台的視窗都沒有系統標題列，像一般視窗一樣從頂部拖動，靠的是 app 自己標的區域。視窗底層三個平台都能拖：主面板外圍的邊（Windows、Linux 包括按鈕旁那條）、導航列與新手引導側欄的空白，以及鎖定、啟動、錯誤畫面的背景。Windows、Linux 上按下不會馬上拖，指標按著移動超過 4 px 視窗才跟著走（`window-chrome/drag.ts`）：觸控板輕點一下不會讓視窗黏在指標上（Xfce 的視窗管理員以前會，`WORK-DRAG-ON-MOVE`）。代價是視窗比指標少走那幾個像素。macOS 上，面板頂端落在紅綠燈那條標題區裡，所以面板裡面也能拖：每個會捲動的畫面頂端 28 px（內容在下面捲過），以及頁首與工具列（History 的搜尋列、Settings 與 Ask 的側欄）的空白處。Windows、Linux 的面板從那條 32 px 下面開始，面板裡面就是內容。按鈕、輸入框、連結照常可點，卡片內文字照常可選。
- 語言在 Settings → General 改（新手引導裡也能改），寫進 config（`useChooseLanguage`），重啟後保留，排程與選單列圖示也用它。導航列上沒有語言鈕。
- 沒有 topbar、沒有麵包屑、沒有通知中心、沒有共享 profile scope。「目前的空間」不是 scope：它換的是整組頁面，不是在同一個頁面上篩選資料。
- 全域快捷鍵（`app-frame.tsx`）：⌘K / Ctrl+K 開關命令面板；⌘L / Ctrl+L 鎖定；⌘1 … ⌘9（Ctrl+1 … Ctrl+9）切換空間；⌘[ / ⌘]（Alt+← / Alt+→）上一頁 / 下一頁。沒設 passcode 時鎖定不會發生，改為提示「先設定 passcode」並打開 Settings → Security。

### 畫面之間的連結

- Home：統計卡分別連到 History、Insights、Settings → Storage、Backup；年度熱力圖點某天 → `/browsing/insights/day/YYYY-MM-DD`；On this day 的日期 → `/browsing/history?date=YYYY-MM-DD`；「常回來的主題」→ 搜尋或頁面的 drill-in（範圍 90 天），「全部」→ Insights；來源卡「管理」→ Backup；備份狀態膠囊 → Backup。
- Insights：每日活動點某天 → day；熱門網站 → site；查過的事、常搜尋 → search；常重開的頁面 → page（帶該列的設定檔，`scores=`）；「你回頭再看的事」→ search 或 page；習慣、各瀏覽器對比的網站 → site。drill-in 都帶目前的範圍與設定檔；day 本身涵蓋所有設定檔，帶著範圍只為了「← 洞察」回得去。
- Insights drill-in 往外：day 的熱門網站 → `/browsing/history?date=D&domain=…`，時段裡的頁面 → `/browsing/history?date=D&visit=<id>`，時段與搜尋卡裡的搜尋 → search；site 的每日長條 → day，頁面 → `/browsing/history?q=<標題>&domain=…`，「帶你來到這裡的搜尋」→ search，「在紀錄中打開」→ `/browsing/history?domain=…&date=<range>`；search 的每一次 → day，打開的網站 → site，「在紀錄中搜尋」→ `/browsing/history?q=…`；page 的最近日子 → day，網站 → site，搜尋 → search，「在紀錄中打開」→ `/browsing/history?q=<標題>&domain=…`；day 的「在紀錄中打開」→ `/browsing/history?date=D`，前一天 / 後一天，回來再看的頁面 → page。每個 drill-in 左上角「← 洞察」回到 Insights，保留打開它時的範圍與設定檔。
- Ask：回答引用的頁面 → `/browsing/history?q=<標題>&visit=<id>`；引用的 Agent 對話紀錄與回答裡的 `pathkeep://conversation/open?…` 連結 → `/agent/chats?chat=<id>&at=<序號>:<來源>`；未設定 AI → Settings → AI；後端以 AI 或助理關著拒絕回答時，失敗的回答附 `設定 › AI`。
- ⌘K：頁面結果 → `/browsing/history?q=…&visit=<id>`；「在「瀏覽紀錄」搜尋「…」」→ `/browsing/history?q=…`；Agent 對話 → `/agent/chats?chat=<id>`；專案 → `/agent/projects/<id>`；「在「Agent 對話」搜尋「…」」→ `/agent/chats?q=…`。
- 背景任務頁：每列的名稱 → 那一次的詳情（`/agent/backup?run=<runRef>`、`/browsing/backup?run=<id>`；佇列的工作沒有詳情，不是連結；Agent 對話的語意索引 → `/settings/agent`）；右上「排程與背景工作」→ Settings → 排程與背景工作。Settings → 排程與背景工作的「打開背景任務」、Settings → AI 語意索引旁的「背景任務」、洞察「上次沒有算完」那句提到的地方都到 `#/tasks`。
- 每個空間的備份頁上「自動備份」那一列 → Settings → 排程與背景工作。
- History：無資料時「前往 Backup」；semantic 未開時提示去 Settings → AI；連結預覽關閉時「去開啟」→ Settings → General；點標籤 → `/browsing/history?q=tag:…`。

### Insights 的「查過的事」

「搜尋」區的第一張兩欄摘要卡，只在服務中的語意索引有搜尋向量時出現。旁邊仍是常搜尋／常重開，接著是搜尋引擎與詞語卡；沒有搜尋向量時保留原排列。最多 31 天列前 6 組，較長範圍列各月前 3 組（新月在上、整月日期帶），副標交代範圍、按意思分組、整月邊界與跨瀏覽器口徑。靜態模型的共詞限制連到 Settings → AI。每組是自己的搜尋文字、數字及日期格，不加裝飾圖；日期格可朗讀日期與有無搜尋。超過三種文字時顯示其餘數量，避免用一個文字假裝命名整個大組。點列保留目前範圍／設定檔進 search drill-in。

卡內清單限高並保留溢出淡出提示；月份虛擬化。載入立即給列 skeleton，未完成月份標「更新中…」並輪詢。空範圍說清楚只計哪些搜尋；讀取失敗留在本卡，有重試。ⓘ 沿用卡片的資料說明與「問問助理」。

### Onboarding

`archive` 尚未初始化時出現，左邊是步驟清單，右邊是內容，上方有細進度條；視窗內可切換語言與深淺色。

1. **歡迎**：各瀏覽器與 Claude Code、Codex 自己會留多久（Chrome / Arc 約 90 天、Claude Code 預設 30 天…）對比 PathKeep 的永久保存，加上三個承諾（只在本機、不碰原始檔、可搜尋）。
2. **要保存什麼**：瀏覽紀錄與 Agent 對話各一張卡（為什麼要保存、這台電腦上找到的來源）；找得到來源的預設勾，找不到的說明之後首頁會問；至少選一種（[data-spaces.md](../features/data-spaces.md) §3.3）。
3. **來源**：選了兩種時左邊是類型（↑/↓ 切換）、右邊是那一種的來源，只選一種時一欄。瀏覽紀錄：勾選要備份的 profile（預設勾所有可讀的）；Safari 缺 Full Disk Access 時說明並提供授權與重新掃描。Agent 對話：每個工具的資料夾、對話檔與 subagent 檔的數量和大小，讀不到的寫原因，`.git` 的說明，勾著 Claude Code 時說它預設 30 天刪舊對話。按繼續時把瀏覽器的選擇存進 config（類型與工具在建立存檔前還存不下來）。
4. **存放位置**：archive 會建在 app 資料夾（不能改，提供「在 Finder 中顯示」）與體積估算；選了兩種時每種一列加合計，Agent 對話用後端的估算。
5. **加密**：加密（預設）或不加密；密碼與強度；是否存進系統鑰匙圈（鑰匙圈可用時預設開，排程備份需要它）。不加密時提醒 Agent 對話常有程式碼與金鑰。
6. **排程**：每小時（預設）/ 每 6 小時 / 每天 / 手動，並顯示將安裝的排程檔內容（可展開）；無法自動安裝時說明。可「略過」（= 手動）。一個排程備份所有類型。
7. **AI**：先不要（預設）/ 本機語意搜尋 / 連接 AI 服務（共用 Settings → AI 的表單）。可略過。
8. **完成**：列出所有選擇，連同「連網：會下載每個頁面的預覽圖，可在設定 → 瀏覽紀錄關閉」，按「開始第一次備份」後依序執行：建立 archive → 存密碼到鑰匙圈 → 安裝排程 → 第一次備份（即時進度；選了 Agent 對話時每種類型一行，各自結束，失敗的那一種寫原因並連到它的備份頁）→ 設定 AI。Agent 對話的第一次保存可以「在背景繼續」：不再等它，其餘階段做完就自己進入主畫面；開啟的回覆丟了而保存其實在跑時，接手那次保存。每階段顯示狀態，失敗時就地顯示錯誤並可重試；除了建立 archive 以外都能略過（略過的階段顯示橫線與刪除線，不打勾）。完成後進入主畫面。

前七步只存選擇：瀏覽器、選了哪些類型和 Agent 工具（在「要保存什麼」與「來源」按繼續時，`save_onboarding_choices`），可自由返回修改。沒有「離開設定」按鈕：archive 建立之前沒有可去的主畫面，關掉 app 下次從歡迎開始，選過的類型、工具和瀏覽器照舊勾著；建立 archive 前再存一次最後的選擇，後端照它設定兩種類型。

### ⌘K 命令面板（`src/app/shell/command-palette.tsx`）

- 對話框的標題「搜尋與指令」、說明「跳到頁面、對話或專案」，輸入框提示「搜尋對話、專案、頁面…」。
- **前往**：每個開著的空間的每一頁，寫成「{空間的短名稱} · {頁面}」（瀏覽紀錄 · 首頁、紀錄、洞察、備份），接著 Ask、背景任務、Settings。從登記表來。
- **動作**：立即備份、切換深淺色、鎖定 PathKeep（⌘L）、新對話。
- **切換到**：開著兩種以上類型時，目前以外的每個空間，帶快捷鍵。
- 頁面與動作依輸入文字過濾。每個空間多一組自己的結果（登記表的 `palette.Results`），一般是輸入兩個字以上才有；登記表標了 `fromEmpty` 的空間一打開就有（列出最近的）。有輸入字時每組最後一項是「在「{空間}」搜尋「…」」，打開那個空間的清單頁並帶著這串字。
- 瀏覽紀錄的那組叫 **頁面**（`src/features/history/palette-results.tsx`）：用全文搜尋（`groupByUrl`，一頁一行）取前 6 筆（favicon、標題、時間）。
- Agent 對話（`src/features/agent-palette/`）有兩組：**Agent 對話**最多 6 段（沒輸入字時是最近的、不含封存的；有輸入字時比對標題，封存的也找得到並標「已封存」；每列圖示、標題、專案、工具、時間，到 `#/agent/chats?chat=<id>`），**專案**最多 5 個（名稱與主資料夾，到那個專案的頁面）。每次輸入的字變了就問一次後端（`query_agent_palette`），用不到的上一次由後端停掉（`cancel_agent_read`）；新的答案到之前舊的列變淡留著。鎖著、關閉或存檔打不開時兩組都不出現。

### 選單列圖示

Settings → General 開啟後出現在 macOS 選單列（Windows / Linux 系統匣）。選單：備份狀態（不可點）、立即備份、搜尋歷史…、打開 PathKeep、結束 PathKeep。

- 「搜尋歷史…」叫出視窗並送 `pathkeep://open-command-palette`，視窗收到就打開 ⌘K。
- 任何 app 內備份結束都送 `pathkeep://backup-finished`；來源是選單列時，視窗顯示與自己發起的備份相同的 toast 並刷新資料（`src/app/backup-runner.tsx`）。
- 開著圖示時關閉視窗只會隱藏；登入啟動不會把視窗推到前面。完整行為見 [archive.md](../features/archive.md) §2「開機啟動與選單列圖示」與 [desktop-command-surface.md](../architecture/desktop-command-surface.md)。
- 「結束 PathKeep」在有工作在跑時先問，見下節。

### 結束時還有工作在跑

有人等著的工作在跑時結束 PathKeep（圖示關著時關視窗、⌘Q、選單列圖示的「結束 PathKeep」），視窗回到前面，跳出對話框（`src/app/shell/quit-prompt.tsx`，掛在 app 根部，鎖定畫面與 onboarding 上也會出現；只寫工作的種類，不帶存檔內容）：

- 標題「PathKeep 還有工作沒做完」，列出正在進行的工作（「正在匯出歷史紀錄」等），每項下面一行說現在結束會怎樣（匯出：不會留下檔案；匯入：已經匯入的會保留，再匯入同一個檔案就能做完；備份：下次備份會補上；其他存檔變更：停在中途但存檔不會損壞；刪除所有資料：下次打開時做完；為這個版本更新存檔：停在中途但存檔不會損壞，下次打開會接著做）。存檔更新在啟動時、開存檔的畫面上就可能在跑，這時也一樣會問。
- 按鈕：「不結束」「現在結束」「做完再結束」。Esc 等於「不結束」。打開時焦點放在對話框本身而不是按鈕上：誤按 Enter 不會替使用者回答，Tab 會走到按鈕。
- 選了「做完再結束」：標題改成「做完就結束 PathKeep」，旁邊轉圈，仍可「現在結束」或「不結束」；做完就結束。
- 沒回答時工作做完了：標題改成「工作都做完了」，說現在結束不會中斷任何工作，按鈕剩「不結束」「結束」。
- 背景佇列（建索引、洞察、連結預覽）重開後會自己續跑，不會讓結束停下來問。

## 共同規則

- 長流程（重新加密、匯入、還原、刪除資料、搬家、釋放空間、健康修復）都在對話框裡走 Preview → 確認 → 執行，結果就地顯示；完成後如需重新開機（刪除資料、還原、匯入 `.pathkeep` 檔）會呼叫 `session.restart()`，從頭跑一次開機流程。
- 寫入 archive 的動作完成後（備份、匯入、還原）呼叫 `refreshAfterArchiveChange()`：重拉 snapshot，並讓所有 `archive` 開頭的查詢失效，Home / History / Insights 一起更新。
- 同時只會有一個手動備份：`BackupRunnerProvider` 持有唯一的執行狀態，Home、Backup、⌘K、onboarding 共用。
- On this day 只回看往年同一天，不含今年今天；日期都用使用者目前時區的本地日曆日。
- Profile / 瀏覽器在 UI 上一律顯示瀏覽器名稱與 profile 名稱，不露出 `chrome:Default` 這類內部 id。

## App Lock 畫面與導航規則

> 2026-10-04 依 [app-lock-panel-tradeoff.md](app-lock-panel-tradeoff.md) 選項 B 改寫（用戶決定）：保留 Touch ID 與「忘記密碼？」，拿掉 config 路徑列、上次解鎖時間、鎖定原因，以及非 macOS 的生物辨識說明。

- 鎖定不是路由，而是 session 狀態 `app-locked`（`src/app/session.tsx`）：主 shell 完全不渲染，只渲染 `src/app/shell/lock-screen.tsx`。
- 啟動時若 App Lock 已啟用，PathKeep 先顯示 lock screen，通過驗證後才載入主 shell。
- 閒置逾時（idle timeout）觸發時同樣進入 `app-locked`。
- `⌘L` / `Ctrl+L` 與 Settings →「立即鎖定」手動鎖定；沒有 passcode 時不鎖，改帶到 Settings → Security 先設定。
- Lock screen 顯示 PathKeep branding、標題、一句說明、passcode input 與輸錯提示。
- 使用者在 Settings 開了 Touch ID（只有 macOS 會出現這個開關）時，lock screen 有「用 Touch ID 解鎖」按鈕；Touch ID 暫時不可用時按鈕停用並說明改用 passcode；取消系統提示不顯示錯誤。關掉 Touch ID 時不顯示按鈕，後端也拒絕生物辨識解鎖。
- 非 macOS 不顯示任何生物辨識控制項或說明。
- 「忘記密碼？」展開顯示 recovery hint（沒存就說沒存）、一句「App Lock 只擋住這個視窗，archive 與其密碼不受影響」、怎麼關掉 App Lock（關掉 PathKeep，把 `config.json` 的 `appLock.enabled` 改成 `false` 再打開）、config 路徑與「在 Finder 中顯示」。沒有重設按鈕。
- lock screen 自己向後端讀 lock status（鎖定時允許），因為鎖定會清空前端查詢快取。
- 鎖定狀態下不僅 UI 隱藏，後端 query 與 MCP history query 也必須被阻擋 — 避免透過 dev tools / MCP 繞過。
- Settings → Security 的 App Lock 分組：開關、passcode 更改 / 移除（passcode 列顯示目前的 hint）、passcode 對話框裡可選的 hint（更改時帶入已存的 hint）、Touch ID 開關（macOS；不可用時不能打開但能關掉）、自動鎖定時間、立即鎖定。
- Settings → Security 的 archive 分組：更改密碼與關閉加密都先要求輸入目前的密碼，錯了就說「這不是目前的密碼，存檔沒有變動」並停在第一步。
- manual update check / install（release availability、notes、install progress、restart CTA）在 Settings → About。
- App Lock 與 archive encryption 是**獨立的兩層保護**：App Lock 保護 UI session，encryption 保護資料庫檔案。兩者可獨立啟用。
- 設計規格 → `docs/features/archive.md` §8
