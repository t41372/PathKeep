# Settings and the background-work job list: what the prototype keeps

Audit of 2026-11-13. Starts from today's app (`src/features/settings/`, the E2E specs that cover it) and looks each feature up in the prototype (`docs/design/prototype-2026-11-agent-history/src/pages/settings/`, `pages/tasks*`, `pages/schedule/`) and in the spec (`docs/features/data-spaces.md` §5, §7, §8; `docs/design/data-spaces-tradeoff.md` §5; `docs/features/agent-history.md` §7; `parity/*.json`).

Paths: real files are relative to the repo root (`src/...`); prototype files are relative to `docs/design/prototype-2026-11-agent-history/src/` and written `proto:pages/...`. Real line numbers are from `HEAD`.

Verdicts: `same` · `moved` · `changed` · `missing`. A `missing` or `changed` row is covered when a spec line keeps the behaviour in words, or a `parity/*.json` entry records it (`kept-not-drawn` = the app keeps that failure or in-between state as it is; the prototype just does not draw it). Otherwise it is **UNDECIDED**.

## Needs a decision

Only the **UNDECIDED** rows, most user-visible first.

1. **Where the non-list parts of today's Background work go** (BG-12, BG-19, BG-21, BG-22, BG-24, BG-25, BG-26): data-spaces §5.2 draws `#/tasks` as four groups and §8 keeps Settings to settings, so nothing places the Insights 重建 button, 洞察資料 with 清除…, 額外的網頁資訊, 網頁摘要's 立即抓取 or 連結預覽's coverage and 立即清理 (nor the whole job history behind 顯示全部), and a builder working from the spec would lose the only way to clear or rebuild Insights data.
2. **Scheduler problems have no home after the move** (SCH-62, SCH-63): the backup page's one-line row is specified only for on and off, and Home's scheduler alerts still say 打開備份, so a user would no longer learn on Backup that the scheduler needs 修復 or permission, has an old job, is a Linux manual setup or has no next time.
3. **Semantic index "背景工作" link** (AI-14): next to a running or waiting build it still opens `#/settings/background`, which no longer lists jobs, so the user does not find the build they went to look at.
4. **Busy states** (AI-35, BG-16): the prototype never disables AI controls, job buttons or the queue controls while a save or action is pending, so a builder would allow double retries, double saves and double index starts.
5. **Turning semantic search on also turns 每次備份後…建立索引 on; cancelling the model download turns it off** (AI-9c, AI-9b): the prototype keeps the auto-update switch as it was and leaves semantic search on after a cancelled download, so a builder would ship different switch behaviour.
6. **Editing an AI service re-checks it** (AI-26b): the prototype checks only after adding, so after an edit with a wrong address the user would not see "沒能讀取…的模型" until they press 測試連線.
7. **Texts that point at 「備份」 for things that moved** (ST-17 = SCH-64, SCH-65, SCH-66): the delete-all schedule-failure text, onboarding's 跳過，之後在「備份」裡設定 and the overdue / incomplete schedule texts send the user to the Backup page, which now has only a one-line row with 更改排程.
8. **History's "去開啟" for link previews** (LINK-2): it still goes to `#/settings/general`, where only a pointer row remains, so the user needs one more click to reach the switch.
9. **macOS old schedule job hides the current one's state** (SCH-42): the prototype's old-job case always has a healthy current job, so nobody sees that removing the old job can leave automatic backup broken or off.
10. **Open-at-login and menu-bar rows when the OS does not support them** (GEN-12): the prototype always draws both switches, so a builder would show a switch that cannot work.
11. **Restore lists only copies that open** (ST-14): the prototype lists every safety copy, so a builder could let the user pick a broken one.
12. **Touch ID row on a Mac without Touch ID** (SEC-21): the prototype shows the row on every Mac, where the app hides it when the backend reports no biometrics.
13. **Text-less skeletons** (AI-18, BG-14, AB-1): the semantic-index area, each job list and the version row show a skeleton while loading in the app and nothing in the prototype, and no parity entry lists them because they have no string.
14. **Re-encryption preview warnings from the backend** (SEC-15): the prototype draws none, which loses nothing today because the backend sends only a warning the dialog filters, but drops the path for warnings added later.
15. **Settings column 680 → 720 px** (NAV-6): Settings is shared by every space and tradeoff §4.5 widens only the Agent space.
16. **Linux schedule dialog label** (SCH-29): today the button briefly reads 安裝 before 儲存間隔; the prototype shows the right label at once, so nothing is lost, but the change is unrecorded.
17. **Browsing settings while 瀏覽紀錄 is 關閉** (BR-0): not a loss of today's behaviour but a new state the spec does not cover; with browsing off the 瀏覽紀錄 settings entry disappears, so the user cannot export the browsing history still in the archive or clear the preview-image cache, and nothing says whether previews and summaries keep fetching.

## Prototype gaps the spec already keeps

Not undecided (a spec line or parity entry keeps them), but the prototype does not show them, so a builder working from the prototype alone would miss them:

- Browsing settings, kept by data-spaces §8 「每一列的內容、文字和行為都跟現在一樣」: export's save dialog and survival across leaving the page (EXP-2, EXP-8); the export-done toast's path and 在 Finder 中顯示 (EXP-6, asserted by `export.spec.ts`); the time-left and no-total wording (EXP-3); turning 連結預覽 on sets 何時抓取 to 每次備份後 when it was off (BR-1); disabled-while-saving and loading states of the browsing switches and selects (BR-2, BR-4, BR-6, BR-11).
- Schedule card, kept by tradeoff §5 「卡片內容跟現在的「自動備份」卡一樣」: the loading skeleton (SCH-9), the next-run roll-forward and minute tick (SCH-11), re-reading the status after backups, imports and failed changes (SCH-18), and that a refused install still saves the interval (SCH-31). Against the decided spec: the browsing row hard-codes 每小時 (SCH-60) and the Agent row has no off state (SCH-61).
- Frame and shell, kept by `screens-and-nav.md` §導航 (not overturned): ⌘L / Ctrl+L, so "先設定 App 密碼" and the jump to Settings › 安全 cannot be reached (SEC-25); the settings sub-nav as a window drag region (NAV-4).

Gaps in today's app itself, found on the way (not prototype losses): a failed schedule status read leaves the card a skeleton for good, and a failed 再檢查一次 shows nothing (SCH-10, SCH-44).
