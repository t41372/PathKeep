# 多種資料類型的外框：空間、每個空間的顏色、頁面寬度 — Trade-off

> **狀態：Accepted — 用戶 2026-11-13 選定 C（每種資料類型一個空間），並同意推翻「單一品牌色」。外框已落地（2026-11-14），只有瀏覽紀錄一個空間；見 §6。**
> **範圍：** 導航列、路由、視窗底色與強調色、頁面寬度、全域快捷鍵
> **牽涉的已接受文檔：** [ux-principles.md](ux-principles.md) §1（導航列、單一品牌色、密度）、[screens-and-nav.md](screens-and-nav.md) §導航、§URL 契約、§畫面清單、[ui-review-guardrails.md](ui-review-guardrails.md) §3 全寬卡片白名單、[design-tokens.md](design-tokens.md) §Brand and status colors。逐條見 §5。

## 1. 為什麼要改

- v0.6 起 PathKeep 不只保存瀏覽紀錄。第二種是 Agent 對話（Claude Code、Codex 等工具留在本機的聊天紀錄）。用戶 2026-11-13 說之後還會加更多「放著就會被自動刪掉」的資料，每一種都能各自開關。所以外框要能放 N 種，不是 2 種。
- 現在的外框把瀏覽紀錄寫死了：導航列固定是 Home / History / Insights / Ask / Backup，路由是 `#/history`、`#/insights`，Backup 只有瀏覽器來源。
- 每種資料都有自己的清單、洞察和備份來源。兩種就是八、九個頁面，放不進 76 px 寬、最小 760 px 高的導航列；六種更不可能。

## 2. 選項

**A. 所有頁面都放進同一條導航列。** 兩種勉強放得下，三種以上要捲動。同名的頁面（兩個「洞察」、兩個「紀錄」）排在一起分不出來。

**B. 導航列每種類型一項，頁面是面板頂端的分頁。** 只開一種時，頁面直接放進導航列。用戶試過後放棄（2026-11-13）：同一個頁面有時在左邊、有時在頂端，開第二種類型時整個導航會換一個樣子，太複雜。

**C. 每種類型一個空間，像切換 profile（用戶提出並選定）。** 導航列頂端是切換鈕，下面永遠是目前這個空間自己的頁面；視窗底色和強調色跟著空間換。

## 3. 怎麼比

- **類型變多時**：A 的導航列變長，B 多一項，C 只是切換選單多一行。只有 C 的導航列不會變。
- **頁面的位置**：C 的頁面永遠在導航列同一個地方。B 會在導航列和面板頂端之間搬家。
- **看不到的狀態**：C 多了「現在在哪個空間」這件事。處理方式：切換鈕永遠寫著空間的名稱和圖示，不只靠顏色；毛玻璃視窗下底色很淡，那時切換鈕就是主要線索。
- **跨空間的事**：C 需要固定的位置放不屬於任何一個空間的東西（背景任務、助理、設定、⌘K）。它們放在導航列下半部，切換空間時不動。
- **名稱**：不叫「profile」。瀏覽紀錄的來源裡已經有 Chrome 的「個人／工作」profile，會撞名。介面上只寫類型的名稱（「瀏覽紀錄」「Agent 對話」）。

## 4. 決定

### 4.1 導航列

由上到下：

1. 上一頁 / 下一頁（不變）。
2. **切換鈕**：目前空間的圖示和名稱，下面一排小圓點表示這是第幾個空間。點開是空間清單：每個空間一行（圖示、名稱、一句狀態、快捷鍵），最後一項是「保存其他類型的資料」。選單裡只有空間，沒有別的操作。
3. **這個空間的頁面**，最多四到五個。
   - 瀏覽紀錄：首頁、紀錄、洞察、備份。
   - Agent 對話：洞察、紀錄、專案、備份。Agent 空間沒有首頁，第一頁就是洞察（用戶 2026-11-13）。
   - 兩邊的清單頁都叫「紀錄」，不叫「對話」：PathKeep 自己有一個聊天機器人（助理），「對話」會跟它混在一起（用戶 2026-11-13）。
4. 一條分隔線。
5. **共用的項目**，切換空間時不動：背景任務指示器（放最上面）、助理、⌘K、鎖定、深淺色、設定。

語言切換不在導航列，只在設定裡（用戶 2026-11-13）。

只開一種資料類型時外框一樣：切換鈕還在，選單裡是那一種加上「保存其他類型的資料」。這樣開第二種時，導航不會變樣。「保存其他類型的資料」只在還有沒開的類型時出現；PathKeep 做好的類型全都開著時，選單裡沒有這一項，不放一個按了沒事的項目。

### 4.2 路由

每個空間的頁面在 `#/<空間>/<頁面>` 底下：`#/browsing/home`、`#/browsing/history`、`#/browsing/insights`、`#/browsing/backup`、`#/agent/insights`、`#/agent/chats`、`#/agent/projects`、`#/agent/backup`。共用的畫面不帶空間：`#/settings/:section`、`#/ask`、`#/tasks`。`#/` 導到上次所在空間的第一頁。

在空間自己的頁面上，目前是哪個空間由網址決定，所以從別的空間的連結、搜尋結果或 ⌘K 跳過去，空間會跟著換。在共用的畫面（設定、助理、背景任務）上，導航列沿用上一個空間。「上一個空間」跟深淺色一樣只是記在本機的偏好，下次打開 app 會回到它的第一頁。

### 4.3 顏色

每個空間有自己的色相。瀏覽紀錄沿用 PathKeep 的橘色，Agent 對話是青綠色。

**跟著空間換的**：視窗底色與漸層（`--wall`、`--window`）、`--brand`、`--brand-soft`、`--ring`、熱力圖色階（`--heat-1` … `--heat-4`）。也就是：選取、焦點框、進行中的狀態、只有一個序列的圖表、熱力圖。

**永遠不換的**：

- 內容面板和卡片是中性色，文字顏色不變，主要按鈕仍是中性黑白。
- 狀態色：紅（失敗、破壞性操作）、綠（成功）。
- 把同一種東西分成幾份來比的圖表（依工具、依瀏覽器、依分類）用一組固定的分類色，不含空間的強調色，所以同一張圖在哪個空間看顏色都一樣。一張圖的主角是這一頁的主要數量、旁邊帶一條對照的序列時（瀏覽紀錄洞察的「每天的頁面與搜尋」），主角仍然用強調色。
- 依工具分的圖表：每個工具一個固定顏色（見 4.4）。

**規則**：

- 顏色永遠不是唯一的線索。空間靠圖示和名稱分辨，狀態靠圖示和文字。
- 新空間的色相離紅色（`--red`）至少 20°，免得強調色讀起來像錯誤。橘色離紅色 23°，是目前最近的一個。
- 每加一個空間，在兩種主題下各量一次對比：強調色拿來當文字或細線圖示時，對卡片要到 4.5:1（WCAG AA）；到不了就只用在填色、框線和選取，文字連結用前景色加底線。
- 毛玻璃視窗下桌面會透出來，底色放在視窗層，很淡是預期的。

### 4.4 依工具分的顏色

洞察裡依工具分的圖表，每個工具用固定的顏色，不跟著空間的強調色。規則：

- 顏色來自一組在淺色、深色主題下都驗過、色盲也分得開的分類色。接近工具自家的顏色是加分，不是規則：好幾家都是黑、白、藍、橘，照抄會撞色。
- 圖例永遠有工具的圖示和名稱。
- 一張圖最多分出色盤放得下的幾個工具，其餘合成「其他」（灰色）。
- 新增一個工具的支援時，在色盤裡給它一個固定的位置；沒有位置的歸「其他」。

### 4.5 頁面寬度

Agent 空間的頁面（洞察、專案、專案洞察、備份）從導航列旁邊開始，隨視窗變寬，不放在置中的固定寬度欄裡。用戶不喜歡寬螢幕上左右兩大片空白（2026-11-13）。

- 多出來的寬度要放有用的東西：更多欄位、更多卡片欄。不是把同樣的內容拉寬。
- 閱讀用的文字仍然限制行寬（對話內文、設定的說明）。
- 洞察是給人看的報告，卡片可以攤開排成多欄；卡片的順序照價值排，排版不能為了填滿空間而調換順序（用戶 2026-11-13）。固定寬度的圖（年度日曆）保持自己的大小，卡片跟著圖的寬度，不把格子拉大。
- 瀏覽紀錄的頁面這次不動，之後另外重做。在那之前，`ui-review-guardrails.md` §3 的白名單只管瀏覽紀錄空間。

### 4.6 快捷鍵

- 切換到第 N 個空間：macOS 是 ⌘1 … ⌘9，Windows、Linux 是 Ctrl+1 … Ctrl+9，順序跟切換選單一樣。跟 ⌘K / Ctrl+K 用同一個修飾鍵。
- 不用 ⌃1 … ⌃9：那是 macOS「切換到桌面 N」的系統快捷鍵，開著的時候系統會先收走，app 收不到。
- ⌘K 搜尋所有空間，並列出「切換到」每個空間。

### 4.7 切換的動畫

切換空間時，導航列裡屬於空間的項目（切換鈕和頁面）照切換的方向左右滑出、滑入，項目之間稍微錯開；共用的項目不動。舊項目滑出之後，新空間的頁面才開始渲染並淡入，所以重的頁面不會拖慢動畫。只動 `transform` 和 `opacity`，不用彈簧。系統開了「減少動態效果」時只淡入淡出。

### 4.8 這次不做

- 一次看兩個空間（分割畫面）、把某個空間的頁面釘到另一個空間。
- 讓使用者自己選空間的顏色。

## 6. 落地

**外框（`WORK-SPACES-SHELL`，2026-11-14）**

做了的：資料類型的登記表與從它組出來的路徑（`src/lib/spaces/`）；切換鈕與選單；`#/<空間>/<頁面>` 的路由，瀏覽紀錄的頁面搬到 `#/browsing/…`；目前的空間由網址決定、共用畫面沿用上一個、記在本機；跟著空間換的 token 與每個空間自己的色相；⌘1 … ⌘9；切換的動畫；語言鈕移出導航列；背景任務指示器；⌘K 從登記表來；固定的分類色 `--chart-1` … `--chart-6` 與 `--chart-other`，有測試守著對比和色盲下的可分辨度。§5 第一張表的七條都已改寫進各自的文件。

跟這份文件不完全一樣、或還不完整的：

- **切換、快捷鍵、動畫的 E2E** 在 `shell-3-switch.spec`（2026-11-20）：兩個空間的選單與狀態行、⌘1 / ⌘2、⌘K 的「切換到」、`#/` 回到上一次的空間、滑動時導航列的項目真的橫移、「減少動態效果」時只淡入淡出、暫停的類型照樣在選單和 ⌘K 裡。
- **Agent 對話已經登記（2026-11-18）。** 哪些空間開著由後端的 `list_data_kinds` 決定，收到 `pathkeep://data-kinds-changed` 就重讀；回答之前照預設（瀏覽紀錄開著），鎖定時連同查詢快取一起清掉。沒有頁面的空間不會被當成開著顯示。關閉中的類型的任何網址都顯示「沒有開啟」的畫面，導航列留在原來的空間。
- **切換選單的「保存其他類型的資料…」** 在有關閉中的類型時出現，寫還有幾種，打開「設定 › 管理資料類型」。
- **切換鈕下面的小圓點**只在開著兩種以上時出現；只有一個空間時一個點不代表什麼。
- **背景任務指示器**點下去和「打開背景任務」都到 `#/tasks`（2026-11-20）。它只顯示 app 在每個畫面本來就追蹤的工作（備份、匯入、搜尋索引佇列、對話備份），不為了它輪詢，所以洞察佇列的工作不在裡面，索引工作沒有即時的百分比。「需要你看一下」是「上一次瀏覽紀錄備份失敗」加上需要看一下的對話備份；選單底下那一行寫同一個數字（`{n} 項需要你看一下`），到 `#/tasks`。背景任務頁上瀏覽紀錄「需要你看一下」的列（每一次失敗或沒做完的工作）不算進這個點，因為後端還不能收起它們，算進去點就永遠不會消失。
- **⌘K**（2026-11-20）照 `data-spaces.md` §6 換了標題、說明和輸入框提示，「前往」裡有背景任務，Agent 對話的兩組（對話、專案）從打開時就在；登記表的 `palette.fromEmpty` 讓一個空間的結果不必等兩個字。
- **Agent 對話的色相（青綠，195）**在 Agent 空間是目前的空間時用上了；§4.3 要求的兩種主題下的對比量測還沒做（沒有開 app 量），之後補。機制是每個空間一個 oklch 色相，其餘的值從它推出來；瀏覽紀錄保留原本逐個寫定的值，畫面跟之前一模一樣。
- **瀏覽紀錄洞察的「每天的頁面與搜尋」**主序列仍是強調色（§4.3 的說明）。現有的圖表都沒有改色；分類色等依工具、依瀏覽器分的圖表做的時候用。
