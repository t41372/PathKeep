# Agent history ecosystem: implementation research

Research date: 2026-11-11. Scope: public implementations of local agent-history backup, export, search, replay, and migration. This document records evidence and engineering implications; it does not claim that every discovered tool was executed, that every advertised provider works, or that an Internet-wide inventory can be complete.

No tool studied here was installed or executed. No private conversation was submitted to a remote service. Source was read at the pinned revisions below. No third-party implementation was copied into PathKeep.

## Method and coverage

Discovery combined searches for agent session backup/archive/export, cross-agent history search, transcript conversion/migration, and agent-specific recovery. Follow-up searches covered Claude Desktop/Cowork and token analytics because sidecars, deletion, and repeated usage records expose failures that a message-only viewer misses. The following evidence levels prevent a repository description from becoming a support claim:

- **Implementation**: relevant parser, archive, discovery, or writer source was inspected.
- **Companion research**: another harness research document in this directory examines the relevant implementation.
- **Inventory**: repository metadata and advertised purpose were checked; no correctness judgment is implied.

The search found three materially different products: immutable/native evidence preservation, lossy conversation conversion, and a catalog that reads original files on demand. They must not share a single undifferentiated “backup supported” flag.

## Native bundles and migration: concrete implementations

### codex-claude-transfer

Its ZIP bundle separates `manifest.json`, `checksums.json`, and native session bytes. The manifest describes source identity, original path, origin OS/home, archived/compressed state, byte count, and digest; Claude task and opt-in memory objects are separate. Legacy bundles without a tool field mean Codex. This is a useful preservation model because the listing metadata is not mistaken for the conversation itself. [Manifest](https://github.com/ahmojo/codex-claude-transfer/blob/13a84383a5e00db61d527e782f36f4bbf0c707d2/internal/bundle/manifest.go)

Ordinary export streams bytes into ZIP while hashing, then closes and syncs a destination-directory temporary file before rename. Redaction/image removal follows a different, whole-file transformation path. The ordinary copy is not bracketed by a source-stability check and reads until EOF; its recorded original size comes from earlier discovery. Therefore its checksum verifies captured bytes, not a point-in-time source snapshot. PathKeep needs both a digest and a defined stable-capture boundary. [Exporter](https://github.com/ahmojo/codex-claude-transfer/blob/13a84383a5e00db61d527e782f36f4bbf0c707d2/internal/bundle/export.go)

Codex inherited history is a particularly important exception to “one JSONL equals one complete session.” `history_base.thread_id` identifies a physical rollout by filename UUID; the exporter recursively includes the parent from active or archived storage. A missing parent fails export. Rewriting images, redacting, changing CWD, or importing as a new copy is refused for inherited history because byte offsets would no longer address the original bytes. A backup must preserve the dependency graph and original bytes even if its query projection flattens the visible conversation. [Lineage](https://github.com/ahmojo/codex-claude-transfer/blob/13a84383a5e00db61d527e782f36f4bbf0c707d2/internal/bundle/lineage.go)

Import checks manifest bindings and all hashes before native writes, bounds member count and decompressed bytes, and rejects undeclared session-shaped members. It distinguishes equal files, conflicts, replacement-with-backup, and a new-identity import. Relative names reject absolute paths, volume syntax, backslashes, dot segments and noncanonical forms; existing destination components are checked for symlinks. File-level atomic rename does not create a multi-file transaction. [Importer](https://github.com/ahmojo/codex-claude-transfer/blob/13a84383a5e00db61d527e782f36f4bbf0c707d2/internal/bundle/import.go), [path checks](https://github.com/ahmojo/codex-claude-transfer/blob/13a84383a5e00db61d527e782f36f4bbf0c707d2/internal/safety/paths.go), [writer](https://github.com/ahmojo/codex-claude-transfer/blob/13a84383a5e00db61d527e782f36f4bbf0c707d2/internal/safety/atomic.go)

Merge compares byte prefixes before trying canonical JSON record equality; numeric values retain their JSON representation rather than passing through floating point. Divergence stays a conflict. Both histories are materialized in memory, which is a scaling limit for PathKeep. Claude persisted tasks are validated against their filename ID and owning transcript; auto-memory remains a separate opt-in. [Merge](https://github.com/ahmojo/codex-claude-transfer/blob/13a84383a5e00db61d527e782f36f4bbf0c707d2/internal/bundle/mergesync.go), [task ownership](https://github.com/ahmojo/codex-claude-transfer/blob/13a84383a5e00db61d527e782f36f4bbf0c707d2/internal/bundle/claude_tasks.go)

### agent-session-pack

This is primarily disk reclamation. It compresses, decompresses, verifies, writes a manifest, removes the original, and writes a stub. Distinct results include missing, backup-only, dry-run, no-candidates, and packed, with an explicit original-modified indicator. PathKeep's approved read-only source boundary excludes this removal/stub workflow. [Packing](https://github.com/YosefHayim/agent-session-pack/blob/6221e2d43abacb066031ff8aa5fd58ce86c181a1/src/pack/sessions.ts), [stub](https://github.com/YosefHayim/agent-session-pack/blob/6221e2d43abacb066031ff8aa5fd58ce86c181a1/src/archive/session-stub.ts)

Its directory digest covers sorted relative regular-file names and content hashes, not complete filesystem metadata, empty directories, or symlink contents. Directory restore removes the destination before decompression/verification, and the inspected capture path has no lock covering the verification-to-delete interval. Those are source-level design observations, not reproduced data-loss incidents. External `tar` is also not a reproducible bundled dependency for this repo. [Writer](https://github.com/YosefHayim/agent-session-pack/blob/6221e2d43abacb066031ff8aa5fd58ce86c181a1/src/archive/writer.ts), [hashing](https://github.com/YosefHayim/agent-session-pack/blob/6221e2d43abacb066031ff8aa5fd58ce86c181a1/src/archive/hash.ts), [manifest writes](https://github.com/YosefHayim/agent-session-pack/blob/6221e2d43abacb066031ff8aa5fd58ce86c181a1/src/archive/manifest-store.ts)

Advertised provider coverage needs implementation checks: the Claude scanner excludes `subagents`; the Codex adapter defaults only to active `sessions`; Cursor discovery returns an empty list; the OpenCode adapter scans directory markers/JSONL and contains no SQLite reader. A provider badge cannot substitute for fixture-backed completeness. [Claude](https://github.com/YosefHayim/agent-session-pack/blob/6221e2d43abacb066031ff8aa5fd58ce86c181a1/src/providers/claude-code.ts), [Codex](https://github.com/YosefHayim/agent-session-pack/blob/6221e2d43abacb066031ff8aa5fd58ce86c181a1/src/providers/codex.ts), [Cursor](https://github.com/YosefHayim/agent-session-pack/blob/6221e2d43abacb066031ff8aa5fd58ce86c181a1/src/providers/cursor.ts), [OpenCode](https://github.com/YosefHayim/agent-session-pack/blob/6221e2d43abacb066031ff8aa5fd58ce86c181a1/src/providers/opencode.ts)

### session-porter and resume-from

session-porter's portable model has no complete raw-record field. Its “raw” transfer still repairs tool pairs, synthesizes missing output text, and merges adjacent same-role messages for Claude. That label means unsummarized conversion, not original-byte preservation. Its Codex writer hardcodes a `state_5.sqlite` schema and native operational settings, calls external `sqlite3`, and treats registration failure as best effort. This is direct evidence that native restore must be a separately versioned capability, not an incidental effect of export. [Model](https://github.com/liwala/session-porter/blob/c973b70d3384e7676375f1186187c4549f172279/src/types.ts), [transfer](https://github.com/liwala/session-porter/blob/c973b70d3384e7676375f1186187c4549f172279/src/transfer.ts), [Claude writer](https://github.com/liwala/session-porter/blob/c973b70d3384e7676375f1186187c4549f172279/src/claude.ts), [Codex writer](https://github.com/liwala/session-porter/blob/c973b70d3384e7676375f1186187c4549f172279/src/codex.ts)

resume-from validates Pi parent chains but intentionally excludes tool-result bodies, hidden reasoning, and unsupported entries from transfer. Its new native session uses new IDs and converts tool effects into ordinary assistant text to avoid unmatched native tool protocol. Its file committer stages private files and publishes without overwrite. These are useful migration decisions, explicitly different from backup fidelity; details are in `pi-deepseek.md`.

## txcript: a modular conversion library, not an archival engine

At version 0.14.4, the public API distinguishes a harness's native `Body`, conversion through `Codec`, text parsing through `TextCodec`, and filesystem discovery/load/save through `Store`. Unknown valid records and unknown tool arguments can remain native JSON. This is a useful separation of format knowledge from presentation. However, the common representation is a whole-session vector with user/assistant roles and tool-result blocks; branch identity, arbitrary native events, system/developer context, and read-side lineage do not all round-trip through it. [Traits](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/src/transcript.rs), [common model](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/src/common.rs)

Its native JSONL path parses and reserializes, silently skips invalid JSON lines, and adds newlines. Claude/Codex/Pi save use ordinary file writes. Semantic preservation of valid unknown JSON does not preserve whitespace, CRLF, malformed tails, or inherited-history byte offsets. There is no immutable raw-capture/retention protocol in those paths. PathKeep should not use conversion output as its authoritative archive. [JSONL helper](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/src/harness/jsonl.rs), [Claude](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/src/harness/claude_code.rs), [Codex](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/src/harness/codex.rs), [Pi](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/src/harness/pi.rs)

Aggregate discovery intentionally suppresses an unreadable store into an empty result, and parallel-worker failure can also contribute no rows. That is a tolerant session-picker policy, not a backup completeness contract. Its source fingerprints use length/mtime; many load paths still materialize the full session. Corpus scanning bounds lifetime to one transcript at a time, but does not bound the largest transcript. [Discovery](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/src/local.rs), [parallel discovery](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/src/harness/mod.rs), [search](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/src/search.rs), [cache](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/cli/src/cache.rs)

Notable per-format boundaries:

- Pi Common conversion traverses records in file order instead of projecting a selected branch. Compaction remains native-only; converted IDs are regenerated. It is neither the original tree nor Pi's exact active context. [Pi caveats](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/docs/formats/pi.md)
- Cowork combines header, Claude transcript, audit log and narrowly identified related artifacts; it excludes subagent transcripts and unreferenced uploads/outputs. Missing transcript/audit can become empty collections. Audit JSON is reserialized, which is unsuitable for preserving an HMAC-chained original log byte-for-byte. The narrow attachment recognizer is preferable to following every tool-mentioned path, but is not a complete bundle inventory. [Cowork](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/src/harness/cowork.rs), [file references](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/src/harness/cowork_files.rs)
- OpenCode reads selected old `session`/`message`/`part` fields with separate queries, excludes archived sessions, and has no encompassing read transaction in the inspected loader. It drops malformed part JSON. This also predates the current upstream v2 schema described below. [Store](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/src/harness/opencode.rs)
- Cursor Desktop notes document global `state.vscdb`, composer headers, composer and bubble rows, and separate sidebar membership, while explicitly excluding older per-workspace databases and shared `agentKv` blobs. This is valuable version-specific reverse-engineering evidence, not an official durable schema contract. [Format provenance](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/docs/formats/cursor-desktop.md)

Default features include live-account transports for Claude Chat, cloud Cowork and ChatGPT, although aggregate local discovery excludes those stores. PathKeep should not acquire those capabilities implicitly. Recommendation: use the project as an interoperability research map, not a dependency for reliable backup. [Features](https://github.com/skillsynchq/txcript/blob/c60e686e7ed30e67019288eed80c4be478512d64/Cargo.toml)

## Search and viewer implementations

### ah

`AgentPlugin` exposes discovery, metadata, parent relation, archive state, message/search iterators, and individual capabilities. Container-backed sessions use virtual identities and provider hooks rather than pretending each session is an OS file. Callbacks can stop traversal. The source explicitly distinguishes self-contained JSONL lines from formats requiring reconstruction before search; a fast byte-level filter is only valid when the adapter promises that property. [Adapter contract](https://github.com/nihen/ah/blob/69b16ef4fe1f250a7e31abab7fa09e62438ff5c4/src/agents/mod.rs)

Discovery expands container sessions, deduplicates aliases, applies stable ordering, and uses a bounded heap for a requested newest-N list. It still gathers source paths before selecting the top N; this is a useful query pattern, not evidence of bounded whole-corpus memory. [Collector](https://github.com/nihen/ah/blob/69b16ef4fe1f250a7e31abab7fa09e62438ff5c4/src/collector.rs)

Cursor's project-directory encoding is lossy: multiple punctuation/path structures can produce the same slug. `ah` walks existing directories to guess a reconstruction, with a visit budget; removed projects and ambiguous matches remain heuristic. PathKeep should store recorded CWD separately from a guessed display label and never use slug inversion as authoritative project identity. [Cursor implementation](https://github.com/nihen/ah/blob/69b16ef4fe1f250a7e31abab7fa09e62438ff5c4/src/agents/cursor.rs)

### Agent Session Browser

Its lightweight catalog samples the first/last 128 KiB of most files and stores summaries, leaving transcript bodies in the provider source. Refresh uses size/mtime/parser version to skip files, and removes missing sources from the catalog. This is sensible for a source viewer but does not retain a conversation after source deletion. Sampling also cannot prove complete parse coverage. [Catalog](https://github.com/gautamgpt1/agent-session-browser/blob/834a16792a63b8b3c4802b43d0a0d33d995e060a/src/server/catalog.ts), [indexer](https://github.com/gautamgpt1/agent-session-browser/blob/834a16792a63b8b3c4802b43d0a0d33d995e060a/src/server/indexer.ts)

Detail pages are bounded to 500 items, but the cached parsed session can still retain all compact items. Compaction truncates message text/tool output and strips raw metadata from the compact projection. Export reparses the original and streams through callbacks; the search collector has a one-million-character cap. These are different guarantees: bounded page size, bounded item text, full raw preservation, and fully searchable content must each be stated independently. [Source reader](https://github.com/gautamgpt1/agent-session-browser/blob/834a16792a63b8b3c4802b43d0a0d33d995e060a/src/server/source-reader.ts), [collector](https://github.com/gautamgpt1/agent-session-browser/blob/834a16792a63b8b3c4802b43d0a0d33d995e060a/src/server/bounded-parse.ts)

### claude-code-transcripts

Its JSONL conversion keeps only `user`/`assistant`, timestamp, message, and the compaction-summary flag. Other events and invalid JSON lines are skipped. That is appropriate to a readable rendering but insufficient as a backup parser unless native bytes are stored separately. The README's optional original-JSON inclusion confirms that distinction. Its undocumented remote-web integration was already marked broken at this revision, a concrete warning against relying on private online APIs for local backup. [Parser](https://github.com/simonw/claude-code-transcripts/blob/316fd093aca3c9c0ad8aa70092711aee3adacc6e/src/claude_code_transcripts/__init__.py#L451), [status](https://github.com/simonw/claude-code-transcripts/blob/316fd093aca3c9c0ad8aa70092711aee3adacc6e/README.md)

## Raw retention and scale lessons from CASS

CASS keeps a raw mirror independent from normalized searchable records. The inspected sources describe content-addressed chunks, versioned manifests, source observations, and retained copies after provider deletion. Append-heavy transcript policy uses smaller chunks to avoid retaining a nearly complete new large file on every append. This is an independent architectural requirement for PathKeep; no CASS implementation is being reused. [Raw mirror boundary](https://github.com/Dicklesworthstone/coding_agent_session_search/blob/c9c94511ace206037ae33200e9649ead52a69b8c/src/raw_mirror.rs), [store](https://github.com/Dicklesworthstone/coding_agent_session_search/blob/c9c94511ace206037ae33200e9649ead52a69b8c/src/raw_mirror/store.rs)

The connector capability boundary distinguishes a self-contained source from one whose interpretation depends on sibling metadata/WAL files. Before/after observations test replacement, disappearance, sidecar changes, and newly appearing optional sidecars. Unavailable observations must not be treated as evidence of stability or as proof of perpetual mutation. Native paths that JSON cannot encode expose another coverage boundary. [Dependency contract](https://github.com/Dicklesworthstone/coding_agent_session_search/blob/c9c94511ace206037ae33200e9649ead52a69b8c/src/connectors/source_dependencies.rs), [stability tests](https://github.com/Dicklesworthstone/coding_agent_session_search/blob/c9c94511ace206037ae33200e9649ead52a69b8c/src/indexer/watch_source_stability.rs)

Published v0.10 release evidence reports a per-conversation indexing cap that left 39.6% of nonempty messages unsearchable on one real archive, giant conversations requiring bounded persistence slices, and WAL-only writes missed by watch mode. These are upstream reports, not PathKeep measurements. A related issue documents profiles hidden by hardcoded default roots. Requirements derived here: no silent whole-conversation text cap, bounded ingest transactions, sidecar-aware freshness, explicit custom roots, and coverage counters independent from success/failure. [Release report](https://github.com/Dicklesworthstone/coding_agent_session_search/releases/tag/v0.10.0), [profile discovery report](https://github.com/Dicklesworthstone/coding_agent_session_search/issues/214)

## Analytics: ccusage

The current Rust project separates source-specific discovery/parser/token semantics from shared aggregation. Codex's parser is stateful: cumulative totals differ from per-turn deltas; copied parent usage in forks must not be counted as new work; compaction response IDs need their own reconciliation. It inspects actual event markers rather than treating `cli_version` as a reliable version for the whole resumed file. Thus backup should retain native usage receipts and provenance even if v1 does not promise reconciled billing analytics. [Adapter responsibilities](https://github.com/ccusage/ccusage/blob/d06f55bb8937479fea5014fd36a0e7b9286fb630/rust/adapters/README.md), [Codex parser](https://github.com/ccusage/ccusage/blob/d06f55bb8937479fea5014fd36a0e7b9286fb630/rust/adapters/codex/src/parser.rs), [format notes](https://github.com/ccusage/ccusage/blob/d06f55bb8937479fea5014fd36a0e7b9286fb630/rust/adapters/codex/src/README.md)

The Codex reader handles plain and Zstandard rollouts and retries the alternate encoding if the file is compressed/restored between discovery and open. Claude daily aggregation distinguishes response identity, repeated streaming rows, and sidechain replay; simple summation of every `usage` object is wrong. Token quantities, estimated API-equivalent price, and a subscription bill are separate concepts. PathKeep must not present inferred price or missing token fields as exact observations. [Encoding reader](https://github.com/ccusage/ccusage/blob/d06f55bb8937479fea5014fd36a0e7b9286fb630/rust/adapters/codex/src/reader.rs), [Claude deduplication](https://github.com/ccusage/ccusage/blob/d06f55bb8937479fea5014fd36a0e7b9286fb630/rust/adapters/claude/src/daily.rs)

## Additional harness storage formats

The following are source-backed adapter candidates, not a claim of delivered PathKeep support. The strongest next candidates are Continue, Cline/Roo, Gemini, and Goose. OpenCode and Kimi need explicit storage-generation detection. Primary research here was read-only; no harness was launched to discover its files.

### Continue

Research revision: `5522c6f44ca0ac3528b37244818fbfa39b5af470`.

Default storage is `~/.continue/sessions/<sessionId>.json` with a separate `sessions.json` index; `CONTINUE_GLOBAL_DIR` overrides the root. The session has `sessionId`, title, workspace directory, history and optional mode/model/usage. Each history entry wraps its actual message under `message`.

`HistoryManager.save` overwrites the session and index separately, without a joint transaction. Discovery must enumerate session files rather than trust the index exclusively. The upstream reader's fallback to an empty session on read/parse error must not be used to certify backup completeness. CLI persistence removes system messages, so even a complete local capture is not complete runtime context. Creation time provenance also varies between recorded index data and filesystem birth time. [History manager](https://github.com/continuedev/continue/blob/5522c6f44ca0ac3528b37244818fbfa39b5af470/core/util/history.ts), [paths](https://github.com/continuedev/continue/blob/5522c6f44ca0ac3528b37244818fbfa39b5af470/core/util/paths.ts), [CLI persistence](https://github.com/continuedev/continue/blob/5522c6f44ca0ac3528b37244818fbfa39b5af470/extensions/cli/src/session.ts)

### Cline and Roo Code

Research revisions: Cline `c5df41f937c496ce8c8e689ba58776593c703dfa`; Roo `b867ec9145750d0ae1ff7f02d35406e9bf2a0b16`.

Cline's classic disk contract includes `api_conversation_history.json`, `ui_messages.json`, `context_history.json` and `task_metadata.json`. API messages and UI messages carry different information. Host/edition determines storage roots; both editor global storage and home-based `~/.cline/data/tasks` layouts exist. Preserve root identity and enumerate task directories directly. An upstream incident describes intact task files becoming invisible after index migration; the index is not the transcript authority. [Disk contract](https://github.com/cline/cline/blob/c5df41f937c496ce8c8e689ba58776593c703dfa/apps/vscode/src/core/storage/disk.ts), [index migration incident](https://github.com/cline/cline/issues/6183)

The same pinned revision also contains an explicit SDK `legacy-state-reader`: it describes this JSON task layout as pre-SDK storage and continues to expose old tasks through it. Therefore support for this layout is **Cline classic task bundles**, not a blanket claim about the current SDK store. Its path resolver prioritizes `CLINE_DATA_DIR`, then `CLINE_DIR/data`, then `~/.cline/data`; its global `secrets.json`, settings and MCP configuration are outside transcript backup. [SDK legacy reader](https://github.com/cline/cline/blob/c5df41f937c496ce8c8e689ba58776593c703dfa/apps/vscode/src/sdk/legacy-state-reader.ts)

Roo supports a custom storage path and extension-global-storage default, with `tasks/<id>` bundles. Extended API messages include timestamps, IDs, reasoning/encrypted content and compaction/truncation parent relations. Its legacy `claude_messages.json` fallback can **delete the old file after reading it**; calling native persistence helpers is therefore not a read-only strategy. Read files independently, preserve both native histories and metadata, and treat multi-file consistency separately from safe writes of each JSON file. [API persistence](https://github.com/RooCodeInc/Roo-Code/blob/b867ec9145750d0ae1ff7f02d35406e9bf2a0b16/src/core/task-persistence/apiMessages.ts), [UI persistence](https://github.com/RooCodeInc/Roo-Code/blob/b867ec9145750d0ae1ff7f02d35406e9bf2a0b16/src/core/task-persistence/taskMessages.ts), [roots](https://github.com/RooCodeInc/Roo-Code/blob/b867ec9145750d0ae1ff7f02d35406e9bf2a0b16/src/utils/storage.ts)

### Gemini CLI

Research revision: `e5d88fb2c036ce7e0c27131469cd963221b9d9e7`.

Current chats use `tmp/<project identifier>/chats/session-<timestamp>-<short id>.jsonl`; old whole-document JSON is also relevant. The JSONL is an ordered state journal: records can replace a message ID, set metadata, patch tool results, remove/reorder messages, or rewind the message sequence. `$rewindTo` removes the target and following messages; an unknown target clears the current projection in the upstream loader. Subagent logs nest under the full parent session ID. A parser that emits every line as a new message is wrong. [Types](https://github.com/google-gemini/gemini-cli/blob/e5d88fb2c036ce7e0c27131469cd963221b9d9e7/packages/core/src/services/chatRecordingTypes.ts), [writer/replay](https://github.com/google-gemini/gemini-cli/blob/e5d88fb2c036ce7e0c27131469cd963221b9d9e7/packages/core/src/services/chatRecordingService.ts)

Project storage now uses a registry mapping absolute roots to identifiers, plus `.project_root` recovery markers and old-hash migration. Do not recompute a project hash and assume it is the only directory. `GEMINI_CLI_HOME` affects roots; seatbelt execution uses `.cache/.gemini` instead of the usual `.gemini`. Related data also lives in session tool-output/log directories. [Storage](https://github.com/google-gemini/gemini-cli/blob/e5d88fb2c036ce7e0c27131469cd963221b9d9e7/packages/core/src/config/storage.ts), [registry](https://github.com/google-gemini/gemini-cli/blob/e5d88fb2c036ce7e0c27131469cd963221b9d9e7/packages/core/src/config/projectRegistry.ts), [artifacts](https://github.com/google-gemini/gemini-cli/blob/e5d88fb2c036ce7e0c27131469cd963221b9d9e7/packages/core/src/utils/sessionOperations.ts)

Upstream can ignore malformed lines and can stop logging after ENOSPC while the conversation continues. Preserve malformed native bytes and report parse coverage; do not imply a disk backup recovers messages the harness never persisted.

### Goose

Research revision: `721edae7284910176fb5d32d6c332aabcb1f738a` in the relocated `aaif-goose/goose` repository.

The current store is `Paths::data_dir()/sessions/sessions.db`, schema 18, using WAL. Sessions carry parent/project/archived metadata; messages carry IDs, content JSON and metadata JSON. Native order is `(created_timestamp, id)`, not timestamp alone. A separate usage ledger records per-request and compaction usage; do not add it to already cumulative session totals. [Schema and query implementation](https://github.com/aaif-goose/goose/blob/721edae7284910176fb5d32d6c332aabcb1f738a/crates/goose/src/session/session_manager.rs)

`GOOSE_PATH_ROOT` must be absolute and puts data under `<root>/data`. A stale source comment mentions a macOS Application Support path, but the dependency selection (`etcetera` 0.11.0) uses XDG on macOS, normally `~/.local/share/goose`, subject to XDG overrides. This is why path discovery must follow executable code, not comments alone. A consistent SQLite snapshot must include WAL-visible data and preserve unknown tables/JSON. [Path implementation](https://github.com/aaif-goose/goose/blob/721edae7284910176fb5d32d6c332aabcb1f738a/crates/goose/src/config/paths.rs), [dependency platform selection](https://docs.rs/crate/etcetera/0.11.0/source/src/app_strategy.rs)

### OpenCode

Research revision: `e56eff2bc01649b3aa21224876b8874e77dea4b0`.

At least three storage generations matter: legacy JSON trees, v1 SQLite, and current v2 SQLite. The current source has moved to `packages/core`. Database names vary by channel and `OPENCODE_DB`; an in-memory database is possible and is not discoverable as a persistent file. Inspect schema rather than assuming every `opencode.db` is the old three-table layout. [Database path](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/cli/src/database-path.ts)

v2 includes `session_v2`, `session_message`, `session_part`, inbox/instruction tables, `blob`, and `blob_ref`. Parent session, fork source, and fork boundary are separate concepts. Messages have session-local sequence; parts have ordinal. Media may live as SHA-256-addressed SQLite blobs rather than inline message content. Backing up only message JSON loses those bytes. Native initialization runs migrations and pragmas; do not invoke it against the user's database. [Session schema](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/core/src/session/sql.ts), [media storage](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/core/src/session/blob.ts), [v1 migration](https://github.com/anomalyco/opencode/blob/e56eff2bc01649b3aa21224876b8874e77dea4b0/packages/core/src/database/v1-migration.bun.ts)

### Aider

Research revision: `5dc9490bb35f9729ef2c95d00a19ccd30c26339c`.

Default `.aider.chat.history.md` and `.aider.input.history` are project-local, with configurable paths; optional LLM-history logging is a separate setting. Raw file backup is straightforward, but Markdown delimiters can also occur inside message text, so structural extraction is inherently weaker than native JSON events. Discovery needs known project roots or explicit source selection: one home directory cannot find all Aider histories. `--restore-chat-history` is optional and is not proof that an arbitrary rendered Markdown export is a fully resumable native session. ### Kimi and Amp

Legacy Kimi CLI research revision: `9ab1286b8fe4e6bcd116949a27ce5e0ac3389c82`; new Kimi Code: `13590cdea594d3dfa86fd38f19f3ff4de22dea15`.

The legacy store groups sessions under an MD5 of working directory and keeps context/wire logs, state and subagent data, with a separate work-directory map. Context can be prepended or rotated/rebuilt during revert; it is not safely modeled as endless append. ## Additional-adapter implementation boundary

The delivered `session_json` adapter family supports the above Continue envelope and classic Cline/Roo JSON task formats through explicitly selected native history roots. Tests were written before implementation; execution belongs to the final project validation record.

- Continue normalizes the `history` array one item at a time, retaining the complete item (including context and unknown fields) in each event payload. `sessionId`, title, workspace directory and model title can appear before or after history. The separate index is raw metadata; index creation dates and aggregate usage are not silently joined or treated as transcript facts.
- Cline/Roo normalizes API conversation arrays. The task directory supplies the native task ID; it does not supply a guessed project path. Earliest/latest native message `ts` are observed event bounds, not proof of independent session creation/update times. Missing times remain absent.
- UI, context, task metadata and history-item files remain raw evidence, so multiple representations do not produce duplicate searchable messages. This means UI-only messages and metadata text are **not** included in the first normalized search projection. Raw exports retain them.
- Roo's legacy `claude_messages.json` is normalized only without a primary API-history file; both are preserved if present. No native migration helper runs, and no source is deleted.
- Inline images remain inside original JSON and event payloads. No arbitrary project file, context-provider path, tool argument or remote image URL grants filesystem/network access. External attachments not already embedded in captured task artifacts are not claimed complete.
- Bounded JSON framing precedes serde validation: memory is bounded by one configured record plus its decoded representation, rather than the whole history. Oversized records are drained and retain their original array ordinal gap; malformed/nonobject records produce content-free diagnostics. The raw captured file remains authoritative.
- Continue's unknown top-level fields remain raw evidence rather than synthetic message events. Unknown history/API objects remain payload-bearing events, with incomplete normalization reported when message semantics are not recognized.
- Cline's newer SDK persistence, source-side indexes as authoritative project metadata, effective Roo compaction projection, native resume and restoration remain outside this adapter family's contract.

These are format-reader guarantees. Actual installed-harness execution, large-corpus performance and additional platform validation must be reported separately; source-compatible synthetic fixtures do not establish those measurements.

## Implications for the core and its test contract

These are research conclusions, not claims that the implementation already satisfies them. Check the final implementation/capability document for delivered behavior.

1. Preserve native bytes and typed related artifacts before parsing. Parse failures, unknown events, invalid UTF-8, malformed lines, and unsupported format versions must not silently erase evidence.
2. Separate physical source ID, native conversation ID, host/root identity, capture version, and parser version. A copied fork, archived file, renamed directory, and duplicate native ID are not interchangeable.
3. Record capture completeness, parse completeness, attachment completeness, and search coverage independently. Missing source, permission denied, volatile file, missing parent, malformed record, unsupported parser, and destination write failure need distinct outcomes.
4. Never delete retained history merely because a provider removes it. Source disappearance changes presence metadata, not archival evidence.
5. A newline log may be append-only, rewritten, truncated, compressed, or an ordered state-change journal. Incremental checkpoints require verified prefix/identity semantics and explicit rewrite recovery; size/mtime alone cannot certify a same-length replacement.
6. SQLite sources require a consistent read/snapshot including WAL state. Copying only the main DB or applying `immutable=1` to a live WAL database is not a valid general rule.
7. Keep attachments within declared adapter roots and explicit references; reject symlink escape/traversal. Do not back up arbitrary tool-mentioned paths or execute native loaders with migration/cleanup side effects.
8. Use bounded file/record buffers and batched database writes. A small result page does not imply bounded parser memory. Search limits must return explicit truncation/coverage, not a false complete result.
9. Human-readable exports and redacted shareable exports are derived artifacts. Unknown events and raw bytes remain separately available; neither Markdown nor a normalized conversion is a native resumable backup.
10. Native resume/migration needs a per-provider, per-version contract. Preserve arguments as data, validate target existence, and avoid implicit shell execution. This task studies those capabilities and does not perform native writes.

Failure scenarios to preserve in the acceptance tests: append during capture; unfinished final line; same-size rewrite; rename/truncate/replacement; active-to-archive movement; plain-to-compressed transition; missing inherited parent; unknown event interleaved with valid messages; duplicate native IDs in different roots; identical replayed usage vs distinct same-text messages; inaccessible sibling; SQLite WAL-only commit; cancellation or disk-full before manifest publication; existing destination collision; and re-opening the backup after deleting its source.
