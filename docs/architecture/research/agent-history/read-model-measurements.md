# Measuring physical reads

Run from `src-tauri`. All three examples use synthetic data in temporary directories. The window example exercises both the retained-evidence reader and the published conversation API. Its separate outline/rendered database remains an independent comparison fixture.

| Prototype                            | Command on the measurement host                                                                                       | Decision                                                                                                                                                                                                                               |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Blob reads and writes                | `AH_SAMPLES=40 AH_BLOB_ROWS=32 cargo run --release -p agent-history --example blob_measurement`                       | Compare p95 fetch, authenticate, decompress and digest cost against **50 ms**. Above that threshold, reduce touched bytes and measure rendered pages before choosing a reader representation.                                          |
| Physical framing and 200-row windows | `AH_BYTES=264000000 AH_RECORDS=23812 AH_SAMPLES=40 cargo run --release -p agent-history --example window_measurement` | A usable window at head, middle and tail should take **≤100 ms p95**. First feedback and the longest interval without progress should be **≤100 ms**. Framing throughput is a baseline; the plan gives no full-file throughput cutoff. |
| Scenario J acceptance                | `cargo test --release -p agent-history --test scenario_j exact_scenario_j -- --exact`                                 | Fixed sizes regardless of size environment variables. Requires correct full bytes, absolute marker positions and physical ordinals 23,612–23,811 in the tail for all three transports.                                                 |
| Random rank                          | `AH_ENTRIES=14400000 AH_READS=100 cargo run --release -p agent-history --example outline_measurement`                 | The directory lookup and page decode contribute to the **≤100 ms p95** usable-window budget. Set `TMPDIR` to a **disk-backed** filesystem on Linux. Run in a four-core, 8 GiB cgroup and record the CPU quota, clock, memory limit, disk and filesystem with the JSON output. Use `/usr/bin/time -v` around the built release example to measure peak RSS independently of compiling it. The small defaults exercise the same paths. Two timing samples establish that a prototype runs; use the higher sample counts for a decision.

- **Cache conditions.** Each cold sequence closes Turso, syncs and evicts only the temporary files, then reopens. Linux uses `POSIX_FADV_DONTNEED` and checks page residency with `mincore` before opening. Open process handles or resident pages trigger bounded retries. The Linux runner prints the filename, attempt, handle count and resident-page count before retrying. After the sixth unsuccessful attempt it fails that sample. macOS uses the original `F_NOCACHE` sweep. Other platforms omit cold results. Opening the archive may warm metadata; timed window reads include page lookup, fetching/verifying evidence slices, native decode, interpretation and row construction. Warm reads repeat the same request on the same connection. Oracle comparisons follow the timed window.
- **Blob oracle.** Both plaintext and encrypted Turso receive compressed transcript and deterministic incompressible slices of 1 and 4 MiB. `AH_BLOB_MIB` scales both sizes. Each ID changes the input. Readers decompress and verify the original length and SHA-256, including mixed reads launched alongside a batch-priority writer. Writes and reads report nearest-rank p50/p95/p99.
- **Framing oracle.** The generator chooses lengths before encoding JSON. At full size the median is 605 bytes and the large group is 199,548 bytes. A deterministic mixture of prose and variable ASCII supplies the body. Every row has a unique native ID and a marker immediately before its JSON suffix. A full scan must agree with every independently accumulated start and length. Plain bytes, groups of 64 rows per zstd frame and one checksum-bearing frame encode the same document.
- **Window oracle.** An encrypted scratch Turso database stores separately compressed locator/context pages, keyed by first rank, with at most 256 entries and 64 KiB of decoded metadata. Each seek loads just the covering pages. All 200 returned raw rows must equal independently regenerated source bytes; both the marker's absolute byte position and the rendered message/ID must agree. A third, warm measurement starts at the raw-commit callback of a real backup on the same archive. `AH_BACKUP_RECORDS` controls that separate producer's size. The JSON field is `after_raw_commit`. Historical output calls it `during_backup`. The callback establishes launch order. The writer may finish before the timed read starts. Evidence reads take their locator binding from the published outline.
- **Array windows.** Set `AH_ARRAY_ONLY=1` on the target window command to measure a plain native Cline array at the same size and ranks. The timer starts with the selected locators in memory. It includes authenticated evidence access and interpretation. Every element, decoded start, ordinal and message is compared with separately generated content.
- **Rank oracle.** Pages restart at an absolute decoded byte position and carry length deltas, role, time delta and a synthetic native identifier. The lookup reads one compressed SQL page. A closed-form prefix sum verifies each selected offset independently of page boundaries; the role and ID also have to match. Boundary ranks and the short final page supplement the random ranks.
- **Window profile.** The first cold evidence read at each rank also reports outline lookup time, time through the first emitted row, decoded bytes consumed, and bytes replayed from the native frame start. Scan progress gaps include the interval through final digest verification and name the phase of the preceding callback. `FetchingSlice` counts chunks of stored input, `VerifyingSlice` counts inflation/hash work within a slice, and `Framing` counts decoded transport bytes. The two slice counters reset on each slice. Only authenticated bytes are passed to the native adapter.
- **Rendered-page experiment.** The window command builds a second table in the disposable encrypted read-model database. Each page contains at most 256 rendered records and 256 KiB of uncompressed JSON lines. Each record has its native ID, ordinal, role, time, kind, complete rendered text and typed part spans in UTF-8 bytes. Each timed sample loads the covering outline and rendered pages and constructs the 200 rows. Each cold path reopens after its own eviction. The independent oracle checks the full text and part ranges against the generated native source. Exact-byte checks still run on the evidence reader for every transport.
- **Storage and append.** The example checkpoints the outline-only database, then measures the increase in checkpointed database size with rendered pages. The normalization denominator is one decimal GB of decoded source. It also commits one additional native message to the rendered-page fixture and verifies the previous and new tail records. The append timer includes interpretation, tail-page lookup, decoding, encoding and the SQL commit. The submitted compressed bytes measure page rewrite amplification. The WAL length after commit is a file-size observation and cannot measure physical writes after a checkpoint.
- **Selective publication (2026-11-19).** A source with any native frame above 32 MiB decoded receives rendered pages in R. Plain and short-frame sources serve evidence. The command publishes a real conversation and reports a separate `production_window` distribution for the same ranks, exact full text, IDs, cache conditions and callback-triggered reads. The benchmark-only table is retained for comparison. The prototype measures a single publication per database. Retention, publication switching, concurrent appends, multipage oversized parts and lifecycle compatibility must be implemented if a representation is approved.

The [small-default JSON lines](validation/read-model-smoke.jsonl) were produced on arm64 macOS with Rust 1.96.0 and the dev profile. There are eight blob results, three full framing scans, nine window results and one rank result. Each smoke window reads 200 of 600 records from 1,200,000 decoded bytes. The rank smoke uses 1,025 entries. These smoke results exercise the commands. Use the target-size results for latency and storage decisions.

### Sparse windows, append publication and access plans

Run the two target measurements from `src-tauri` in a shared release target.

```sh
cargo test --release -p agent-history --lib read_model::publication::measure:: -- --ignored --test-threads=1 --nocapture
AH_MEASURE_ENCRYPTED=1 cargo test --release -p agent-history --lib append_and_sparse_windows_at_target -- --ignored --nocapture
cargo clean -p agent-history --release
```

The sparse-window fixture alternates a visible Codex message and a hidden record. It reads the final 200 visible messages on a 264,000,000-byte plain source and a 31,457,280-byte decoded single zstd frame. Each source contains 23,812 physical records. Each of the 40 disk-backed samples opens the archive after eviction and repeats the same read on that handle. Verification compares the complete generated text and physical ordinal after the timer stops.

The append measurement adds one 700-byte message to the plain source through backup. The scan timer includes reader framing and its page writes during delivery. The staging interval also includes legacy projection work. The backup timer runs through search synchronization and eligible reader collection. Inventories at the start, at `projection_staged`, and after return give physical page pieces, logical payload lengths and unique compressed blob storage in R.

The access-plan fixture retains 120,000 distinct Pi headers, each followed by 120 body records. The four-phase body uses distinct global event and call IDs and a tied timestamp range. Only the final record has the unique search marker. The fixture writes complete compressed documents to evidence in bounded batches. Session, version and head indexes are populated at that cardinality with tied timestamps. Two additional live Codex rollouts exercise native lineage and a parent with zero children. The fixture measures the actual bound SQL on Turso. The access-plan fixture omits the unqueried legacy event rows, search index and reader payload pages for the bulk population. It authenticates and scans the retained first, middle and last roots before exercising the production queries.

The [macOS release results](validation/reader-step3-reviewed-macos.jsonl) include both archive protection modes, the append phase timings and all five captured Turso plans.

### Two visible rows separated by 14,399,998 hidden records

From `src-tauri`, run the release fixtures serially in the shared target.

```sh
cargo test --locked --release -p agent-history --lib -- --ignored --test-threads=1 --nocapture long_hidden_gap_at_scale plans_on_many_roots
cargo clean -p agent-history --release
```

The hidden-gap fixture publishes a plain Claude JSONL revision of 14,400,000 physical records. Only the first and last contain visible messages. The public rank window must return physical ordinals 0 and 14,399,999 and their independently known texts. The test counts logical reader-page fetches on a separate traced read, then times 40 first reads after eviction and reopen, each followed by a warm read. The timer covers the public window call. The trace counts page lookups across all reader families, including the outline. It does not measure filesystem page faults.

The many-root fixture also checks the actual Turso plan of the child-list query for a seek by parent on `ah_reader_children`. Removing just that index still produces the correct empty result but fails the plan assertion. The [round-two release output](validation/reader-round2-macos.jsonl) contains the hidden-gap timings and the five bound query plans.
