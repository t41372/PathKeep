# Codex conversation storage: evidence and adapter requirements

Research date: 2026-11-11. Scope: local Codex CLI, Codex desktop, and their shared harness. This document describes observed formats and implementation requirements; it is not a claim that every capability below is already implemented or tested in PathKeep.

The primary source pin is `openai/codex@3a89580f08c985e99b9cc99df53c67fb8482ef93`. Source inspection was checked against a read-only inventory and schema inspection on the development Mac. No private transcript text, account IDs, workspace paths, attachment bytes, or session IDs are reproduced here. No harness was launched, no native state was changed, and no tests were run during this research.

## Findings that determine the design

1. **Rollouts are the durable conversation record, but they are no longer necessarily plain JSONL or self-contained.** Cold files use `.jsonl.zst`; current paginated rollouts can inherit a bounded prefix of another rollout. A scanner limited to `*.jsonl` misses most of the locally observed corpus.
2. **SQLite is an index and also contains metadata that JSONL cannot reconstruct completely.** The state database contains names, pinning, projects, sections, attachments, archive state, and the current rollout path. The history database contains derived turn/item projections. Back up a coherent database snapshot in addition to every rollout; do not discover conversations exclusively from database rows.
3. **Thread identity, root-session identity, rollout identity, source path, and project path are different fields.** Revert can keep the thread ID while creating a new immutable rollout ID. Forking may copy or reference earlier history. Changing the project directory does not itself change the conversation UUID.
4. **A transcript projection must distinguish mirrored representations from additional messages.** Raw `response_item` records, legacy `event_msg` messages, and paginated `event_msg.item_completed` records can describe the same interaction. Keep raw evidence and derive a separately versioned reading projection.
5. **Source completeness has limits.** Codex can omit ephemeral sessions, truncate persisted tool output, retain opaque encrypted content, or reference provider-owned media that is absent locally. A backup cannot recreate data never retained by the harness.

The upstream storage boundary explicitly treats rollout JSONL as durable replay data and SQLite as the queryable metadata index: [LocalThreadStore](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/thread-store/src/local/mod.rs). The additional metadata limitation follows from the inspected state schema and the [attachment adapter](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/thread-store/src/local/thread_attachments.rs).

### Local observations and their limits

The inspected Mac had more than 2,000 compressed active rollouts and about 300 plain rollouts; all 45 files in `archived_sessions` were compressed. The initial state DB inventory contained 2,301 threads, all marked `paginated`. Counts are a moving observation, not a reproducible acceptance fixture: the app and this research were active during inspection.

The installed CLI symlink identified version `0.167.1`; sampled desktop rollouts identified `0.167.0-alpha.3.2`. The Mac showed `state_5.sqlite` and `thread_history_1.sqlite`, each with WAL/SHM companions. Three recent plain rollouts contained multiple `session_meta` records. This corroborates the source warning that inherited metadata can occur later in a file.

The `threads` schema contained stable `id`, `rollout_path`, source and originator, cwd, creation/update/recency timestamps, archived state, model/provider, native title/name/preview, history mode, pin state, section/project IDs, creator fields, agent fields, and parent attachment fields. Separate tables included `projects`, `project_roots`, `thread_sections`, `thread_spawn_edges`, `thread_attachments`, and dynamic tools. The history DB had `thread_turns`, `thread_items`, `thread_realtime_items`, and `thread_history_projection_state` with rollout byte/ordinal positions.

This establishes macOS evidence only. Windows/Linux default resolution is source-backed, not a completed native E2E. No claim is made about all desktop releases, remote-only chats, or undeclared custom storage roots.

## Raw record format and identities

A modern decompressed line has an outer `timestamp`, optional `ordinal`, a string `type`, and `payload`. Preserve the exact source bytes; parsing into a JSON value and serializing again can change whitespace, number representation, unknown fields, or escaping. Store physical byte ranges in the decompressed stream separately from offsets into compressed bytes.

The first valid `session_meta` is canonical for the file. Later metadata can be copied parent history; it must not overwrite the conversation identity. Upstream deliberately uses the first metadata record and separately counts parse errors. Unknown future records should remain backed up even when their display projection is unsupported. See [canonical loading](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/rollout/src/recorder.rs#L1143) and [JSON decoder](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/rollout/src/lib.rs).

| Native field                                           | Meaning that must survive normalization                                             |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| `session_meta.id`                                      | Stable logical thread ID                                                            |
| `session_meta.session_id`                              | Root session ID; older records may omit it and upstream falls back to `id`          |
| Rollout ID                                             | Immutable physical history identity; usually thread ID, but can differ after revert |
| `forked_from_id`                                       | Logical fork relationship                                                           |
| `parent_thread_id`                                     | Parent relationship for spawned threads                                             |
| `source.subagent.thread_spawn.parent_thread_id`        | Older/nested source representation of spawn relationship                            |
| `history_base`                                         | Physical inherited prefix, not merely a UI parent                                   |
| `subagent_history_start_ordinal`                       | Boundary between inherited model context and the child's own projected history      |
| `forked_from_ordinal_exclusive`                        | Logical fork boundary, independent of later physical-history changes                |
| `attached_thread`                                      | Attached fork semantics                                                             |
| `cwd`, `runtime_workspace_roots`, `git`                | Project evidence; do not collapse them into UUID identity                           |
| `originator`, `source`, `thread_source`, `cli_version` | Provenance and compatibility evidence                                               |

The field meanings and backward-compatible `session_id` deserialization are defined in [protocol.rs](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/protocol/src/protocol.rs#L3463).

### CLI, IDE, desktop, and subagent attribution

`source` can be `cli`, `vscode`, `exec`, `mcp`, custom/internal, or a structured subagent value. It is not a desktop/CLI boolean. Observed desktop metadata used `originator = "Codex Desktop"` while `source = "vscode"`. Preserve the original pair and derive a confidence-qualified surface label. Missing originator or an unfamiliar source must remain unknown, rather than mislabeling it as CLI or VS Code. A child can retain desktop originator while its source describes a subagent.

The shared harness and frontend relationship is also documented by OpenAI in [Codex as a platform](https://developers.openai.com/blog/codex-as-a-platform). The exact source enum is in [protocol.rs](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/protocol/src/protocol.rs#L3185).

## Legacy and paginated reading projections

Legacy records commonly expose user/assistant messages through both `event_msg` and `response_item`. `response_item.message` content uses `input_text`, `output_text`, media, and other typed parts. Function/custom tool calls and outputs carry their own linking IDs. Reasoning summaries and encrypted reasoning payloads are distinct from ordinary assistant messages.

Paginated history persists `event_msg` with `payload.type = "item_completed"`; its nested `item.type` uses PascalCase variants such as `UserMessage`, `AgentMessage`, `CommandExecution`, `FunctionCallOutput`, `McpToolCall`, `FileChange`, `Plan`, `Reasoning`, or `ContextCompaction`. `thread_id`, `turn_id`, native item ID, and completion/start times support a turn/item projection. Raw model `response_item` records continue to exist, so merely appending both to one list duplicates interactions. The lower-case app-server wire schema must not be assumed to match this persisted enum. See [TurnItem](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/protocol/src/items.rs#L46), [completed event](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/protocol/src/protocol.rs#L2214), and [persistence policy](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/rollout/src/policy.rs).

Other currently persisted records include `compacted`, `turn_context`, `world_state`, `retained_context`, `token_usage_record`, `realtime_item`, security records, dynamic tools, and inter-agent communication. This vocabulary evolves quickly. A stable backup API should expose a small normalized model plus native-kind/provenance information and preserved unknown records, rather than exposing a closed copy of every upstream enum.

Model context and the historical transcript are separate views. A `compacted` record can contain replacement history, checkpoint metadata, and summaries. This must not erase earlier backed-up interactions or count replacement messages as new human activity. Preserve native compaction evidence and allow a future reading layer to explain it. See [history domain](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/history/src/lib.rs).

## Referenced history, forks, and revert

`history_base` is a triple: `thread_id`, `end_ordinal_exclusive`, `end_byte_offset`. Despite its name, `history_base.thread_id` is an immutable **rollout ID**, not necessarily the stable `session_meta.id`. The byte offset bounds the decompressed JSONL prefix. Source comments explicitly distinguish this after `thread/revert`.

The upstream resolver follows these edges, checks for cycles, resolves active and archived ancestors, validates boundaries, and returns ordered bounded segments. A child is not a complete transcript if its prefix ancestor is missing. Backup discovery should preserve all eligible rollouts, including unindexed/older generations; backup validation should report unresolved/cyclic/out-of-bounds lineage. A first implementation that preserves but does not materialize lineage must advertise that limitation rather than exporting the child suffix as a complete conversation. See [rollout_lineage.rs](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/thread-store/src/local/rollout_lineage.rs), [paginated fork](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/thread-store/src/local/paginated_fork.rs), and [revert](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/thread-store/src/local/revert_thread.rs).

Legacy-to-paginated migration can rewrite the file; it is not an eternal append-only promise. Upstream migration has a staged publish/recovery journal and SQLite recovery. Source replacement, truncation, equal-length rewrite, compression, and file movement therefore need capture generations and revalidation, not only a last-read byte offset. See [rollout migration](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/thread-store/src/local/rollout_migration.rs).

## Live consistency and incremental backup

The recorder serializes each JSON record, adds a newline, writes it, and flushes. Capture can still encounter an unfinished trailing line, source replacement, or a representation transition. Retain raw bytes with an explicit incomplete-tail diagnostic; do not let one tail fragment hide all complete earlier records or silently count it as parsed.

Cold compression uses a temporary output, validates decompression, synchronizes output, rechecks source state under coordination, publishes the compressed representation, and removes the plain source. Resume can materialize compressed content back to plain JSONL. A source may disappear between enumeration and open, and both variants may temporarily exist. Upstream readers retry resolution; `.jsonl` and `.jsonl.zst` are representation variants, not two independent conversations. The raw archive should preserve captured original representation bytes and record decoded identity separately. See [compression.rs](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/rollout/src/compression.rs).

Recommended capture boundary:

- Enumerate both active and archived trees and both encodings; retain per-path enumeration failures.
- Read a pinned source handle with an explicit original-length bound. Verify object identity and source/captured bytes before committing a generation; retry observable concurrent changes within a bounded policy.
- Do not claim an atomic filesystem snapshot from size/mtime checks alone. Same-size edits can preserve those values. Capture evidence must describe the actual guarantee.
- Decode compressed files as streams with bounded resources. A truncated/checksum-invalid compressed stream means parsing is incomplete even if its prefix yields valid JSON.
- Use a read-only SQLite connection and online backup API for a coherent DB snapshot. Sequentially copying the live DB, WAL and SHM is not equivalent.
- Treat the collection of rollouts, metadata DB and projection DB as separately captured objects with timestamps and validation. Without harness coordination or a filesystem snapshot, a single global point-in-time snapshot across these stores is not established.
- Preserve deleted/renamed source generations already captured. Source absence is an observation, not an instruction to delete the archive.

The snapshot guarantee distinction is independently stated in [CASS's source-budget snapshot guard](https://github.com/Dicklesworthstone/coding_agent_session_search/blob/c9c94511ace206037ae33200e9649ead52a69b8c/src/connectors/codex/source_budget/snapshot.rs); the coherent database pattern is implemented in [codex-rehome backup.rs](https://github.com/CalebYcj/codex-rehome/blob/485e72da26dfd0c511a3e2463794072117de7fd1/desktop/src-tauri/src/core/backup.rs#L870).

## Attachments and completeness

Native message parts can contain inline data URLs, external `file_id`, remote URLs, or local paths. `UserInput::LocalImage` and `LocalAudio` explicitly carry local paths; input media can later be converted to inline data or a provider file reference. Preserve the original reference and separately record whether bytes were captured, were missing, lay outside approved source roots, or existed only remotely. Do not issue network requests during a local backup merely because a transcript contains a URL. See [user input](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/protocol/src/user_input.rs), [media references](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/protocol/src/models.rs#L909), and [attachment-store contract](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/attachment-store/src/lib.rs).

The native `thread_attachments` table is not a media-file catalog. Locally observed attachment types were `pull_request`, `worktree`, and `archived_worktree`; their payloads held linking metadata. Preserve those as metadata and do not recursively copy a whole referenced worktree as a chat attachment.

Generated images can live beneath `<save-root>/generated_images/<session>/<call>.png|gif`; the save root is supplied by the hosting environment and is not universally Codex home. Preserve explicit local references and capture eligible native asset roots. See [image artifact naming](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/ext/image-generation/src/artifact.rs).

Current `ImageViewItem.path` uses a canonical `file:` URI rather than a native path string. The URI implementation distinguishes POSIX, Windows drive and UNC syntax, preserves percent-encoded bytes, and has an opaque fallback namespace `file:///%00/bad/path/<base64>`. A reference resolver must not turn a foreign `file:///C:/...` into a local POSIX path or decode arbitrary URI strings as filesystem authority. Preserve the native URI, resolve only supported same-host forms under approved roots, and report the rest. See [PathUri serialization and conversion](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/utils/path-uri/src/lib.rs).

Paginated command output and MCP results are truncated for persistence at 64 KiB in the inspected policy. Some transient events are not persisted at all. Encrypted reasoning and encrypted inter-agent content must remain opaque bytes; PathKeep cannot label an empty readable text projection as an empty native record. Ephemeral sessions and remote-only content may have no local rollout. These are source limitations, separate from parse failures.

## Search, analytics, and export implications

Search should index selected normalized readable fields while retaining raw-record lookup. Keep source/harness identity, project evidence, native creation time, last message time, source mtime and capture time separate. Stable pagination requires a deterministic tie-breaker; file order alone is not a global activity order.

Usage numbers need provenance and semantics. `token_count` may contain cumulative and last-response values; copied fork history and compaction can repeat them. `token_usage_record` adds response/session/thread/turn IDs and usage levels. Do not sum every numeric field or infer billing from these counters. The inspected ccusage implementation has dedicated fork-prefix replay and compaction deduplication, which is evidence that naive aggregation is wrong. Preserve reported metrics first, with a versioned derivation and explicit incomplete/unknown state for later analytics.

Offer distinct export purposes: original captured files for preservation, a structured normalized export with native provenance, and readable text/Markdown/HTML for people. The readable rendering is inherently selective; it must not replace canonical raw backup or claim to be a native-restorable Codex home. Resolve export links against archived media, escape HTML, and never execute transcript content.

## Resume and project migration: research only

The native CLI supports `codex resume <UUID-or-name>`, `--last`, `--all` to disable cwd filtering, and `--include-non-interactive`. Exact UUID selection is more reliable than names and picker state. The command surface also exposes workspace overrides through shared CLI options. A future action should produce structured executable/argument/environment data, not concatenate untrusted paths into a shell command. Check executable availability and native session availability; a backed-up-only conversation is not automatically resumable. See [CLI resume definition](https://github.com/openai/codex/blob/3a89580f08c985e99b9cc99df53c67fb8482ef93/codex-rs/cli/src/main.rs#L365).

Project paths are metadata, not the full native identity. A moved directory can disappear from a cwd-filtered picker while the UUID still exists. PathKeep can group historical paths under its own project identity without rewriting Codex. A native migration would need to consider `session_meta.cwd`, turn contexts, DB metadata, project roots, worktree attachments, references to local assets, and current rollout paths. Broad textual replacement is unsafe because the same pathname may appear as quoted historical content.

Codex app-server provides thread operations, but starting it for backup can invoke migrations/background maintenance and is not a read-only file inspection. Desktop deep links and account/remote filtering are not established as a universal launch contract here. This task deliberately does not launch, migrate, restore, reindex, or rewrite native sessions.

## Failure scenarios to encode before implementation

These are requirements for the implementation's prewritten test plan; listing them here is not evidence that tests ran.

1. Plain and compressed active/archived files; a compressed-only corpus; both variants temporarily present; disappearance during compression/resume; corrupt/truncated compressed data.
2. Interrupted final JSON record, malformed middle record, unknown type, excessive record size, invalid UTF-8, and unknown future history mode. Preserve bytes and report projection completeness separately.
3. Canonical first metadata followed by a different inherited metadata record; missing legacy `session_id`; conflicting UUIDs across independently configured source roots.
4. Referenced fork prefix, same logical ID with a different rollout ID after revert, missing ancestor, cyclic lineage, out-of-range byte/ordinal boundary, and subagent inherited-context boundary.
5. File append, truncate, same-length rewrite, atomic replacement with preserved mtime, archive move without mtime change, and legacy-to-paginated rewrite between captures.
6. Live SQLite WAL content, unavailable or stale DB index, configured separate SQLite home, metadata without a rollout, valid rollouts without DB rows, and SQLite schema drift. Source files remain unchanged.
7. Mirrored user/assistant representations, paginated PascalCase items, tool-call correlation, opaque encrypted records, compaction replacement history, and copied fork token counters.
8. Inline media, explicit local image/audio, file-ID-only media, missing/deleted asset, symlink escape, attachment changing during copy, and a worktree attachment that must not become recursive workspace capture.
9. Filesystem enumeration denied for one subtree while others succeed; partial result must retain failure evidence. Old retained generations remain usable after source deletion.
10. Portable raw export and normalized export must be generated exclusively from captured state, with repeatable hashes and a machine-readable verification artifact. Test source independence by removing the isolated source after capture.

## Maintenance boundaries

Watch upstream `rollout`, `history`, `thread-store`, `protocol`, `state`, `attachment-store`, and image artifact changes. Revalidate against a pinned commit and real local samples whenever supporting a new harness version. A stored parser version and source format/capability report should make reindexing possible without reacquiring source data.

Unresolved boundaries are remote-only threads and provider media, universal desktop launch/deep-link behavior, future schemas, non-macOS real execution, and exact global consistency across independently written native stores. Keep these visible in the capability matrix and handoff notes. No native migration, resume execution, account access, or cloud fetch is authorized by a conversation backup itself.

## Initial implementation notes

The adapter lives in `src-tauri/crates/agent-history/src/adapters/codex.rs`. `tests/codex_adapter.rs` and its synthetic paginated fixture were written before the implementation; final execution belongs to the whole-library verification phase. The fixture follows the pinned native schemas, including the mixed casing of `UserMessage` input `text` and `AgentMessage` content `Text`. It contains no copied personal conversations.

Discovery is an allowlist under an explicitly supplied Codex home: active/archived JSONL and Zstandard JSONL, native attachment/generated-image directories, input/name indexes, and versioned state/history SQLite databases. It does not read auth, config, logs, or arbitrary workspace files. A separate `sqlite_home` must be provided as an additional source root by the caller; the adapter does not interpret every Codex configuration layer or mutate process environment variables. Compression decoding and coherent SQLite capture are responsibilities of the shared transport/capture layer.

Parsing emits every valid native object with the complete outer record in `NativeEvent.payload`. Searchable text and role/kind facts are selective derivations. It deliberately exposes native event records, including mirrored records; callers must not call their count a count of distinct user messages or chargeable model interactions. Native metadata, unknown records, source ordinals, parent links and inline bytes remain available for future projection improvements.

The first valid metadata record sets the logical session; later inherited metadata cannot rename it or change its origin/project. Current item-completed events, legacy messages, tool calls/results and readable reasoning summaries have text extraction. Explicit local image/audio and native image-view/generated-image paths become untrusted attachment references. Remote media IDs/URLs produce `codex-remote-attachment-unavailable`; there is no network resolution. Referenced inherited history produces `codex-lineage-unresolved` and a partial parse report, even though all discovered raw files remain capture candidates. These diagnostics distinguish preservation from a fully reconstructed transcript.

Deferred references are bounded by the shared helper. The adapter never reads an attachment itself, never follows a source directory symlink, and never merges raw files by thread ID. Raw event preservation does not establish native restore, lineage materialization, full native UI metadata projection, or pricing analytics; those remain separately documented integration work.
