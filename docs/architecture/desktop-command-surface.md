# Desktop Command Surface

> 這是 M0 凍結的 Tauri command surface 草案。正式 IPC facade 仍可暫留單檔，但命名與 envelope 之後要向這裡收斂。
>
> 2026-10：草案裡的 dashboard、explorer、audit 是舊前端的畫面。現在註冊的命令全在 `src-tauri/src/lib.rs`（`generate_handler!`），畫面呼叫的每一個都經過 `src/lib/backend-client/` 的 typed client；這次 redesign 改了什麼見下方「2026-10 redesign backend」。

本草案與 [module-boundary-map.md](module-boundary-map.md) 的 command sections 同步維護；若兩者出現衝突，以本文件的 API 分類為準。

---

## Interface Types

1. Read model
   - 回傳給 onboarding、dashboard、explorer、audit、settings 的純讀取資料
2. Preview / manual / execute
   - 高風險操作一律先產生 preview artifact，再進 execute
3. Long-running job trigger
   - 啟動 backup / import / doctor / future reindex，回傳 `run_id`
4. Artifact fetch
   - 用 `run_id` 或 artifact id 拉 manifest、snapshot metadata、preview bundle
5. Session guard
   - 提供 app lock 狀態、鎖定 / 解鎖與 lock-aware refusal path

## Open at login 與選單列圖示（2026-10）

三個命令，Tauri 與 dev bridge 都有註冊，回傳值都是呼叫後 OS 實際的狀態：

| 命令                      | 參數                   | 回傳                 |
| ------------------------- | ---------------------- | -------------------- |
| `get_desktop_integration` | —                      | `DesktopIntegration` |
| `set_launch_at_login`     | `{ enabled: boolean }` | `DesktopIntegration` |
| `set_menu_bar_icon`       | `{ enabled: boolean }` | `DesktopIntegration` |

`DesktopIntegration = { launchAtLogin, menuBarIcon, launchAtLoginSupported, menuBarIconSupported }`。

- `launchAtLogin` 讀 OS 的登入項目，不存在 config。macOS 用 PathKeep 自己的 LaunchAgent（`vault_platform::login_item`，經 `/usr/bin/open` 啟動，避開 macOS 26 的 Launch Constraint kill）；Windows / Linux 用 `tauri-plugin-autostart`。webview 不再有 `autostart:*` capability，只能走這三個命令。
- `menuBarIcon` 是「圖示現在在不在」；偏好存 `AppConfig.menuBarIcon`。`set_menu_bar_icon` 先改圖示再存 config，存失敗就把圖示改回去並回錯。`save_config` 存完也會讓圖示與選單語言跟上 config。
- `menuBarIconSupported`：macOS / Windows 恆為 true；Linux 需要能載入 libappindicator，且 session bus 上有 `org.kde.StatusNotifierWatcher`（問不到時不擋）。不支援時 `set_menu_bar_icon(true)` 回錯。
- 事件：`pathkeep://open-command-palette`（選單「搜尋歷史…」，無 payload）；`pathkeep://backup-finished`（任何 app 內備份結束，`{ source: "app" | "menu-bar", report?, error? }`）。`run_backup_now` 與選單的「立即備份」走同一條 `desktop_integration::run_backup`，`pathkeep://backup-progress` 不變。dev bridge 的 `run_backup_now` 在 app 已啟動時也走這條路徑。
- 登入啟動帶 `--launched-at-login`。主視窗在 `tauri.conf.json` 設為 `visible: false`，由 setup 決定：一般啟動顯示；登入啟動時保持隱藏（圖示開著，或 macOS 有 Dock 可叫回），Windows / Linux 沒圖示時以最小化開啟。圖示開著時關視窗只是隱藏；圖示關著時關視窗就是結束，有工作在跑時先問（見下節）。細節與理由見 `docs/features/archive.md` §2「開機啟動與選單列圖示」。

## 結束時還有工作在跑（2026-10 / `WORK-QUIT-DURING-WORK`）

有人等著的工作在跑時要結束 PathKeep，先問再結束（`src-tauri/src/desktop_integration/quit.rs`）。起因：2026-10-16 有人在 move.spec 途中按了測試視窗的關閉鈕，35 ms 後程序結束，跑了 40 秒的 `export_app_data` 白做，畫面只說連不上 desktop bridge。

- **哪些工作算**：`vault_worker::foreground_work()`，一份只讀記憶體的登記表（`vault-worker/src/foreground_work.rs`）。手動備份（視窗與選單列的「立即備份」）、匯出歷史、匯入 Takeout / 瀏覽器檔案、搬到另一台電腦的匯出與匯入、從安全快照還原、釋放空間、升級存檔、更改存檔密碼、開關加密、刪除所有資料，以及開存檔時跑的 schema 更新（2026-11-15 `WORK-SCHEMA-UPDATE-QUIT`）。登記在 vault-worker 的入口與 `maintenance_jobs::run`，所以 Tauri 命令、dev bridge 與 owner endpoint 都看到同一份。schema 更新在 vault-core 開檔時跑，比 vault-worker 低一層，所以由 vault-core 自己記（`vault_core::schema_update_running`），`foreground_work()` 讀它，排在最後：vault-store 開檔時，真的要改一個已有的資料庫之前通知一次（`MigrationRegistry::on_update`；新建的、已是最新的都不通知），vault-core 從那一刻算到這次開檔結束，成功、失敗或 panic 都一樣。排程備份不算（下次檢查會再跑）；背景佇列（建索引、洞察、連結預覽）也不算，重開後自己續跑，結束照常。
- **攔在哪**：選單列圖示關著時按視窗的關閉鈕，攔在 `CloseRequested`（視窗還在，就地問；圖示開著時關視窗只是隱藏，不問）。其餘都經 `AppHandle::exit` 到 `RunEvent::ExitRequested`：選單列圖示的「結束 PathKeep」、macOS 的 ⌘Q、問題的回答本身。Tauri 預設選單的 Quit 走 AppKit 的 `terminate:`，app 攔不到，所以 macOS 的 app 選單換成同一份預設選單、只把 Quit 換成 PathKeep 自己的項目（`app_menu.rs`；文字跟著 app 的語言，取自 `copy.rs`，設定換語言時重建。AutoFill、聽寫、視窗排列這些 macOS 自己加進去的項目跟著系統語言）。更新後重開（`RESTART_EXIT_CODE`）不攔。判斷在主執行緒上做，只讀記憶體，不碰選單狀態的鎖。
- **事件與命令**：`pathkeep://quit-request`，payload 是 `QuitRequest = { id, work: ForegroundWork[], waiting }`，或 `null`（沒有問題了）；`work` 依開始順序、每種一次，做完會變空陣列。dev bridge 的 `/events` 也轉發。視窗晚開或重新載入時用 `get_quit_request` 讀。`answer_quit_request({ id, answer: "wait" | "quit-now" | "keep-open" })` 回傳回答後的 `QuitRequest | null`；`id` 不是目前的問題時什麼都不做，因為可能有兩個視窗都在問（E2E 的 Tauri 視窗與 Chromium）。
- **之後的行為**：選「做完再結束」，工作清單一空就結束。改密碼與開關加密把鑰匙圈和「把密碼存到鑰匙圈」設定一起算在工作裡（`RekeyRequest.rememberInKeychain`，worker 在同一個 hold 裡寫），不是視窗事後再補，所以「做完再結束」不會把鑰匙圈留在上一步。新存檔裝上時帶的是原本的設定，鑰匙圈存好（或清掉）了才改設定；鑰匙圈寫不進去時，改動照樣算完成、設定維持原樣，下次開啟不會去等一把鑰匙圈裡沒有的鑰匙。存檔換好之後的步驟（鑰匙圈、設定、稽核紀錄）都不再讓命令失敗，免得視窗說「存檔沒有改動」；`rekey_archive` 回傳 `RekeyOutcome = { snapshot, keychainFailed }`，視窗照 `keychainFailed` 提醒，不從快照的鑰匙圈狀態去猜（舊鑰匙還在時猜不出來）；改寫途中 App Lock 鎖上時讀不到快照，`snapshot` 是 `null`，解鎖時視窗再讀。鑰匙圈拒絕刪除鑰匙也算沒更新（以前原生的刪除錯誤被吞掉）。還原、升級、搬移匯入沒人要求改鑰匙圈：照存檔原本的設定存鑰匙，設定說不記住時只清掉狀態看得到的鑰匙；鑰匙圈不肯存、讀不到或清不掉就不動，只記 log，不讓已經裝好的存檔變成失敗（說失敗，使用者會在裝好的存檔上再還原一次）。鑰匙圈不肯存新鑰匙時會留著原本那一項，可能是被換掉的存檔的鑰匙，什麼都打不開，首頁卻以為鑰匙還在；所以存不進去時，鑰匙圈裡那一項不是這個存檔的鑰匙（也不是打得開它的舊版密碼）就刪掉（`store_data_key_in_keyring`，每個存鑰匙的地方都走它）。這時首頁會提醒「設定要記住密碼，鑰匙圈裡卻沒有」，下次開啟問密碼。用密碼開存檔時鑰匙圈不肯存，也是同樣處理，存檔照樣打開，下次再問密碼。沒回答時工作做完了，問題改說都做完了，仍由使用者選：不會自己結束，也不會自己消失。問題開著時再結束一次：還有工作在跑，視窗回到前面、問題再送一次；已經沒有工作在跑（問題說的就是這個），就照第二次的要求結束。沒有視窗（`--background` 啟動）時會開出視窗來問。
- **「現在結束」**跟以前的結束一樣，程序直接結束，不先取消工作：匯出先寫暫存檔再換名，不會留下半個檔案；匯入已存進去的批次保留，再匯入同一個檔案可以做完；存檔變更由下次開啟時各自的恢復流程收拾；刪除所有資料在下次開啟時做完（`finish_interrupted_data_wipe`）。
- **攔不到的**：macOS Dock 選單的「結束」、登出與關機也走 `terminate:`，tao 0.35 沒有 `applicationShouldTerminate:` 讓 app 回答，程序立刻結束，跟以前一樣。所以 PathKeep 不會擋住登出或關機；工作會中斷，檔案不會寫壞（同上）。Windows、Linux 的登出與關機沒有驗證過。
- **測試**：debug build 的 dev bridge 有 `debug_request_quit({ via: "window" | "app" })`，關閉主視窗或呼叫 `AppHandle::exit(0)`，走的就是關閉鈕與 ⌘Q 的處理。E2E：`tests/e2e/quit-during-work.spec.ts`（`restart` project）；schema 更新是 `tests/e2e/schema-update-quit.spec.ts`，在 backup-integrity 設定的 v1 存檔上跑，排在 backup-integrity.spec 前面。fixture 的更新不到一秒就做完，所以 debug build 的 `PATHKEEP_TEST_HOLD_SCHEMA_UPDATE` 在更新改第一個資料庫之前停住，等它指的檔案被刪掉，並把程序 id 寫到旁邊的 `.held`（`vault-core/src/test_support.rs`）。真的 ⌘Q、關閉鈕與三語選單是手動驗的（2026-10-30）：沒打包的 debug binary 沒有 bundle id，自動化工具只指得到已安裝的 PathKeep，所以把 debug 的 `pathkeep-desktop` 與 `pathkeep-worker` 放進另一個 bundle id 的 `.app`，用 `bun run dev:demo -- --backend <app>/Contents/MacOS/pathkeep-desktop` 跑；示範資料要加大（例如 `perDay: 1200`，約 46 萬筆），匯出才跑得夠久來回答問題。

## Debug 平台沙盒（2026-10）

### Built-in model download events

`download_static_embedding_model` starts or joins a transfer and returns its `transferId`. Subscribe to `pathkeep://model-download-progress` before invoking the command and match events to that ID. The window and the dev bridge's `/events` stream deliver the same JSON. Each transfer emits exactly one terminal event.

The start request is `{}` and the reply is `{"transferId":"0123456789abcdef0123456789abcdef","seq":7}`. Cancel takes `{"transferId":"0123456789abcdef0123456789abcdef"}` and returns a Boolean. Only the first accepted cancellation returns `true`. Deciding to publish, reuse a verified selection, or report a final failure closes cancellation and attachment. A subsequent start receives its own ID and waits for the predecessor to release its response and candidate.

The owner assigns a strictly increasing JSON-safe integer `seq` to each new transfer across its archives, starting at 1. Joining a transfer returns its existing ID and sequence. Every event for that transfer carries the same pair. A window follows the highest sequence it has seen and can ignore a delayed event from an older transfer. The sequence starts over when the owner process restarts.

Each event below is a separate payload on the same channel.

```jsonl
{"kind":"waiting","transferId":"0123456789abcdef0123456789abcdef","seq":7,"reason":"archive-busy"}
{"kind":"waiting","transferId":"0123456789abcdef0123456789abcdef","seq":7,"reason":"previous-transfer"}
{"kind":"fileStarted","transferId":"0123456789abcdef0123456789abcdef","seq":7,"file":"model.safetensors","totalBytes":1049688}
{"kind":"fileProgress","transferId":"0123456789abcdef0123456789abcdef","seq":7,"file":"model.safetensors","downloadedBytes":1048576,"totalBytes":1049688}
{"kind":"fileFinished","transferId":"0123456789abcdef0123456789abcdef","seq":7,"file":"model.safetensors"}
{"kind":"done","transferId":"0123456789abcdef0123456789abcdef","seq":7}
{"kind":"error","transferId":"0123456789abcdef0123456789abcdef","seq":7,"message":"disk full"}
{"kind":"cancelled","transferId":"0123456789abcdef0123456789abcdef","seq":7}
```

`waiting` is emitted immediately on contention and every 20 seconds while that wait continues. `archive-busy` means another archive operation holds the gate. `previous-transfer` means an earlier transfer still owns its response or files. Both are signs of life for the matching ID. Before start admission there is no transfer ID to report. `totalBytes` is zero for unknown content length. Only `error` carries a diagnostic to display. The worker allows 15 seconds to connect and 30 seconds for response headers or each body read. There is no whole-file deadline. A stalled request releases its response and candidate, and an accepted cancellation still ends with `cancelled`.

`get_model_download_state` takes `{}` and reads the owner process's registry for the current archive's built-in model. It returns `null` when no transfer is registered. For a running transfer, the native command and dev bridge return the same snapshot:

```json
{
  "transferId": "0123456789abcdef0123456789abcdef",
  "seq": 7,
  "phase": "downloading",
  "currentFile": "model.safetensors",
  "downloadedBytes": 1048618,
  "totalBytes": 1049730,
  "files": {
    "config.json": { "downloadedBytes": 42, "totalBytes": 42 },
    "model.safetensors": { "downloadedBytes": 1048576, "totalBytes": 1049688 }
  }
}
```

The `downloading` phase includes file verification. During a wait, `phase` is `"waiting"` and `reason` is `"archive-busy"` or `"previous-transfer"`. Counts retain the last reported values. `currentFile` is `null` between files. Totals sum the files announced so far, and an unknown file length contributes zero to `totalBytes`. A replacement has its own ID and starts at zero. Terminal outcomes arrive on the event channel. On mount, subscribe before reading state. Seed the file map from the snapshot and keep events received during the lookup so a late reply cannot revive a transfer that already ended.

After a matching `done`, built-in setup submits this `build_ai_index` command payload:

```json
{
  "request": {
    "providerId": "static-in-app",
    "transferId": "0123456789abcdef0123456789abcdef",
    "fullRebuild": false,
    "clearOnly": false,
    "scope": "incremental"
  }
}
```

The response is the usual `AiIndexReport` with `jobId`. Both transports share the owner's completion record. Only a successful transfer for this archive can authorize this form of the request. The saved selection is checked again at enqueue. A repeated request returns the first job ID even after completion. Ordinary builds omit `transferId`. Wipe clears the archive's records and process exit clears all records.

### Settings save durability

`save_config` returns the applied snapshot. On Unix, if the rename installed the settings but the parent directory flush failed, the response also contains `configDurabilityWarning` (a diagnostic string). Use the returned settings, including the effect on download consent, and show the durability warning separately. The menu-bar icon setting is saved without an open screen, so its durability warning is written to the log. A normal save omits the field. A failure before the rename rejects the command. In a debug desktop, `const clear = injectFault('config-save-parent-sync')` exercises the warning after the live config rename, at the parent-directory sync. Call `clear()` after the save; the marker applies to every live config save while present. Release builds compile out this checkpoint.

## 單一資料庫擁有者（Turso 遷移 §2）

App 在任何資料庫工作前持有 `archive/.pk-owner.lock`，並提供同一使用者才能連線的本機 endpoint。
排程、worker CLI 與 MCP stdio 都透過它執行；未啟動時會以 `--background` 啟動 app。

### Backup outcomes

`run_backup_now` and `run_snapshot_restore` return a `BackupReport` in Tauri and the devtools
bridge. A backup that ran returns `Ok(report)` with `run.status` `success` (every selected
profile complete) or `partial` (some profile could not be read; what could be read is saved).
`Err(CommandError)` means the backup itself failed (archive, disk, lock); its `message` is the
original chain, as for other commands, and `backup-no-profiles` (nothing selected or found) is
a classified code. Every selected profile appears in `profiles` with an `outcome`, also kept in
the run's `stats_json.profiles`:

```ts
type ProfileOutcome =
  | { status: 'complete' }
  | { status: 'unavailable'; code: string } // could not be found or opened
  | { status: 'failed'; code: string } // opened, could not be read to the end
```

| Code                            | Meaning                                                               |
| ------------------------------- | --------------------------------------------------------------------- |
| `source-profile-not-discovered` | A selected profile is no longer on this computer                      |
| `source-unreadable`             | Its history file is missing or cannot be read                         |
| `source-permission-denied`      | The OS refused access (macOS: Full Disk Access)                       |
| `source-read-failed`            | The staged file or its schema could not be read                       |
| `source-stream-failed`          | Reading stopped part way; what was read before is saved               |
| `source-favicons-unavailable`   | Icons could not be read; history is saved (a warning, not an outcome) |
| `source-visits-without-page`    | Note: rows whose page row is gone, counted; the run stays `success`   |
| `source-ids-reset`              | Note: the browser numbered its rows again; every row was read         |

Each non-complete outcome is also a warning with the same code and `profileId`, translated in
all three languages; the frontend reads codes, never English text (Safari's Full Disk Access
guidance reads the outcome). Scheduled attempts record a partial run as `partial` with reason
`backup-incomplete`, and tell `write-lock` and `disk-full` failures apart. Request fields and
command names are unchanged.

Each private frame has `streamId,sequence,type,payload`, beginning at sequence
`"0"`. Progress uses `phase:"discovery",unit:"entries",done`. A `root` frame
contains one inventory row. `finished` encloses the complete report in the
fixture. `cancelled` or `error` ends the stream with `{code}`. A stalled preview or unused ticket expires after five minutes. The owner keeps
at most 32 live streams and 32 tickets, evicting the oldest ticket at capacity.
Dropping the private reader cancels production. Counts, bytes and sequence numbers are
decimal strings except for the bounded number of roots per tool. Dates are
UTC epoch milliseconds. Earliest/latest are null when no filesystem
modification time was observed.

A root reports `known-layout` for Claude's recognized positions,
`file-candidates` for the other tools, or `unavailable` for an inaccessible
root. Native discovery supplies the same file stream to the inventory and the
capture producer. Top-level candidates, recognizable child files, ambiguous
candidates and ancillary files sum to `files`; `sourceBytes` measures those files.
`unknownFiles` counts unrecognized names skipped inside native transcript trees.
Directory counts exclude the selected root. A row can be readable with a
reason if a descendant was inaccessible. Totals then cover observed metadata.
The estimate applies measured growth ratios for evidence, the read model and the search index to ordinary and native-compressed input bytes in the chosen archive mode. Free bytes come from the volume containing the
conversation evidence database, or its nearest existing ancestor during setup.

After a committed policy edit, `pathkeep://data-kinds-changed` carries
`{policyToken,changedKinds}`. A no-op produces no event. Content and paths
travel on the private request stream. A mismatched policy token returns
`policy-changed`; a last-on transition returns `last-active-kind`.
Other domain refusals include `invalid-request`, `lock-required`,
`enable-preview-required`, `scope-denied`, `source-selection-empty`,
`root-changed`, `preview-expired`, `archive-replaced`, `archive-busy`,
`archive-uninitialized`, `destination-unavailable`, and `cancelled`.
Existing archive admission and key errors keep their codes. A missing source
reports `root-missing`; denial or an unreadable entry reports
`root-unreadable`. The scan depth limit reports `source-depth-limit`.

An unavailable conversation store leaves the browsing row readable.
`availability` is `available`, `not-initialized`, or `unavailable`.
An unavailable row has null `hasSavedData`, absent `archiveCount` and
`firstBackup`, and unavailable coverage. Role-local damage also carries
`failure:{role,stage,reason}` from the open owner. Roles are `evidence`,
`read-model`, or `shared`. Stages are `preflight,open,key-check,migrate,recover`.
Reasons are `archive-store-missing,wrong-key,integrity-failed,schema-too-new,archive-busy,kind-unavailable`.

can exceed JavaScript precision are decimal strings. Times are UTC epoch
milliseconds. During streaming discovery a committed prefix may already be
readable. The progress denominator is null. A new child, a newly identified
top-level conversation and a revised conversation are distinct units.

The owner emits `pathkeep://data-kinds-changed` on policy publication,
`pathkeep://agent-settings-changed` for active source settings,
`pathkeep://kind-backup-progress` for coalesced progress,
`pathkeep://background-task-changed` for task state,
`pathkeep://kind-backup-finished` at completion and
`pathkeep://agent-catalog-changed` for overview invalidation. Refetch after
unlock, reconnect or an event gap. The terminal run and attention are durable.

Conversation runs report save failures in `warningCount` and `warnings`. Retained format
limitations and transient changes appear in `noteCount`, `newNoteCount` and the paged
`notes` on run detail. A source row groups its most recent notes by code. Counts are decimal
strings. Reports predating note accounting omit the counts. A successful task may have
`attention: true` and `formatNotices` containing the first newly encountered tool/version
pairs. Use `control_background_task` with `action:"dismiss-notice"` and `notice:{"tool":"pi","version":"1000"}` to dismiss one pair. On an Agent task, `dismiss` acknowledges a save failure. The finish event includes both
note counts and the list of newly raised format notices.
The legacy browsing backup command and its progress and report remain the
browsing screen's entry point.

A desktop conversation run detail includes `task` with its current actions and comparison token, including after the local day changes. Native runs without desktop receipts omit it. If a read overlaps a first-save claim, the task can briefly report `state:"queued"`, `phase:"queued"` and no actions. Its run result is `running`. A terminal publication that failed while storage was unavailable is reconciled on service access, with reason `terminal-publication-failed`. Source edits may include an already-selected logical root ID in the submitted preview. A bound preview row and a saved source row expose an opaque `directoryToken`. Offer a renewed grant when the same `rootId` has a different token. Unbound and tool-only rows omit it. Send the union of old and reviewed IDs once each. The reviewed directory replaces its earlier binding. An on device with a missing descriptor can use the ordinary enable dialog to repair it.

Overview and source-list requests share aggregates from committed evidence. Backup overview omits physical size by default. Fetch it after first content with `list_data_kinds` and `includeArchiveBytes:true`, or explicitly request `get_agent_overview` with `includeArchiveBytes:true`.

The active grant appears as `policy.selectionRef` in `get_agent_settings`.
`list_data_kinds` includes `activeTaskId` for an active conversation backup.
`archiveBytes` measures the two native conversation databases, their usage
companions and the owned conversation search index. `retainedBytes:null`
in a run means the physical storage newly attributable to that attempt was
not measured. `filesAbsent` counts previously observed source files confirmed missing during a completed directory walk. A missing or unreadable directory cannot increase it. A committed transcript without a known current identity contributes
to `unclassified`; it does not increase the conversation count by being a file.

### Info panel and errors

`own` counts this conversation’s original work, including abandoned work. `total` adds descendant usage and tool contributions. `currentLineTokens` belongs to the selected line; `subagentTokens` is the known child subtotal. `usageCoverage:{known,conversations}` counts conversations with a usage reading. A token object has `input,cacheWrite,cacheRead,output`. Reasoning tokens are already part of output. `recordedUsd,estimatedUsd,unpricedResponses` distinguish native charges, standard-price estimates for other measured responses and missing prices. Both cost switches default on. With estimates disabled, estimate fields and the table version are omitted. With costs hidden, recorded amounts are omitted too.

Fact counts include `calls,failedCalls,addedLines,removedLines,editedFileCount,unknownEditCounts,compactions,apiErrors,usageResponses`. `ownershipPartial` marks unresolved original ownership. Duration coverage is `recordedTurns,derivedTurns,unknownDurationTurns`; `timeSource` can also be `mixed`. `models` lists model IDs and known attributed output tokens in descending order; `primaryModel` requires measured output. `pullRequests` contains recorded PR references with nullable `repository`, `number` and HTTPS `url`. `permissionMode,effort,startCommit,agentType,allErrorsRetried` are null without native evidence. Admission can return `lock-required`, `archive-uninitialized`, `kind-off`, `kind-unavailable`, or `archive-replaced`. List/count failure is distinct from an empty result. A missing header, info or edit target returns `conversation_not_found`. Reader calls can return `reader_rebuild_required`, `stale_cursor`, `not_found` (branch, anchor or retained bytes), `limit_exceeded`, `cancelled` or an archive/storage error. On `stale_cursor`, refresh the header before using a reader continuation. Pass a fresh optional UUID `requestId` to window, branch or byte reads and cancel it through `cancel_agent_read` with `{"request":{"requestIdOrStreamId":"…"}}`. An already active ID returns `archive-busy`.

**Native metadata values.** `parentStatus` is `none`, `resolved` or `unresolved`. Source `base` is null or `{source_id,own_end,prefix_digest}` for a proven inherited prefix; `own_end` is its exclusive physical ordinal in the base. Boundary kinds are `compaction`, `context_edit` and `unresolved_parent`. Raw framing coverage is `Object`, `Blank`, `Oversized`, `InvalidUtf8`, `Malformed`, `Incomplete` or `NonObject`. Roles and event kinds retain the adapter’s vocabulary. Use the typed parts for rendering. A response’s `at` is its timestamp and `durationMs` its recorded response duration, which can differ from the whole turn’s duration.

### Records search and reader find

| Command                      | Example request                                                                                                                            | Scope                                                                                                                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `search_agent_conversations` | `{"request":{"query":"\"amber needle\"","roles":["user","agent","thinking","tool"],"filters":{"harnesses":["claude-code"],"range":"7d"}}}` | All eligible saved roots in descending last-activity order, including their subagents. Forks retain their own cards.                                                            |
| `find_in_agent_conversation` | `{"request":{"id":"<conversationId>","query":"/needl[eE]/"}}`                                                                              | All readable records in the conversation and its descendants, including collapsed parts and subagent titles. Uses the reader publication even while global indexing is pending. |

Both return `{"streamId":"<uuid>","viewToken":"<uuid>"}`. On Tauri supply `onEvent` alongside `request`. On the dev bridge subscribe once to `GET /previews/{streamId}/events`. The receipt and frames are private to the requesting view. On a new query or dismissal use `cancel_agent_read` with `{"request":{"requestIdOrStreamId":"<streamId>"}}` and discard that stream. Closing the receiver releases its producer.

Unquoted words must all occur in a single native record across the enabled parts, in any order. Quotation marks require consecutive tokens in order within one part, including repetitions. Slashes delimit a case-insensitive Rust regular expression over a readable string. Word and phrase searches use the same Unicode word and CJK tokenization as indexing. The maximum expression length is 4,096 UTF-8 bytes. Each matching word occurrence, phrase start or regex match counts once. Titles participate separately. A title that repeats the first prompt can therefore contribute one title hit and one message hit.

`roles` defaults to all four values and requires at least one. Tool includes inputs and outputs. Assistant strings are readable CommonMark text. Titles always participate in Records search, including a rename made since the last backup. `filters` accepts the list's `harnesses`, `projectId`, `range` or `day`, `timeZone` and conjunctive `flags`. The default includes archived roots and excludes trashed trees. The trash flag searches trashed roots. Results have a fixed activity order and stream through completion.

Each frame has the following envelope. Sequence is a decimal string beginning at zero.

```json
{
  "streamId": "<uuid>",
  "sequence": "0",
  "type": "progress",
  "payload": { "scanned": 0, "total": null, "conversations": 0, "hits": 0 }
}
```

| Type                 | Payload and client action                                                                                                                                                                                                                                                                                           |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `started`            | `{"total":131,"indexLag":1,"indexedThrough":721,"filtered":false}`. Total is the number of eligible roots in the selected search epoch. Lag counts distinct pending conversations at admission. Find has one tree, zero index lag and a null index watermark.                                                       |
| `groups`             | `{"items":[card,…]}`. Upsert each card by its root ID in arrival order. A later copy of the card supplies its new cumulative count and preview.                                                                                                                                                                     |

## Agent conversation AI access

Settings uses `set_agent_viewer_preferences` with independent boolean patches `assistantMayRead`, `buildSemanticIndex` and `mcpMayRead`. Each defaults to false on a new installation. The saved global AI master and the corresponding Assistant, semantic-index or MCP capability must also be on. Paused Agent backup permits retrieval of saved conversations. An off Agent space and a locked archive refuse it. Lexical Records search keeps working with AI disabled.

**Ask.** The existing `ai_chat_send` tool-enabled request advertises `search_agent_conversations` when Assistant has access. The configured chat provider receives an array of cited excerpts such as `[{"citation":"pathkeep://conversation/open?conversationId=C&sourceId=S&ordinal=7","passage":"…"}]`. The model can request up to eight per call. The citation event and reopened Ask transcript carry `target:{"kind":"conversation","conversationId":"C","sourceId":"S","ordinal":7}`. Route this target to the Agent reader's record anchor. The existing journal key occupies the negative event-ID range and `profileId` is `"agent-history"`. Browsing citations keep their existing shape.

A terminal Ask refusal carries its code on the ordinary stream event, for example `{"runId":"…","chunk":{"kind":"error","code":"agent-conversations-access-disabled","message":"…"}}`. Use `chunk.code` to localize the refusal. Unclassified failures retain the diagnostic `message` and omit `code`.

**Records.** Use `search_agent_conversations({"request":{"mode":"semantic","query":"medical care for an ill dog","roles":["user","agent"],"filters":{}}})`. Omitting mode retains lexical search. Supply the native event channel as for lexical search. The receipt and cancellation use the same stream ID as lexical search. Semantic queries take natural-language text and score every indexed passage with the chosen embedding model. Each request returns up to 100 eligible passages, ordered by descending quantized cosine score, then ascending event ID and chunk. There is no minimum score. Zero and negative scores are eligible. Root filters also apply to descendants. Trash is excluded. The query stays within the same serving generation.

| Frame      | Payload                                                                                                                                                                                                                                                                                        |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `started`  | `{"mode":"semantic","pageSize":100}`                                                                                                                                                                                                                                                           |
| `passages` | `{"items":[{"id":"root","title":"…","harness":"pi","lastActivityAt":1794355500000,"archived":false,"onlyInPathKeep":false,"address":{"conversationId":"C","sourceId":"S","ordinal":7,"nativeId":"n","publication":"P"},"role":"agent","part":0,"start":0,"text":"…","chunk":0,"score":0.72}]}` |
| `finished` | `{"hits":42,"generation":"generation-…","stale":false,"nextCursor":null}`                                                                                                                                                                                                                      |

To scroll, repeat the same request with its opaque continuation at `request.cursor`, e.g. `{"request":{"mode":"semantic","query":"medical care for an ill dog","roles":["user","agent"],"filters":{},"cursor":"…"}}`. Each page has its own cancellable stream. `finished.hits` counts passages on this page. Sum it across completed pages for the number loaded. A null `nextCursor` means the result is exhausted. Keep the current rows on retry of the same cursor and append its successful page once. If the index, conversation view, query or scope changed, `stale_cursor` asks the screen to start again. A malformed continuation gives `invalid-cursor`.

`start` counts Unicode scalars inside the readable part. Each passage contains at most 1,024 scalars. `chunk` counts passages from the start of the record. A semantic match can have no literal highlight. A provider switch or missing publication gives `agent-semantic-index-not-ready`; Settings can request a build. The ordinary stream cancellation, expiry and access refusals still apply.

**Embedding jobs.** Enabling the setting starts a build when eligible. Desktop Agent backup checks for updates after capture. Builds keep the previous generation serving while the next one is staged. Pauses are cooperative at batch boundaries. Cancellation discards the staged generation. Each job is bound to an archive owner and the selected provider/model.
