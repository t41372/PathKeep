# Desktop Command Surface

> 這是 M0 凍結的 Tauri command surface 草案。正式 IPC facade 仍可暫留單檔，但命名與 envelope 之後要向這裡收斂。
>
> 2026-10：草案裡的 dashboard、explorer、audit 是舊前端的畫面。現在註冊的命令全在 `src-tauri/src/lib.rs`（`generate_handler!`），畫面呼叫的每一個都經過 `src/lib/backend-client/` 的 typed client；這次 redesign 改了什麼見下方「2026-10 redesign backend」。

本草案與 [module-boundary-map.md](module-boundary-map.md) 的 command sections 同步維護；若兩者出現衝突，以本文件的 API 分類為準。

---

## Interface Types

1. Read model
   - 回傳給 onboarding、dashboard、explorer、audit、settings 的純讀取資料
2. Preview / manual / execute
   - 高風險操作一律先產生 preview artifact，再進 execute
3. Long-running job trigger
   - 啟動 backup / import / doctor / future reindex，回傳 `run_id`
4. Artifact fetch
   - 用 `run_id` 或 artifact id 拉 manifest、snapshot metadata、preview bundle
5. Session guard
   - 提供 app lock 狀態、鎖定 / 解鎖與 lock-aware refusal path

## Open at login 與選單列圖示（2026-10）

三個命令，Tauri 與 dev bridge 都有註冊，回傳值都是呼叫後 OS 實際的狀態：

| 命令                      | 參數                   | 回傳                 |
| ------------------------- | ---------------------- | -------------------- |
| `get_desktop_integration` | —                      | `DesktopIntegration` |
| `set_launch_at_login`     | `{ enabled: boolean }` | `DesktopIntegration` |
| `set_menu_bar_icon`       | `{ enabled: boolean }` | `DesktopIntegration` |

`DesktopIntegration = { launchAtLogin, menuBarIcon, launchAtLoginSupported, menuBarIconSupported }`。

- `launchAtLogin` 讀 OS 的登入項目，不存在 config。macOS 用 PathKeep 自己的 LaunchAgent（`vault_platform::login_item`，經 `/usr/bin/open` 啟動，避開 macOS 26 的 Launch Constraint kill）；Windows / Linux 用 `tauri-plugin-autostart`。webview 不再有 `autostart:*` capability，只能走這三個命令。
- `menuBarIcon` 是「圖示現在在不在」；偏好存 `AppConfig.menuBarIcon`。`set_menu_bar_icon` 先改圖示再存 config，存失敗就把圖示改回去並回錯。`save_config` 存完也會讓圖示與選單語言跟上 config。
- `menuBarIconSupported`：macOS / Windows 恆為 true；Linux 需要能載入 libappindicator，且 session bus 上有 `org.kde.StatusNotifierWatcher`（問不到時不擋）。不支援時 `set_menu_bar_icon(true)` 回錯。
- 事件：`pathkeep://open-command-palette`（選單「搜尋歷史…」，無 payload）；`pathkeep://backup-finished`（任何 app 內備份結束，`{ source: "app" | "menu-bar", report?, error? }`）。`run_backup_now` 與選單的「立即備份」走同一條 `desktop_integration::run_backup`，`pathkeep://backup-progress` 不變。dev bridge 的 `run_backup_now` 在 app 已啟動時也走這條路徑。
- 登入啟動帶 `--launched-at-login`。主視窗在 `tauri.conf.json` 設為 `visible: false`，由 setup 決定：一般啟動顯示；登入啟動時保持隱藏（圖示開著，或 macOS 有 Dock 可叫回），Windows / Linux 沒圖示時以最小化開啟。圖示開著時關視窗只是隱藏；圖示關著時關視窗就是結束，有工作在跑時先問（見下節）。細節與理由見 `docs/features/archive.md` §2「開機啟動與選單列圖示」。

## 結束時還有工作在跑（2026-10 / `WORK-QUIT-DURING-WORK`）

有人等著的工作在跑時要結束 PathKeep，先問再結束（`src-tauri/src/desktop_integration/quit.rs`）。起因：2026-10-16 有人在 move.spec 途中按了測試視窗的關閉鈕，35 ms 後程序結束，跑了 40 秒的 `export_app_data` 白做，畫面只說連不上 desktop bridge。

- **哪些工作算**：`vault_worker::foreground_work()`，一份只讀記憶體的登記表（`vault-worker/src/foreground_work.rs`）。手動備份（視窗與選單列的「立即備份」）、匯出歷史、匯入 Takeout / 瀏覽器檔案、搬到另一台電腦的匯出與匯入、從安全快照還原、釋放空間、升級存檔、更改存檔密碼、開關加密、刪除所有資料，以及開存檔時跑的 schema 更新（2026-11-15 `WORK-SCHEMA-UPDATE-QUIT`）。登記在 vault-worker 的入口與 `maintenance_jobs::run`，所以 Tauri 命令、dev bridge 與 owner endpoint 都看到同一份。schema 更新在 vault-core 開檔時跑，比 vault-worker 低一層，所以由 vault-core 自己記（`vault_core::schema_update_running`），`foreground_work()` 讀它，排在最後：vault-store 開檔時，真的要改一個已有的資料庫之前通知一次（`MigrationRegistry::on_update`；新建的、已是最新的都不通知），vault-core 從那一刻算到這次開檔結束，成功、失敗或 panic 都一樣。排程備份不算（下次檢查會再跑）；背景佇列（建索引、洞察、連結預覽）也不算，重開後自己續跑，結束照常。
- **攔在哪**：選單列圖示關著時按視窗的關閉鈕，攔在 `CloseRequested`（視窗還在，就地問；圖示開著時關視窗只是隱藏，不問）。其餘都經 `AppHandle::exit` 到 `RunEvent::ExitRequested`：選單列圖示的「結束 PathKeep」、macOS 的 ⌘Q、問題的回答本身。Tauri 預設選單的 Quit 走 AppKit 的 `terminate:`，app 攔不到，所以 macOS 的 app 選單換成同一份預設選單、只把 Quit 換成 PathKeep 自己的項目（`app_menu.rs`；文字跟著 app 的語言，取自 `copy.rs`，設定換語言時重建。AutoFill、聽寫、視窗排列這些 macOS 自己加進去的項目跟著系統語言）。更新後重開（`RESTART_EXIT_CODE`）不攔。判斷在主執行緒上做，只讀記憶體，不碰選單狀態的鎖。
- **事件與命令**：`pathkeep://quit-request`，payload 是 `QuitRequest = { id, work: ForegroundWork[], waiting }`，或 `null`（沒有問題了）；`work` 依開始順序、每種一次，做完會變空陣列。dev bridge 的 `/events` 也轉發。視窗晚開或重新載入時用 `get_quit_request` 讀。`answer_quit_request({ id, answer: "wait" | "quit-now" | "keep-open" })` 回傳回答後的 `QuitRequest | null`；`id` 不是目前的問題時什麼都不做，因為可能有兩個視窗都在問（E2E 的 Tauri 視窗與 Chromium）。
- **之後的行為**：選「做完再結束」，工作清單一空就結束。改密碼與開關加密把鑰匙圈和「把密碼存到鑰匙圈」設定一起算在工作裡（`RekeyRequest.rememberInKeychain`，worker 在同一個 hold 裡寫），不是視窗事後再補，所以「做完再結束」不會把鑰匙圈留在上一步。新存檔裝上時帶的是原本的設定，鑰匙圈存好（或清掉）了才改設定；鑰匙圈寫不進去時，改動照樣算完成、設定維持原樣，下次開啟不會去等一把鑰匙圈裡沒有的鑰匙。存檔換好之後的步驟（鑰匙圈、設定、稽核紀錄）都不再讓命令失敗，免得視窗說「存檔沒有改動」；`rekey_archive` 回傳 `RekeyOutcome = { snapshot, keychainFailed }`，視窗照 `keychainFailed` 提醒，不從快照的鑰匙圈狀態去猜（舊鑰匙還在時猜不出來）；改寫途中 App Lock 鎖上時讀不到快照，`snapshot` 是 `null`，解鎖時視窗再讀。鑰匙圈拒絕刪除鑰匙也算沒更新（以前原生的刪除錯誤被吞掉）。還原、升級、搬移匯入沒人要求改鑰匙圈：照存檔原本的設定存鑰匙，設定說不記住時只清掉狀態看得到的鑰匙；鑰匙圈不肯存、讀不到或清不掉就不動，只記 log，不讓已經裝好的存檔變成失敗（說失敗，使用者會在裝好的存檔上再還原一次）。鑰匙圈不肯存新鑰匙時會留著原本那一項，可能是被換掉的存檔的鑰匙，什麼都打不開，首頁卻以為鑰匙還在；所以存不進去時，鑰匙圈裡那一項不是這個存檔的鑰匙（也不是打得開它的舊版密碼）就刪掉（`store_data_key_in_keyring`，每個存鑰匙的地方都走它）。這時首頁會提醒「設定要記住密碼，鑰匙圈裡卻沒有」，下次開啟問密碼。用密碼開存檔時鑰匙圈不肯存，也是同樣處理，存檔照樣打開，下次再問密碼。沒回答時工作做完了，問題改說都做完了，仍由使用者選：不會自己結束，也不會自己消失。問題開著時再結束一次：還有工作在跑，視窗回到前面、問題再送一次；已經沒有工作在跑（問題說的就是這個），就照第二次的要求結束。沒有視窗（`--background` 啟動）時會開出視窗來問。
- **「現在結束」**跟以前的結束一樣，程序直接結束，不先取消工作：匯出先寫暫存檔再換名，不會留下半個檔案；匯入已存進去的批次保留，再匯入同一個檔案可以做完；存檔變更由下次開啟時各自的恢復流程收拾；刪除所有資料在下次開啟時做完（`finish_interrupted_data_wipe`）。
- **攔不到的**：macOS Dock 選單的「結束」、登出與關機也走 `terminate:`，tao 0.35 沒有 `applicationShouldTerminate:` 讓 app 回答，程序立刻結束，跟以前一樣。所以 PathKeep 不會擋住登出或關機；工作會中斷，檔案不會寫壞（同上）。Windows、Linux 的登出與關機沒有驗證過。
- **測試**：debug build 的 dev bridge 有 `debug_request_quit({ via: "window" | "app" })`，關閉主視窗或呼叫 `AppHandle::exit(0)`，走的就是關閉鈕與 ⌘Q 的處理。E2E：`tests/e2e/quit-during-work.spec.ts`（`restart` project）；schema 更新是 `tests/e2e/schema-update-quit.spec.ts`，在 backup-integrity 設定的 v1 存檔上跑，排在 backup-integrity.spec 前面。fixture 的更新不到一秒就做完，所以 debug build 的 `PATHKEEP_TEST_HOLD_SCHEMA_UPDATE` 在更新改第一個資料庫之前停住，等它指的檔案被刪掉，並把程序 id 寫到旁邊的 `.held`（`vault-core/src/test_support.rs`）。真的 ⌘Q、關閉鈕與三語選單是手動驗的（2026-10-30）：沒打包的 debug binary 沒有 bundle id，自動化工具只指得到已安裝的 PathKeep，所以把 debug 的 `pathkeep-desktop` 與 `pathkeep-worker` 放進另一個 bundle id 的 `.app`，用 `bun run dev:demo -- --backend <app>/Contents/MacOS/pathkeep-desktop` 跑；示範資料要加大（例如 `perDay: 1200`，約 46 萬筆），匯出才跑得夠久來回答問題。

## Debug 平台沙盒（2026-10）

Debug build（`tauri dev`、`bun run dev:demo`、desktop-bridge E2E）設定 `PATHKEEP_PLATFORM_TEST_SANDBOX_DIR` 時，排程與開機啟動的 OS 狀態改寫到該目錄的檔案，不呼叫 `launchctl` / `schtasks` / 登入項目 API：

- `LaunchAgents/`：排程 plist；`launchd-loaded/<label>`：代表「已 loaded」的標記檔。
- `TaskScheduler/<label>.xml`：Windows 排程。
- `login-items/com.yi-ting.pathkeep.login.plist`：開機啟動（所有 OS 都用這個格式記錄）。

Plan 產生、plist / XML 內容、audit 與 status 解析照常執行。每次 apply / remove / repair / status 只解析一次沙盒設定，同一個操作不會混用真實與沙盒。Release build 忽略此變數（與 `PATHKEEP_PLATFORM_TEST_KEYRING_DIR` 相同）；舊的 `PATHKEEP_PLATFORM_TEST_LAUNCH_AGENTS_DIR` 也改成只在 debug build 生效。Linux 排程本來就只給手動步驟，沙盒對它沒有作用。Debug build 若設了 `CHB_PROJECT_ROOT` 卻沒設沙盒，macOS / Windows 的排程 status / apply / remove / repair 與開機啟動一律回錯誤（`sandbox::ensure_native_os_allowed`），不會讀到或改到開發者自己的排程與登入項目。可能的失效方式與對應測試列在 `vault-platform/src/sandbox.rs` 檔頭。`scripts/dev-demo.mjs` 與 `playwright.desktop-bridge.config.ts` 都會設定它。

## 單一資料庫擁有者（Turso 遷移 §2）

App 在任何資料庫工作前持有 `archive/.pk-owner.lock`，並提供同一使用者才能連線的本機 endpoint。
排程、worker CLI 與 MCP stdio 都透過它執行；未啟動時會以 `--background` 啟動 app。

### Backup outcomes

`run_backup_now` and `run_snapshot_restore` return a `BackupReport` in Tauri and the devtools
bridge. A backup that ran returns `Ok(report)` with `run.status` `success` (every selected
profile complete) or `partial` (some profile could not be read; what could be read is saved).
`Err(CommandError)` means the backup itself failed (archive, disk, lock); its `message` is the
original chain, as for other commands, and `backup-no-profiles` (nothing selected or found) is
a classified code. Every selected profile appears in `profiles` with an `outcome`, also kept in
the run's `stats_json.profiles`:

```ts
type ProfileOutcome =
  | { status: 'complete' }
  | { status: 'unavailable'; code: string } // could not be found or opened
  | { status: 'failed'; code: string } // opened, could not be read to the end
```

| Code                            | Meaning                                                               |
| ------------------------------- | --------------------------------------------------------------------- |
| `source-profile-not-discovered` | A selected profile is no longer on this computer                      |
| `source-unreadable`             | Its history file is missing or cannot be read                         |
| `source-permission-denied`      | The OS refused access (macOS: Full Disk Access)                       |
| `source-read-failed`            | The staged file or its schema could not be read                       |
| `source-stream-failed`          | Reading stopped part way; what was read before is saved               |
| `source-favicons-unavailable`   | Icons could not be read; history is saved (a warning, not an outcome) |
| `source-visits-without-page`    | Note: rows whose page row is gone, counted; the run stays `success`   |
| `source-ids-reset`              | Note: the browser numbered its rows again; every row was read         |

Each non-complete outcome is also a warning with the same code and `profileId`, translated in
all three languages; the frontend reads codes, never English text (Safari's Full Disk Access
guidance reads the outcome). Scheduled attempts record a partial run as `partial` with reason
`backup-incomplete`, and tell `write-lock` and `disk-full` failures apart. Request fields and
command names are unchanged.

Each private frame has `streamId,sequence,type,payload`, beginning at sequence
`"0"`. Progress uses `phase:"discovery",unit:"entries",done`. A `root` frame
contains one inventory row. `finished` encloses the complete report in the
fixture. `cancelled` or `error` ends the stream with `{code}`. A stalled preview or unused ticket expires after five minutes. The owner keeps
at most 32 live streams and 32 tickets, evicting the oldest ticket at capacity.
Dropping the private reader cancels production. Counts, bytes and sequence numbers are
decimal strings except for the bounded number of roots per tool. Dates are
UTC epoch milliseconds. Earliest/latest are null when no filesystem
modification time was observed.

A root reports `known-layout` for Claude's recognized positions,
`file-candidates` for the other tools, or `unavailable` for an inaccessible
root. The mutually exclusive file counts cover top-level candidates,
recognizable child files, ambiguous candidates, ancillary files, and unknown
files within the inspected trees. Source bytes include all five categories.
Directory counts exclude the selected root. A row can be readable with a
reason if a descendant was inaccessible. Totals then cover observed metadata.
The estimate budgets the observed byte length of native-compressed and ordinary
inputs, one additional byte per observed input byte for derived storage, and
4 KiB per file for overhead. Free bytes come from the volume containing the
conversation evidence database, or its nearest existing ancestor during setup.

After a committed policy edit, `pathkeep://data-kinds-changed` carries
`{policyToken,changedKinds}`. A no-op produces no event. Content and paths
travel on the private request stream. A mismatched policy token returns
`policy-changed`; a last-on transition returns `last-active-kind`.
Other domain refusals include `invalid-request`, `lock-required`,
`enable-preview-required`, `scope-denied`, `source-selection-empty`,
`root-changed`, `preview-expired`, `archive-replaced`, `archive-busy`,
`archive-uninitialized`, `destination-unavailable`, and `cancelled`.
Existing archive admission and key errors keep their codes. A missing source
reports `root-missing`; denial or an unreadable entry reports
`root-unreadable`. The scan depth limit reports `source-depth-limit`.

An unavailable conversation store leaves the browsing row readable.
`availability` is `available`, `not-initialized`, or `unavailable`.
An unavailable row has null `hasSavedData`, absent `archiveCount` and
`firstBackup`, and unavailable coverage. Role-local damage also carries
`failure:{role,stage,reason}` from the open owner. Roles are `evidence`,
`read-model`, or `shared`. Stages are `preflight,open,key-check,migrate,recover`.
Reasons are `archive-store-missing,wrong-key,integrity-failed,schema-too-new,archive-busy,kind-unavailable`.

The pre-password preview does not reveal the encrypted conversation count. |

Debug owners read `PATHKEEP_TEST_AGENT_PREVIEW_ENTRY_DELAY_US` per inventory
walk and `PATHKEEP_TEST_AGENT_CAPTURE_FILE_DELAY_US` per capture root. Positive
integer values are microseconds per entry or discovered file. Unset, invalid
and zero values disable pacing. Waits check cancellation in slices of at most
10 ms. Release builds ignore both variables.

### Protect browsing and repair conversation storage

All four commands run on the unlocked archive owner. A preview token binds its execute request.
The repair preview verifies the selected source and counts its conversations before returning.

| Command                        | Fields inside `request`                                | Result                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------ | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `preview_archive_safety_copy`  | Empty object                                           | `directory`, `conversationsUnreadable`, `previewToken`                                                                                                                                                                                                                                                                                                                               |
| `create_archive_safety_copy`   | `previewToken`                                         | Listed recovery snapshot, including `conversationsUnreadable`                                                                                                                                                                                                                                                                                                                        |
| `preview_agent_history_repair` | Optional `copyPath` and `copyPassword`                 | `action`, `copyPath`, `sourceOp`, `createdAt`, decimal-string `conversations`, nullable `conversationsRecoveredWhole`, `conversationsRecoveredPartially`, `conversationsOnlyInCopy`, decimal-string `skippedOptionalRecords` and `unreadableOptionalSections`, `keptAs`, `reviewSourcesBeforeBackup`, `nextBackupRecapturesToolFiles`, `archiveOnlyConversationsUnreadable`, `token` |
| `repair_agent_history`         | Same source fields and `previewToken` from the preview | `keptCopyPath` and `availability:"available"`. Publishes `pathkeep://data-kinds-changed` with the current policy token and `changedKinds:["agent-history"]`.                                                                                                                                                                                                                         |

An omitted source lets the owner choose `rebuild` when canonical evidence is intact or
`startFresh` to salvage verified revisions into new stores when the original evidence database cannot be admitted. `fromCopy` takes both roles from one
verified safety copy or rebuilds from its verified evidence. A marked full copy can restore browsing. A held-only copy is listed with `sourceOp:"heldGeneration"` and can supply evidence for repair.
Mode conversion and move-file conversion return `conversation-repair-required` with
`actionHint:"preview_agent_history_repair"`. A failing live query can supply a `read` or
`write` stage on the kind's failure. The desktop test `conversation_repair_screen_wire_contract`
records the serialized requests, results, errors and events in
`artifacts/vault-lifecycle/conversation-repair-wire.json`.

The repair preview's `conversations` is the decimal-string count visible after the proposed action.
For `startFresh`, verified revisions can make this count positive. `conversationsOnlyInCopy` is
a decimal string when a readable conversation inventory establishes the difference and `null`
when it cannot be measured or the action does not use salvage. Render an unknown count explicitly.
A preview expires after fifteen minutes. A later successful preview supersedes it. The existing
`cancel_maintenance` command cancels active preparation or discards a prepared preview. Execute
consumes the token and verifies the selected copy and live inputs again.

The first conversation quarantine discovered by a query or a conversion emits
`pathkeep://data-kinds-changed` with the current `policyToken` and
`changedKinds:["agent-history"]`. Refetch the kind snapshot even if the policy token is unchanged.
A retained-byte failure names the evidence role. Retry verifies the failed revision before it
publishes workers. A refusal to preserve an OS-unreadable file identifies its path.

For salvage, `conversationsRecoveredWhole` counts visible conversations with their original latest revisions available. `conversationsRecoveredPartially` counts visible conversations for which an earlier revision survived and a latest revision did not. `conversationsOnlyInCopy` counts original conversations absent from the repaired view. Each field is a decimal string or `null` when its inventory is insufficient. `conversations` remains the total visible in the prepared result. `skippedOptionalRecords` counts individually rejected optional records, and `unreadableOptionalSections` counts inventories or metadata sections that could not be enumerated. Counts refer to this preview. Actions that do not compare original and salvaged inventories leave the comparison fields null. Only `copyPath` and the preview token are needed on execute after the copy was authenticated at preview.

A temporarily inaccessible role reports `access-denied`. An operation requiring that group can return `conversation-access-unavailable` with `actionHint:"retry_agent_store"`. Retry checks access to the held files. A changed named input that cannot be read during execute returns `conversation-preservation-failed` with the member path. Execute verifies the consumed private stage and selected copy before acquiring the exclusive session lease. A marked source with no verified evidence returns `conversation-copy-no-verified-evidence`.
